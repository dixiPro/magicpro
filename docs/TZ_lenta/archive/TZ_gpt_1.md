# ТЗ v4. Модуль «Ленты» (`Feeds`)

## 1. Назначение

`MagicPro Lenta` — универсальный модуль хранения линейных данных небольших сайтов:

- новости;
- статьи и блог;
- рецепты;
- FAQ;
- отзывы;
- сотрудники;
- вакансии;
- события;
- телепрограмма;
- справочники;
- новинки.

Модуль не является конструктором произвольных баз данных.

Структура таблиц фиксирована. Разработчик работает с логическими именами полей, физические колонки скрыты.

Везде, где возможно, используются стандартные механизмы Laravel:

- Eloquent;
- Query Builder;
- casts;
- paginator;
- validation;
- transactions;
- Spatie Media Library.

---

# 2. Основной принцип хранения

Данные делятся на две группы.

## 2.1. Индексируемые данные

Данные, по которым требуется:

- искать;
- фильтровать;
- сортировать;
- проверять уникальность;
- строить связи.

Они хранятся в фиксированных физических колонках:

- `string_*`;
- `bigint_*`;
- `date_*`;
- `bool_*`;
- `link_*`.

## 2.2. Неиндексируемые данные

Данные, которые требуется только:

- хранить;
- редактировать;
- отображать.

Они хранятся в JSON-колонке `data`.

Модуль не поддерживает:

```php
where('data->content', ...)
```

или аналогичные запросы.

JSON не используется для фильтрации и сортировки. Это обеспечивает одинаковое поведение SQLite, MySQL и PostgreSQL.

# 3. Таблица `feed_groups`

Хранит группы лент.

| Колонка      | Тип      | Правила         |
| ------------ | -------- | --------------- |
| `id`         | bigint   | Первичный ключ  |
| `title`      | string   | Название группы |
| `position`   | bigint   | Позиция группы  |
| `created_at` | datetime |                 |
| `updated_at` | datetime |                 |

Миграция создаёт группу по умолчанию.

Группа по умолчанию:

- не может быть удалена;
- используется для новых лент;
- может быть переименована.

Лента не может существовать без группы.

Удаление группы, содержащей ленты, запрещено.

---

# 4. Таблица `feeds`

Хранит описание лент и структуру формы.

| Колонка          | Тип      | Правила                            |
| ---------------- | -------- | ---------------------------------- |
| `id`             | bigint   | Первичный ключ                     |
| `code`           | string   | Уникальный программный код         |
| `title`          | string   | Название в административной панели |
| `schema`         | json     | Описание полей                     |
| `schema_version` | integer  | Версия формата схемы               |
| `lock`           | boolean  | Запрет изменения схемы             |
| `group_id`       | bigint   | Обязательная связь с `feed_groups` |
| `position`       | bigint   | Позиция внутри группы              |
| `created_at`     | datetime |                                    |
| `updated_at`     | datetime |                                    |

## 4.1. Код ленты

`code`:

- уникален на уровне базы данных;
- соответствует регулярному выражению:

```text
^[a-z][a-z0-9_]*$
```

- не может быть равен `mpro`;
- после создания ленты не изменяется.

Пример:

```text
news
recipes
recipe_types
employees
```

Использование:

```php
MproHelper::feed('news');
```

## 4.2. Блокировка

При `lock = true` запрещено:

- добавлять поля;
- удалять поля;
- менять `code` поля;
- менять физическую колонку;
- менять тип поля;
- менять настройки связи.

Разрешено менять:

- название ленты;
- группу;
- позицию;
- значения записей.

---

# 5. Таблица `feed_items`

Хранит записи всех лент.

| Колонка                  | Тип               | Назначение                     |
| ------------------------ | ----------------- | ------------------------------ |
| `id`                     | bigint            | Первичный ключ                 |
| `feed_id`                | bigint            | Лента записи                   |
| `string_1` … `string_10` | string nullable   | Строки для поиска и сортировки |
| `bigint_1` … `bigint_5`  | bigint nullable   | Целые числа                    |
| `date_1` … `date_5`      | datetime nullable | Даты и время                   |
| `bool_1` … `bool_5`      | boolean not null  | Булевы значения                |
| `link_1` … `link_5`      | bigint nullable   | Ссылки на другие `feed_items`  |
| `data`                   | json              | Неиндексируемые данные         |
| `position`               | bigint            | Позиция внутри ленты           |
| `visible`                | boolean           | Видимость записи               |
| `created_at`             | datetime          |                                |
| `updated_at`             | datetime          |                                |

Колонки `text_1 … text_5` отсутствуют.

Большие тексты хранятся в `data`.

## 5.1. Значения по умолчанию

При создании записи:

```text
bool_1 … bool_5 = false
visible = false
data = {}
position = max(position) + 1 внутри feed_id
```

Все незанятые колонки, кроме булевых, хранят `NULL`.

Пустая строка не подставляется автоматически.

## 5.2. Позиция

Расчёт позиции выполняется в транзакции с блокировкой строки `feeds`.

Это исключает создание нескольких записей с одинаковой позицией при параллельных запросах.

# 6. Формат `schema`

`schema` содержит объект:

```json
{
  "version": 1,
  "fields": []
}
```

Порядок элементов массива `fields` определяет порядок полей в административной форме.

Каждое поле описывается одним объектом.

## 6.1. Пример схемы

```json
{
  "version": 1,
  "fields": [
    {
      "column": "string_1",
      "code": "title",
      "label": "Заголовок",
      "type": "string",
      "editor": "input",
      "required": true,
      "unique": false
    },
    {
      "column": "string_2",
      "code": "slug",
      "label": "Адрес страницы",
      "type": "string",
      "editor": "input",
      "required": true,
      "unique": true
    },
    {
      "column": "data",
      "code": "content",
      "label": "Текст статьи",
      "type": "text",
      "editor": "html",
      "format": "html",
      "sanitize": true,
      "required": false,
      "lines": 20
    },
    {
      "column": "data",
      "code": "source_code",
      "label": "Пример кода",
      "type": "text",
      "editor": "code",
      "format": "code",
      "language": "php",
      "sanitize": false,
      "required": false,
      "lines": 15
    },
    {
      "column": "link_1",
      "code": "category",
      "label": "Категория",
      "type": "link",
      "editor": "select",
      "required": false,
      "relation": {
        "feed_code": "recipe_types",
        "display_code": "title"
      }
    }
  ]
}
```

# 7. Параметры поля

## 7.1. Обязательные параметры

| Параметр | Назначение                         |
| -------- | ---------------------------------- |
| `column` | Физическая колонка или `data`      |
| `code`   | Логическое имя                     |
| `label`  | Название в административной панели |
| `type`   | Тип значения                       |

## 7.2. Общие необязательные параметры

| Параметр      |           По умолчанию | Назначение                      |
| ------------- | ---------------------: | ------------------------------- |
| `editor`      | определяется по `type` | Компонент формы                 |
| `required`    |                `false` | Обязательность                  |
| `unique`      |                `false` | Уникальность внутри ленты       |
| `default`     |                 `null` | Значение по умолчанию           |
| `placeholder` |                 `null` | Подсказка внутри поля           |
| `help`        |                 `null` | Текст под полем                 |
| `lines`       |                    `1` | Высота многострочного редактора |
| `format`      |                `plain` | Правило отображения             |
| `sanitize`    |     зависит от формата | Очистка входных данных          |
| `language`    |                 `null` | Язык редактора кода             |
| `readonly`    |                `false` | Запрет ручного редактирования   |

Новые параметры могут добавляться в будущих версиях модуля.

Неизвестные параметры игнорируются.

# 8. Логические имена полей

`code` поля:

- соответствует:

```text
^[a-z][a-z0-9_]*$
```

- уникален внутри ленты;
- не может быть равен `mpro`;
- не содержит точек;
- не меняется после появления данных в поле.

Примеры:

```text
title
slug
content
category
published_at
is_featured
```

---

# 9. Физические колонки

## 9.1. Строковые поля

```text
string_1 … string_10
```

Используются для:

- заголовков;
- slug;
- кодов;
- статусов;
- коротких значений;
- строкового поиска;
- уникальных строк.

Тип — `varchar(255)`.

## 9.2. Числовые поля

```text
bigint_1 … bigint_5
```

Используются только для целых чисел.

Денежные значения хранятся в минимальных единицах:

```text
150000 = 1500.00
```

Дробные неиндексируемые значения можно хранить в `data`.

## 9.3. Даты

```text
date_1 … date_5
```

Хранят дату и время.

В модели используются Laravel casts `datetime`.

Все даты сохраняются в едином часовом стандарте проекта.

## 9.4. Булевы поля

```text
bool_1 … bool_5
```

Булевы поля никогда не содержат `NULL`.

Для старых записей отсутствие значения означает `false`.

## 9.5. Связи

```text
link_1 … link_5
```

Каждое поле содержит `feed_items.id`.

Связи поддерживаются только между записями модуля «Ленты».

Связи с произвольными таблицами проекта в базовый модуль не входят.

Описание связи:

```json
{
  "feed_code": "recipe_types",
  "display_code": "title"
}
```

При сохранении проверяется:

1. связанная запись существует;
2. запись принадлежит указанной ленте;
3. поле `display_code` существует в схеме связанной ленты.

На уровне базы `link_*` использует внешний ключ:

```text
feed_items.id ON DELETE SET NULL
```

## 9.6. JSON `data`

Для поля с:

```json
{
  "column": "data",
  "code": "content"
}
```

значение хранится как:

```json
{
  "content": "<p>Текст статьи</p>"
}
```

В одном `data` может находиться любое количество полей:

```json
{
  "content": "<p>...</p>",
  "annotation": "Краткое описание",
  "source_code": "<?php echo 'test';",
  "seo_description": "Описание страницы"
}
```

По значениям из `data` запрещены:

- `where`;
- `orderBy`;
- `unique`;
- связи;
- автоматическая индексация.

---

# 10. Совместимость физических колонок

Одна физическая колонка может использоваться только одним полем схемы.

Допустимые соответствия:

| Колонка    | Допустимые типы                                                                       |
| ---------- | ------------------------------------------------------------------------------------- |
| `string_*` | `string`                                                                              |
| `bigint_*` | `integer`                                                                             |
| `date_*`   | `datetime`, `date`                                                                    |
| `bool_*`   | `boolean`                                                                             |
| `link_*`   | `link`                                                                                |
| `data`     | `string`, `text`, `integer`, `decimal`, `boolean`, `date`, `datetime`, `json`, `code` |

Нельзя назначить:

```text
type = text
column = bigint_1
```

или:

```text
type = link
column = string_1
```

Проверка выполняется при сохранении схемы.

# 11. Редакторы

Поддерживаемые базовые значения `editor`:

| Значение   | Назначение                  |
| ---------- | --------------------------- |
| `input`    | Однострочное поле           |
| `textarea` | Обычный многострочный текст |
| `html`     | HTML-редактор               |
| `markdown` | Markdown-редактор           |
| `code`     | Редактор кода               |
| `number`   | Число                       |
| `checkbox` | Булево значение             |
| `date`     | Дата                        |
| `datetime` | Дата и время                |
| `select`   | Одиночный выбор             |
| `json`     | JSON-редактор               |

Неизвестный редактор заменяется безопасным стандартным редактором, выбранным по `type`.

Схема не может содержать:

- PHP-классы;
- callback-функции;
- исполняемый JavaScript;
- имена произвольных Blade-компонентов.

Все значения работают только через белые списки модуля.

# 12. Форматирование и безопасность

## 12.1. `plain`

Значение выводится с HTML-экранированием.

## 12.2. `html`

HTML очищается при сохранении, если:

```json
"sanitize": true
```

Для вывода используется отдельный безопасный метод или Blade-компонент.

Обычное обращение к значению не должно автоматически выводить сырой HTML.

## 12.3. `markdown`

В `data` хранится исходный Markdown.

При выводе:

1. Markdown преобразуется в HTML;
2. результат очищается;
3. очищенный HTML отображается.

## 12.4. `code`

Код:

- не исполняется;
- не очищается как HTML;
- всегда выводится с экранированием;
- может подсвечиваться согласно `language`.

---

# 13. Версионирование схемы

В `feeds` хранится:

```text
schema_version
```

Внутри JSON также хранится:

```json
{
  "version": 1
}
```

Правила развития формата:

- новые параметры добавляются как необязательные;
- для отсутствующих параметров используются значения по умолчанию;
- неизвестные параметры игнорируются;
- существующие параметры не меняют смысл;
- удаление поддерживаемого параметра допускается только через отдельную миграцию схемы;
- структура таблицы `feed_items` при расширении схемы не изменяется.

Благодаря этому новые версии MagicPro могут добавлять:

- новые редакторы;
- новые правила валидации;
- предпросмотр;
- подсказки;
- настройки санитизации;
- оформление;
- дополнительные параметры медиа;

без миграции основной таблицы и без нарушения работы старых лент.

---

# 14. Изменение схемы

Разрешается без миграции данных:

- изменить `label`;
- изменить `placeholder`;
- изменить `help`;
- изменить `lines`;
- изменить настройки редактора;
- изменить настройки отображения;
- добавить необязательное JSON-поле;
- удалить пустое JSON-поле.

Запрещается, если в поле уже существуют данные:

- менять `code`;
- менять `column`;
- менять `type`;
- назначать физическую колонку другому полю;
- превращать физическое поле в JSON-поле;
- превращать JSON-поле в физическое поле.

Такие операции требуют отдельной миграции данных и не выполняются обычной административной формой.

Удаление поля из схемы не удаляет физические данные автоматически.

# 15. Доступ к данным

## 15.1. Логические поля

```php
$post->title;
$post->content;
$post->category;
```

Разработчик не работает с:

```php
$post->string_1;
$post->data['content'];
$post->link_1;
```

## 15.2. Системные поля

Системные данные доступны через `mpro`:

```php
$post->mpro->id;
$post->mpro->feed_id;
$post->mpro->visible;
$post->mpro->position;
$post->mpro->created_at;
$post->mpro->updated_at;
```

---

# 16. Query Builder

Получение ленты:

```php
MproHelper::feed('news');
```

Запрос:

```php
MproHelper::feed('news')
    ->where('mpro.visible', true)
    ->where('category', $categoryId)
    ->orderBy('mpro.position')
    ->paginate(10);
```

Разрешено использовать в запросах:

- системные поля `mpro.*`;
- поля физических колонок.

Запрос по JSON-полю вызывает понятное исключение:

```php
MproHelper::feed('news')
    ->where('content', 'text');
```

Пример ошибки:

```text
Field [content] is stored in JSON and cannot be used in where().
```

---

# 17. Видимость записей

`visible` не применяется автоматически.

Список сайта:

```php
MproHelper::feed('news')
    ->where('mpro.visible', true)
    ->orderBy('mpro.position')
    ->paginate(10);
```

Получение отдельной записи выполняется без фильтра `visible`, чтобы сохранить возможность предпросмотра.

Решение о показе скрытой записи принимает контроллер или Blade-шаблон.

---

# 18. Уникальность

`unique` разрешён только для полей физических колонок.

Проверка выполняется среди всех записей текущей ленты, включая скрытые.

Проверка и запись выполняются:

1. в транзакции;
2. с блокировкой строки `feeds`;
3. до сохранения новой записи.

Это предотвращает параллельное создание одинаковых значений.

Для `feeds.code` создаётся настоящий уникальный индекс базы данных.

---

# 19. Индексы `feed_items`

Все индексы статические и создаются миграцией.

Административная панель никогда не выполняет `ALTER TABLE`.

## 19.1. Основные списки

```text
(feed_id, visible, position, id)
(feed_id, visible, created_at, id)
```

## 19.2. Даты

```text
(feed_id, visible, date_1, id)
...
(feed_id, visible, date_5, id)
```

## 19.3. Связи

```text
(feed_id, visible, link_1, position, id)
...
(feed_id, visible, link_5, position, id)
```

## 19.4. Булевы значения

```text
(feed_id, visible, bool_1, position, id)
...
(feed_id, visible, bool_5, position, id)
```

## 19.5. Строковые значения

```text
(feed_id, string_1)
...
(feed_id, string_10)
```

## 19.6. Числовые значения

```text
(feed_id, bigint_1)
...
(feed_id, bigint_5)
```

JSON-колонка `data` не индексируется.

# 20. Индексы служебных таблиц

## `feeds`

```text
UNIQUE(code)
(group_id, position, id)
```

## `feed_groups`

```text
(position, id)
```

# 21. Удаление

## 21.1. Группа

Удаление группы с лентами запрещено.

## 21.2. Лента

Удаление ленты запрещено, если:

- в ней существуют записи;
- на неё ссылаются схемы других лент.

Для полного удаления используется отдельная явная операция с подтверждением.

## 21.3. Запись

При удалении записи:

- связанные `link_*` получают `NULL`;
- связанные медиа удаляются средствами Spatie Media Library;
- операция выполняется в транзакции.

---

# 22. Медиа

Изображения и файлы хранятся через Spatie Media Library.

Количество медиа для одной записи не ограничено.

Описание медиа-полей и коллекций может расширяться через `feeds.schema`, например:

```json
{
  "code": "gallery",
  "label": "Галерея",
  "type": "media",
  "editor": "media",
  "multiple": true,
  "collection": "gallery"
}
```

Добавление новых параметров медиа не требует изменения `feed_items`.

---

# 23. Итоговая структура `feed_items`

Фиксированный набор:

```text
10 string
5 bigint
```
