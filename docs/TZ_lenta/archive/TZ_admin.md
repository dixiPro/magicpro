# ТЗ. Модуль «Ленты» (Feeds). Админка

Экраны админки лент. Структура данных и удаление описаны в `TZ_data.md`, команды — в
`TZ_api.md`.

## Сборка фронтенда

**`npm` запускается из `packages/dixipro/magicpro`, не из корня проекта.**

```bash
cd packages/dixipro/magicpro
npm run dev     # разработка
npm run build   # сборка
```

Здесь лежит `vite.config.js` пакета: он собирает точки входа из `admin/js/`, кладёт
результат в `public/vendor/dixipro/magicpro` хоста и туда же пишет манифест. Запуск из
корня подхватит конфиг приложения, а не пакета, и админка не соберётся.

**Сам `vite.config.js` не правится.** Единственное разрешённое изменение — добавить строку
со своей точкой входа в массив `input` внутри `laravel({ … })`. Всё остальное в файле —
пути сборки, манифест, hot-файл, очистка ассетов — трогать нельзя.

## Заготовка

Первый шаг — не экраны, а живая связка «страница → API → команда → ответ». Собирается по
образцу почтовой админки `/a_dmin/mailSystem`, теми же пятью точками.

### 1. Роуты

В `admin/web.php`, рядом с почтовыми:

```php
// Ленты
use MagicProSrc\Lenta\API_Feeds;

Route::get('/a_dmin/feed', function () {
    return view('magicAdmin::feed');
})->name('magic.feed');

Route::post('/a_dmin/api/feed', [API_Feeds::class, 'handle'])
    ->middleware('magic.auth')
    ->withoutMiddleware([$csrf]);
```

Команда едет в теле запроса, `handle` её разбирает сам — отдельного роута на каждую команду
не нужно.

Страница открыта только пользователю с `role === 'admin'`, как у почты.

### 2. Блейд страницы

`admin/views/feed.blade.php`:

```blade
@extends('magicAdmin::templateAdmin')

@section('title', 'Ленты')

@section('body')
    @if (Auth::guard('magic')->user()->role === 'admin')
        <div id="feedAdmin"></div>
        @vite('admin/js/feedAdmin.js', 'vendor/dixipro/magicpro')
    @else
        <div>@magic_msg('no_permissions')</div>
    @endif
@endsection
```

Идентификатор `div` обязан совпасть с тем, во что монтируется приложение.

### 3. Точка входа

`admin/js/feedAdmin.js` — копия почтовой: Vue, PrimeVue с темой Aura, `ToastService`,
`ConfirmationService`, i18n, `app.mount('#feedAdmin')`.

### 4. Компонент

`admin/js/app/feedAdmin/feedAdmin.vue`. В заготовке — только проверка связки: слева
группы и ленты, полученные командами `groupsList` и `feedsList`, справа пусто. Внизу
`<TosatConfirm>`, он даёт `document.showToast()` и `await document.confirmDialog()`.

### 5. Обвязка

- строка `'admin/js/feedAdmin.js'` в массив `input` в `vite.config.js`;
- пункт меню в `admin/views/leftColumn.blade.php`: `['route' => 'magic.feed', 'label' => 'feed', 'icon' => 'fas fa-stream']`;
- подпись пункта — в `lang/en/messages.php` и `lang/ru/messages.php`;
- строки внутри компонента — в `admin/js/app/CommonCom/translate.js`, в оба блока, `en` и `ru`.

**Систем перевода две, и они не связаны.** Пункт левого меню берёт текст из PHP-файлов
через `@magic_msg`, всё, что внутри Vue, — из `translate.js` через `t()`. Забыть вторую —
классическая потеря времени.

## Экран групп

Главный экран `/a_dmin/feed`. Только группы: название и число лент в каждой. Самих лент
здесь не видно — клик по группе открывает её список лент.

Группа — это заголовок и порядок, больше в ней ничего нет.

### Создать

Кнопка «Добавить группу» → `groupCreate` → в конце списка появляется «Новая группа» с полем
ввода в фокусе, ввод завершается `groupSave`. Пустое название API не примет, текст отказа —
тостом.

### Переименовать

Клик по карандашу открывает поле ввода, `Enter` или потеря фокуса — `groupSave`, `Esc` —
отмена без запроса.

### Удалить

Корзина → `document.confirmDialog()` → `groupDelete`. Два отказа приходят от API и
показываются как есть:

- «Группа по умолчанию не удаляется»;
- «В группе есть ленты, она не удаляется».

Чтобы удалить непустую группу, её ленты сначала переносят в другую.

### Порядок групп

Перетаскиванием, средствами PrimeVue: `DataTable` с колонкой `rowReorder` и обработчиком
`@row-reorder`, отдельная библиотека не нужна. В событии приходит `value` — список уже в
новом порядке — и `dropIndex`, он же новая позиция: нумерация с нуля, прибавлять ничего не
надо. Отпустили строку → `groupMove`.

### Вставить ленту

Правая кнопка на группе → «Вставить», если в буфере лежит вырезанная лента (вырезают её на
экране лент). Команда — `feedMove` с этим `groupId` и позицией в конце. Буфер чистится,
списки перечитываются.

## Экран лент группы

Открывается кликом по группе. Ленты этой группы по порядку: название, код, число записей.
Наверху — название группы и возврат к списку групп.

- «Добавить ленту» → `feedCreate` с `groupId` этой группы.
- Клик по ленте — переход к её экрану: код, название, схема, записи.
- Корзина → подтверждение → `feedDelete`. Ответ `false` означает, что часть записей держат
  ссылки и лента осталась; что именно осталось, читается отдельно.
- Порядок — тем же перетаскиванием, `feedMove` с текущим `groupId`.

### Перенос в другую группу

Перетащить ленту между экранами нельзя, поэтому перенос сделан вырезанием и вставкой, как в
дереве статей (`ArtEditor/component/TreeArticle.vue`):

- правая кнопка на ленте → «Вырезать»: лента кладётся в буфер, тост «Вырезано: …»;
- дальше — «Вставить» на нужной группе, на экране групп.

Буфер — обычная переменная компонента, не реактивная: меню собирается заново на каждый
клик. Отмены нет, буфер живёт до вставки или до перезагрузки страницы.

### Общее

- Одно действие оператора — одна команда API.
- Любой `status: false` показывается тостом текстом из `errorMsg`, экран не меняется.
- После успешной команды список перечитывается: сервер — источник истины и по порядку, и по
  счётчикам.
