# МСП для лент

## Действия с лентой

?

План. Кода пока нет.

## Зачем

API лент живёт за `magic.auth`, то есть за сессией админки. Агент из консоли туда
не попадёт: у него нет ни куки, ни браузера. Со статьями это решено МСП, у лент
такого входа нет.

Чтобы написать страницу над лентой, агенту нужны имена полей. Сейчас их можно
взять только из `magicPro_feeds.schema`, то есть залезть в базу — чего делать
нельзя.

## Что инструмент делает

Даёт агенту читать ленты — список, схему, записи — тем же путём, каким это делает
админка, со всеми её проверками, но без http и без сессии.

## Устройство

Один инструмент поверх `AbstractFeedApi::run()`. Отдельные инструменты на каждую
команду не нужны: `run()` уже универсальная точка — команда, массив параметров,
ответ всегда одной формы, исключений не бросает.

```
feed-api { command: "itemsList", params: { "feedId": 2 } }
```

Внутри — `API_Feeds::run($command, $params)`. Наружу: `status: true` — отдаём
`data` структурой, `status: false` — ошибку с текстом из `errorMsg`.

Место: `src/Mcp/Tools/FeedApiTool.php`, регистрация в `MagicProServer::$tools`
рядом со статьями. Класс — обычный `Laravel\Mcp\Server\Tool`, как
`GetArticleTool`.

Новые команды API появляются в МСП сами, инструмент править не надо.

## Команды

Разрешён только список чтения, он зашит в инструменте:

- `groupsList` — группы
- `feedsList` — ленты с кодами и числом записей
- `feedGet` — лента со схемой
- `schemaGet` — только схема
- `itemsList` — записи, с фильтром, сортировкой и страницами
- `itemGet` — одна запись
- `itemLinks` — кто ссылается на запись
- `itemsLookup` — записи справочника для поля связи

Команда не из списка — ошибка инструмента, до `run()` дело не доходит.

## Что не входит и почему

- `itemSave`, `itemCreate`, `itemDelete`, `itemsDelete`, `feedClear`, `feedDelete`
  — это правка данных. У нас правило не трогать базу без спроса, а инструмент его
  обходит.
- `schemaSave` — не даём вовсе: схема ломает связь с существующими записями молча,
  и откатить это нечем.

Понадобится запись — заводим второй инструмент, `feed-api-write`, с таким же
устройством и своим явным списком команд. Тогда разрешение на запись — это
подключение отдельного инструмента, а не строка в описании.

## Описание инструмента

Описание — единственное, что агент читает перед вызовом, поэтому в нём должно
быть: что такое лента, что поля зовутся логическими именами, что список команд и
их параметры описаны в `docs/ru/feed/use.md`. Сами параметры команд в схему
инструмента не переносим — их полтора десятка, и они меняются.
