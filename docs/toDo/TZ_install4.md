# ТЗ: инсталлер, ресурсы, окружение

## Классы

Все три класса возвращают массив строк одного вида:

```php
[
    'status'      => false,
    'errorMsgHtml'    => 'то что хочет класс нам сообщить',  //  в формате html
]
```

Контроллер умный смотрит можно продолжать или нет.

### Installer

- Проверяет права на запись, если не ок, возвращает false и что нужно сделать, что бы исправить
- Проверяет Таблицу Артикл, если не ок, возвращает false и что нужно сделать, что бы исправить
- Проверяет есть ли рут, если нет, создает рут
- Вызывает перегенерацию статей

Порядок обязателен, на первом `false` останавливается и дальше не идёт.

- Права: `storage/app/private/magic` и `storage/dataMagicPro`. Создать каталог,
  записать файл, удалить. Не вышло — команда `chown` в `errorMsgHtml`.
- Права первые: без них некуда писать собственный статус.
- Таблица `articles`: нет — `php artisan migrate` в `errorMsgHtml`, без текста
  SQL-исключения.
- Рут — статья `id = 1`. Создаётся моделью `Article`, не запросом: сработают
  проверки имени и `parentId`.
- Перегенерация: только если блейдов меньше, чем статей. Столько же — ничего не
  делаем, `status` `true`, `errorMsgHtml` пустой.

### Resources

Чинит молча, останова не даёт. `false` — только когда починить не вышло.

- Ассеты `public/vendor/dixipro/magicpro`: `version.txt` не совпал с
  `MAGIC_VERSION` — копирует `readyBundle`, пишет версию.
- Каталог загрузок `public/{PUBLIC_UPLOAD_DIR}`: нет — создаёт.
- Симлинк `public/storage`: только проверяет. Нет — рекомендация
  `php artisan storage:link` в `errorMsgHtml`, сам не ставит.

Почему симлинк не ставим сами: запись нужна в `public/`, а он часто принадлежит
не веб-серверу. Плюс `symlink` бывает в `disable_functions`, а `open_basedir`
может не пускать к цели. Команда одна и стандартная, пусть её выполнит человек.

Проверять не только наличие, но и цель: `is_link()` на битой ссылке отвечает
`true`, картинки при этом не отдаются, а строка была бы зелёной.

`version.txt` остаётся: версию скопированных файлов узнать больше неоткуда.

Права на эти каталоги отдельно не проверяются: `mkdir` не прошёл — значит прав
нет, это и есть ответ.

### Environment

Ничего не чинит, только сообщает. `false` — не останов.

- `cwebp`, `vips` — по коду возврата, не по выводу.
- Расширение `gd`.
- Крон — по свежести отметки `Heartbeat`, порог 120 секунд.

В `errorMsgHtml` — готовая команда установки утилиты или крона.

Файл отвечает на вопрос «почему не работает» без доступа к серверу: прислали —
и видно всё. Он же годится на вход ИИ.

#### Две роли

- **Где остановились.** По `step` инсталлер пропускает уже пройденное.
- **Снимок состояния.** Остальное — для разбора чужой установки.

#### Когда пишется

- На каждый заход в `/a_dmin`, целиком. Иначе снимок позавчерашний.
- Нет файла — не пройдено ничего.
- `magicpro` не совпала с `MAGIC_VERSION` — проверяем всё заново.
- Удалили файл — то же самое.

#### Что запоминается, а что нет

- Запоминается: таблица, рут. Проверены один раз — больше не проверяются.
- Не запоминается: права и сверка блейдов. Проверяются всегда.

Права теряются как раз тогда, когда файл говорит «готово»: перенесли проект,
каталог создал root. Файл — запись, а не судья: нынешняя поломка ровно такая,
маркером работал сам каталог, он говорил «сделано», а сделано не было.

#### Правила содержимого

- `msg` — текст, не html. При записи `strip_tags()` от `errorMsgHtml`.
- `articles` против `blades` — сразу объясняет пустые каталоги.
- `user` — от кого работает процесс; вместе с `paths` закрывает все вопросы о
  правах.
- Ни email админа, ни ключей, ни чего-либо из `.env`. Файл уезжает по почте, в
  нём только факты об окружении.

#### Методы

| Метод                         | Что делает                                                |
| ----------------------------- | --------------------------------------------------------- |
| `passed(string $stage): bool` | стадия пройдена; `false`, если файла нет или версия не та |
| `pass(string $stage): void`   | записать пройденную стадию                                |
| `save(array $blocks): void`   | переписать снимок целиком                                 |
| `reset(): void`               | удалить файл                                              |

На `/a_dmin/setup` — ссылка «скачать отчёт», чтобы не объяснять человеку путь.

## AdminController

```php
public function index()
{
    return view('magicAdmin::index', [
        'install'     => (new Installer())->run(),
        'resources'   => (new Resources())->run(),
        'environment' => (new Environment())->run(),
    ]);
}
```

- Контроллер смотрит `status` строк установки и решает, звать ли следующий класс.
- Блейд рисует любой блок одним `foreach`: строки везде одной формы.
- Из контроллера уезжают `install()`, все четыре `install*`, `imageTools()`,
  `cron()`, `stepOk()`, `stepFailed()`.
- Остаются списки статей и админов, `clearCache`.
- Блокировка `Cache::lock('magicpro:install')` переезжает внутрь `Installer`.

## Консоль

Та же логика, другой вывод.

| Команда                               | Что делает                                       |
| ------------------------------------- | ------------------------------------------------ |
| `magicpro:install`                    | зовёт `Installer` и `Resources`, печатает строки |
| `magicpro:admin --email= --password=` | создаёт администратора                           |

- `magicpro:admin` спрашивает значения только при живом терминале.
- Без терминала и без параметров — ошибка с текстом, чего не хватило.
- Пароль в консоль не печатается.
- Мёртвый `src/Installer/InstallCommand.php` заменяется первой командой.

## Правки вне классов

- `create_magicPro_users_table.php`: убрать `readline()` и печать пароля, только
  создание таблицы.
- `create_magicPro_articles_table.php`: у `root` и `error404` полный
  `routeParams`, как у `index`. Сейчас `{}`.
- `admin/views/artList.blade.php`: нет ключа `useController` — это `false`.
  Ошибка — только если `routeParams` не разобрался в массив, и подсказка своя,
  про параметры маршрута.
- `admin/views/index.blade.php`: три блока по новому формату.

## Приёмка

- Пустая база: строка про `migrate`, без `SQLSTATE`. Прогнали, обновили — идём
  дальше.
- `chown root` на `storage/dataMagicPro`: строка про права с командой,
  перегенерация не запускается.
- Снести `storage/dataMagicPro` при пройденной установке — блейды вернулись.
- Удалить `install.json` — проверки прошли заново, лишнего не сделали.
- Второй заход подряд — ничего не пишется, перегенерации нет.
- `migrate --force` неинтерактивно — без вопросов и без пустого админа.
- После чистой установки в списке статей нет красных кружков.

## Вопросы

- В списке `Installer` нет проверки администратора и непрогнанных миграций.
  Оставляем их стадиями или выкидываем? Первая ловит установку без входа, вторая
  — обновление пакета с новой таблицей.
- Права на `database/database.sqlite` и каталог рядом: проверять здесь же или
  нет. Иначе `attempt to write a readonly database` вылезет позже и в другом
  месте.
- Кнопка `testWrite` на `/a_dmin/setup` дублирует проверку прав. Убрать или
  оставить ручным прогоном по `MAGIC_FILE_ROLES` — она шире.
- Нужна ли кнопка «проверить установку заново» — то же, что удалить
  `install.json`.
- Сверять блейды поимённо или по количеству: счёт не заметит статью,
  переименованную мимо админки.
- `/a_dmin` работает без `magic.auth`: установку запускает любой, кто открыл
  адрес.
- Таблица называется `articles`, без префикса пакета — отсюда конфликт с
  хост-приложением.
