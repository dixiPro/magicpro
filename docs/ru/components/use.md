# Компоненты: как пользоваться

Зовутся из любого блейда и из текста записи ленты:

```blade
<x-magic::img :img="$item->main" width="700" />
```

Двоеточие перед именем параметра значит «это выражение, а не строка».

## img

Картинка с набором размеров и форматов.

```blade
<x-magic::img :img="#img1#" width="700" />
<x-magic::img :img="#img1#" width="340" mobile="2" />
```

| Параметр | Что значит |
| --- | --- |
| `img` | поле-картинка записи ленты: `path`, `x`, `y`, `alt` |
| `width` | ширина места на десктопе, в пикселях |
| `mobile` | сколько таких картинок в ряду на телефоне: 1, 2, 3, 4. Умолчание 1 |

Параметры описывают место на странице, файлы компонент считает сам. `mobile` —
делитель ширины экрана: `100 / mobile` даёт `100vw`, `50vw`, `33vw`, `25vw`.

Что получается:

- три источника — avif, webp, jpg, каждый в обычном и двойном размере. Браузер
  берёт первый, чей формат понимает, поэтому до jpg доберётся только старьё;
- `sizes` собран из `width` и `mobile`. Это обещание браузеру, какой ширины будет
  картинка: он выбирает файл до вёрстки, сам ширину места знать не может;
- ширины в `srcset` — из ответа ресайзера, а не из запроса. `MAX_RESIZE` может
  срезать запрошенное, и врать браузеру нельзя;
- в `src` — крупная копия во весь исходник, потолок 3840. Это слот для поиска:
  Google индексирует именно `src` и avif там понимает. Живой браузер её не
  качает, `<source>` совпадает раньше;
- `width` и `height` на `<img>` — размер места и настоящая пропорция записи,
  чтобы страница не прыгала при загрузке;
- поле пустое или ресайз не удался — не выводится ничего.

Тройного размера нет намеренно: глаз разницы с двойным не видит, а вес растёт
вдвое. Телефон с 3x возьмёт самый крупный из имеющихся.

Файлов выходит шесть на картинку, все делаются один раз и живут в кеше ресайза.

Места на странице компонент не держит: картинка тянется на всю ширину родителя.
Это верно для вёрстки, где место задано колонкой. Для текста записи есть обёртка
— `img_box` ниже.

## img_box

Тот же `img`, но в обёртке, которая держит место.

```blade
<x-magic::img_box :img="#img1#" width="400" mobile="2" />
```

Параметры те же и уезжают в `img` как есть. Обёртка — `<span class="mimg …">`:
ширина десктопа идёт инлайном, доля телефона классом `mimg-m2`, `mimg-m3`,
`mimg-m4` из `public/design/style.css`, потому что медиазапрос в атрибут `style`
не поставить.

`span`, а не `div`: в тексте записи редактор кладёт тег внутрь `<p>`, а блок
оттуда браузер выкидывает наружу — получается разорванная разметка.

В блейде статьи, где ширину задаёт колонка, обёртка не нужна: там зовите `img`.

## paginator

Постраничная навигация к любому `LengthAwarePaginator`.

```blade
<x-magic::paginator :items="$items" label="zapisa" />
```

| Параметр | Что значит |
| --- | --- |
| `items` | сам пагинатор |
| `label` | слово после чисел: «zapisa», «записей» |
| `count` | `false` убирает строку со счётом, остаются только страницы |

Ничего не выводит, когда страница одна. Номера схлопываются в многоточие: края,
текущая и её соседи.

Вёрстка своя, не ларавеловская. У штатного вида фраза «Showing 1 to 2 of 6
results» зашита внутрь, и поменять её можно только переводами или публикацией
вида в проект — а тут текст лежит рядом, в блейде компонента.

Страницу компонент не считает, он её только показывает. Запрос собирается в
статье:

```php
$page  = max(1, (int) ($Get['page'] ?? 1));
$items = $feed->items()
    ->where('__visible', true)
    ->paginate(10, ['*'], 'page', $page)
    ->withPath('/blog');
```

`page` придётся разрешить в параметрах маршрута статьи, иначе адрес `/blog?page=2`
даст 404. `withPath()` прибивает адрес ссылок, иначе на `/blog/page/2` они начнут
наслаиваться.
