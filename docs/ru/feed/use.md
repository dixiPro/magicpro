# Ленты: использование

Этот документ нужен тому, кто создаёт ленты в админке, выводит их на сайте или
обращается к Feed API. Внутреннее устройство и правила изменения модуля описаны
в `inside.md`.

## Что такое лента

Лента — настраиваемый список однотипных записей: новости, товары, сотрудники,
отзывы, тарифы. Оператор создаёт ленту и её поля в админке, а приложение работает
с ними как с обычными Eloquent-моделями.

У ленты есть:

- `code` — постоянное имя для кода сайта, например `products`;
- `title` — название в админке;
- `schema` — описание полей;
- группа и позиция в ней;
- записи со своими полями, видимостью, позицией и slug.

Все записи хранятся в общей таблице. Схема связывает понятное имя поля, например
`title`, с физическим слотом вроде `__string_1`. В прикладном коде используйте
логические имена из схемы.

## Работа в админке

Раздел лент открыт по адресу `/a_dmin/feed`.

Обычный порядок работы:

1. Создать или выбрать группу.
2. Создать ленту, задать постоянный `code` и название.
3. Настроить структуру: занять нужные слоты и добавить поля в `__data`.
4. Настроить колонки списка, порядок формы, источник slug и статью просмотра.
5. Создать записи, заполнить их и включить видимость.

Доступные индексируемые слоты одной ленты:

| Слот | Количество | Для чего |
| --- | ---: | --- |
| string | 5 | короткие строки, поиск, сортировка, уникальность |
| bigint | 3 | целые числа и поиск по ним |
| date | 3 | дата/время, фильтрация и сортировка |
| bool | 3 | флаги |
| link | 3 | ссылка на запись другой ленты |
| `__data` | 1 контейнер | тексты, decimal, JSON, code, изображения и прочие выводимые данные |

Поле в `__data` читается и сохраняется как обычное, но по нему нельзя делать
SQL-фильтрацию, сортировку или проверку `unique`.

Коды лент и полей состоят из латинских букв, цифр, дефиса и подчёркивания. Код
поля физического слота нельзя переименовать, когда в ленте уже есть записи.

**Убрали поле из структуры — его значения уходят у всех записей ленты**, у поля-
картинки вместе с файлами. Вернуть их, вернув поле, уже нельзя.

### Slug и видимость

`slugFrom` в схеме может указывать на строковый слот. Тогда `__slug` каждый раз
пересчитывается из этого поля при сохранении записи. Если источник не выбран,
slug вводится вручную. В обоих случаях он транслитерируется и должен быть
уникален внутри ленты.

Новая запись скрыта: `__visible = false`. Модуль не добавляет фильтр видимости к
запросам автоматически. Для публичного списка всегда задавайте его явно.

## Получение данных на сайте

Провайдер пакета регистрирует короткие алиасы `Feed` и `FeedItem`.

### Список записей

Получайте записи через отношение конкретной ленты: тогда запрос знает схему и
переводит логические имена в физические колонки.

```php
$feed = Feed::where('code', 'products')->first();

$items = $feed?->items()
    ->where('__visible', true)
    ->where('price', '>=', 100)
    ->orderByDesc('created_at')
    ->paginate(20);
```

Если лента обязательна для страницы, вместо молчаливого `null` используйте
`firstOrFail()`.

С логическими именами поддержаны:

- `where()` — включая массив условий и вложенный callback;
- `whereIn()`, `whereNotIn()`, `whereNull()`, `whereNotNull()`;
- `orderBy()`, `orderByDesc()`;
- `value()`, `pluck()` и `update()`.

У `FeedItem::query()` нет схемы конкретной ленты. Такой запрос предназначен для
системных и физических колонок. Не используйте в нём логические имена.

### Лента в статье: контроллер и блейд

Типичный контроллер статьи отдаёт в блейд ленту и её записи:

```php
$feed = \Feed::where('code', 'products')->firstOrFail();
$items = $feed->items()
    ->where('__visible', true)
    ->orderByDesc('created_at')
    ->paginate(20);

return ['feed' => $feed, 'items' => $items];
```

В блейде поля записи доступны как свойства:

```blade
@foreach ($items as $item)
    <h2>{{ $item->title }}</h2>
@endforeach
```

### Одна запись

Запись, найденная по id, сама загрузит карту полей своей ленты:

```php
$item = FeedItem::find($id);

if ($item) {
    $title = $item->title;
}
```

Slug уникален только в пределах ленты, поэтому ищите его через отношение:

```php
$item = Feed::where('code', 'products')->firstOrFail()
    ->items()
    ->where('__slug', $slug)
    ->firstOrFail();
```

Если страница должна быть публичной только для опубликованных записей, добавьте
`->where('__visible', true)` и сюда.

### Значения полей

```blade
{{ $item->title }}
{{ $item->price }}
{{ $item->publishedAt?->format('d.m.Y') }}
{{ $item->featured ? 'да' : 'нет' }}
```

Дата из датового слота приводится к `Carbon`, целое — к `int`, флаг — к `bool`.
Метод `$item->fields()` возвращает логические поля вместе с системными данными.
Обычный `toArray()` намеренно сохраняет физическую форму модели.

```blade
{{ MproHelper::dump($item->fields()) }}
```

### Связи

В поле `link` хранится id другой записи. Связанная модель автоматически не
подгружается. Для списка заранее соберите справочник, чтобы не получить запрос
на каждой итерации:

```php
$categories = Feed::where('code', 'categories')->firstOrFail()
    ->items()
    ->pluck('title', 'id');
```

```blade
{{ $categories[$item->category] ?? '' }}
```

Админка и `itemSave` не позволяют сохранить несуществующую цель, запись из
другой ленты или связь, которая замыкает цепочку в кольцо. Прямая запись через
Eloquent эту API-проверку не запускает.

### Изображения

Поле типа `image` содержит массив:

```php
[
    'path' => '/storage/magicFeed/19/1.png',
    'alt'  => 'Описание изображения',
    'x'    => 1200,
    'y'    => 800,
    'mime' => 'image/png',
    'size' => 345678,
]
```

Для HTML берите `path` как URL без хоста:

```blade
<img
    src="{{ $item->image['path'] ?? '' }}"
    alt="{{ $item->image['alt'] ?? '' }}"
    width="{{ $item->image['x'] ?? '' }}"
    height="{{ $item->image['y'] ?? '' }}"
>
```

Хелперы уменьшения изображения принимают абсолютный путь файловой системы:

```php
$path = $item->image['path'] ?? null;
$img  = $path ? MproHelper::imageReduceX(public_path($path), 800) : null;
// $img['path'] — URL производной, пустой — картинки нет
```

Одно поле хранит одну картинку. Новая загрузка заменяет старую. Обычная загрузка
сохраняет исходный формат; кадрирование перекодирует результат в
`RESIZE_FORMAT`. Подробнее о ресайзе — `../image/use.md`.

### Текстовые подстановки и компоненты

Текст может содержать `#field#`, `#image.alt#` и одиночные теги компонентов.
Компоненты — статьи сайта, в дистрибутиве их нет: `<x-magic::img>` ниже работает,
только если на сайте заведена статья `img`.

```html
<x-magic::img :img="#image#" width="400" />
<iframe src="#videoUrl#"></iframe>
```

Такое поле выводите через:

```blade
{!! MproHelper::feedText($item, 'body') !!}
```

Метка неизвестного поля остаётся в тексте. Отсутствующий вложенный ключ даёт
пустую строку. Blade-код вокруг компонента не исполняется.

Текст оператора в обычных полях автоматически не очищается. Не выводите
непроверенный HTML через `{!! !!}`. Для Markdown оператора используйте
`MproHelper::mdToHtml()`.

## Создание и изменение записей

Предпочтительный способ — отношение ленты: схема уже передана будущей модели.

```php
$feed = Feed::where('code', 'products')->firstOrFail();

$item = $feed->items()->create([
    '__visible' => true,
    'title' => 'Сыр',
    'price' => 100,
]);

$item->update(['price' => 120]);
```

Прямой `FeedItem::create()` тоже поддержан, если передать корректный `feed_id`:
модель устанавливает его до заполнения логических полей. Отношение читается
яснее и исключает случайную запись не в ту ленту.

Валидация из схемы, `unique` и корректность полей `link` проверяются командой
`itemSave`, а не общим событием Eloquent. Прямая запись модели подходит
доверенному прикладному коду, который сам обеспечивает эти правила. Модель
всегда сохраняет собственные гарантии slug, позиции и защищённого удаления.

Удаляйте запись через модель:

```php
try {
    $item->delete();
} catch (RuntimeException $e) {
    // Another feed item still links to this item.
}
```

Вместе с записью удаляются её медиафайлы. Если на неё ссылаются, удаление
запрещено. Не применяйте массовый `->delete()` Query Builder: он обходит события
модели, проверку ссылок и корректное удаление файлов.

## Feed API

HTTP-точка: `POST /a_dmin/api/feed`. Она защищена middleware `magic.auth`.
Команда и параметры передаются одним объектом:

```json
{
  "command": "itemsList",
  "feedId": 2,
  "page": 1,
  "perPage": 20
}
```

Успешный ответ:

```json
{
  "status": true,
  "errorMsg": "",
  "data": {},
  "request": {}
}
```

При ошибке `status` равен `false`, описание находится в `errorMsg`. Ошибка
валидации записи дополнительно содержит `errors` по кодам полей.

### Команды

| Область | Команды |
| --- | --- |
| группы | `groupsList`, `groupCreate`, `groupSave`, `groupMove`, `groupDelete` |
| ленты | `feedsList`, `feedGet`, `feedCreate`, `feedSave`, `feedMove`, `feedClear`, `feedDelete` |
| схема | `schemaGet`, `schemaSave` |
| записи | `itemsList`, `itemGet`, `itemCreate`, `itemSave`, `itemMove`, `itemDelete`, `itemsDelete`, `itemLinks`, `itemsLookup` |
| изображения | `uploadFormat`, `imageUpload`, `imageCropUpload`, `imageDelete` |
| текст | `mdToHtml` |

### Список через API

```json
{
  "command": "itemsList",
  "feedId": 2,
  "page": 1,
  "perPage": 20,
  "orderBy": "__position",
  "direction": "asc",
  "filter": [
    { "field": "title", "op": "like", "value": "сыр" },
    { "field": "price", "op": ">=", "value": 100 }
  ]
}
```

Допустимые операции: `like`, `=`, `<>`, `>`, `>=`, `<`, `<=`. Фильтры
объединяются через `AND`. Поле должно быть физическим слотом или его логическим
именем; поле из `__data` использовать нельзя.

### Сохранение через API

```json
{
  "command": "itemSave",
  "id": 6,
  "visible": true,
  "slug": "syr",
  "fields": {
    "title": "Сыр",
    "price": 100
  }
}
```

Админская форма отправляет все свои поля. Сам обработчик принимает и частичный
объект `fields`: он проверяет и меняет только пришедшие значения. Неизвестные
поля отклоняются. `visible` и `slug` передаются отдельно.

Особые результаты удаления:

- `itemDelete` возвращает `false`, если запись удерживается ссылками;
- `itemLinks` показывает записи, которые на неё ссылаются;
- `itemsDelete` возвращает `{deleted, skipped}`;
- `feedClear` и `feedDelete` возвращают `false`, если после проходов остались
  записи, удерживаемые из других лент.

## Короткий список запретов

- Не читать публичную ленту без явного `__visible = true`.
- Не фильтровать и не сортировать по полям из `__data`.
- Не обращаться к логическому полю через голый `FeedItem::query()`.
- Не писать напрямую в `magicPro_feed_items` и не удалять записи массовым SQL.
- Не ожидать, что прямой Eloquent update применит validation/unique/link rules
  из Feed API.
- Не менять код занятого физического поля у ленты с данными.
- Не считать HTML оператора безопасным автоматически.
- Не править файлы, сгенерированные в `storage/dataMagicPro/`.

## Вёрстка текста записи

Эти правила относятся к текстовому описанию записи, а не к Blade всей страницы
ленты или карточки товара.


- используй простую семантическую HTML-разметку;
- сохраняй читаемость и смысл текста;
- основные теги: `<p>`, `<strong>`, `<ul>`, `<li>`, при необходимости `<h2>` и `<h3>` для внутренних смысловых разделов;
- не создавай контейнеры, карточки, колонки, фоновые блоки и сложную декоративную верстку;
- не добавляй собственный CSS;
- не используй inline-стили;
- не добавляй `<html>`, `<head>`, `<body>`;
- не добавляй главный `<h1>` в описание записи: его выводит шаблон страницы;
- разбивай длинный текст на короткие абзацы;
- списки оформляй через `<ul><li>`;
- важные фразы можно выделять через `<strong>`;
- не меняй смысл исходного текста и не добавляй факты от себя;
- ссылки и кнопки добавляй только если они присутствуют в исходном тексте.
