# Ленты: как пользоваться

Документ для того, кто **работает с готовыми лентами**: выводит их на сайте в
блейдах и контроллерах статей или дёргает API админки. Как модуль устроен внутри
и что делать при его правке — в `inside.md`, сюда это не нужно.

## Что такое лента

Лента — таблица данных, которую оператор заводит в админке сам: цены, новости,
тренинги. У ленты есть `code` (`products`, `news`), заголовок и **схема** —
описание её полей.

Все записи всех лент лежат в одной таблице `magicPro_feed_items`. Колонки в ней
фиксированные и безымянные по смыслу: `__string_1`, `__date_2`, `__bool_1` и так
далее, плюс json-контейнер `__data`. Схема ленты говорит, что `__string_1` этой
ленты — это `title`, а `__date_1` — `expiration`.

Поэтому в коде вы пишете **логические имена** (`title`, `price`), а физические
колонки не видите вообще.

## Три вещи, которые надо знать сразу

1. **Запись знает свою ленту.** У неё есть `feed_id`, по нему подтягивается схема.
   Поэтому `FeedItem::find($id)` сам разбирается, как называются его поля.
2. **Искать и сортировать можно только по слотам.** Поля, живущие в `__data`
   (тексты, картинки, json), читаются и пишутся как обычные, но в `where()` и
   `orderBy()` не годятся — у них нет своей колонки. Попытка даст понятную
   ошибку, а не тихо неверный результат.
3. **Новая запись скрыта.** `__visible` по умолчанию `false`, порядок `__position`
   считается сам.

## На сайте

`Feed` и `FeedItem` зарегистрированы алиасами, поэтому в блейдах и контроллерах
статей пишутся коротко, без `use`.

### Лента и её записи

```php
$items = Feed::where('code', 'products')->first()   // лента products или null
    ?->items()                    // её записи + её схема
    ->where('__visible', true)    // скрытые не показываем
    ->orderByDesc('created_at')   // новые сверху
    ->paginate(20, ['*'], 'page', $page);
```

`items()` — это запрос, к нему можно доклеивать условия и сортировку до тех пор,
пока не вызван `get()`, `first()`, `find()` или `paginate()`.

Идти именно через ленту важно: так запрос получает схему и понимает логические
имена. У голого `FeedItem::query()` схемы нет, там работают только физические и
системные колонки.

### Одна запись по id

```php
$item = $id ? FeedItem::find($id) : null;
```

Ленту знать не нужно. Если id чужой или его нет — вернётся `null`.

### Одна запись по slug

`__slug` — адрес записи для SEO, латиница в нижнем регистре: `pesnya-o-syre`. Он
уникален внутри ленты, поэтому читать надо через ленту, а не через `FeedItem`:

```php
$item = Feed::where('code', 'products')->first()
    ?->items()
    ->where('__slug', $slug)
    ->first();
```

Записи без адреса лежат с `NULL`, и таких может быть сколько угодно. Видимость в
запрос не входит: черновик открывается по адресу, чтобы его можно было
посмотреть.

### Чтение полей

```php
{{ $item->title }}                        {{-- строка --}}
{{ $item->price }}                        {{-- целое --}}
{{ $item->expiration?->format('d.m.Y') }} {{-- дата: это Carbon --}}
{{ $item->hasDiscount ? 'да' : 'нет' }}   {{-- boolean --}}
{!! $item->description !!}                {{-- текст с разметкой --}}
```

Даты приходят объектами `Carbon`, числа — числами, флаги — `bool`.

Для отладки есть `$item->fields()` — весь набор под логическими именами, вместе с
`id`, `feed_id`, `__slug`, `__position`, `__visible` и датами:

```blade
{{ MproHelper::dump($item->fields()) }}
```

### Поле связи

В колонке связи лежит **id** записи другой ленты, а не её название. Разворачивать
надо самому — одним запросом на всю страницу:

```php
$categories = Feed::where('code', 'categories')->first()
    ?->items()->pluck('title', 'id') ?? collect();

// в цикле
{{ $categories[$item->category] ?? '' }}
```

### Поле картинки

Массив с готовыми размерами — их стоит проставить в атрибуты, иначе страница
прыгает при загрузке:

```blade
<img src="{{ $item->img1['path'] ?? '' }}"
     alt="{{ $item->img1['alt'] ?? '' }}"
     width="{{ $item->img1['x'] ?? '' }}"
     height="{{ $item->img1['y'] ?? '' }}">
```

Ключи: `path`, `alt`, `x`, `y`, `mime`, `size`. `path` — адрес без хоста,
`/storage/magicFeed/19/1.png`: он же в `src`, он же в `public_path()` для
ресайза. `alt` пишет оператор в форме, остальное — загрузка.

Кадрирует оператор в браузере, при загрузке. Обрезанный кусок уходит на сервер
голыми пикселями, а в рабочий формат его кодирует сервер — тот же, что стоит в
`RESIZE_FORMAT`. Загрузка без обрезки сохраняет файл как есть, со своим форматом.
Подробнее — `docs/ru/image.md`.

**Имя файла.** В окне загрузки есть список «имя файла взять из» — в нём
строковые слоты записи. Выбрал слот, имя собралось из его текущего значения:
латиница в нижнем регистре, цифры и дефис, всё прочее выброшено. Так же
разбирается и имя выбранного файла.

Набранное руками не подменяется, а проверяется при сохранении: что-то кроме
латиницы, цифр и дефиса — тост с ошибкой и картинка не уходит. Молча чинить
нельзя: `ууу` превратилось бы в `uuu`, и оператор остался бы уверен, что
сохранил написанное.

Имя режется до 217 символов. Число не круглое: файловая система держит 255 байт
на имя, а к имени в кеше ресайза приписывается ось с размером и расширение — в
худшем случае `_x10000.iwebp.webp`, восемнадцать символов. Остаток ещё на
двадцать меньше, про запас.

**alt.** Рядом такой же список «alt взять из», с теми же слотами, но значение
берётся как есть, без транслитерации: это подпись для человека, а не кусок
адреса. Убираются только угловые скобки и кавычки обоих видов — строка уезжает в
атрибут HTML, и незакрытая кавычка ломает тег. Амперсанд остаётся, «Чай & кофе»
— обычный текст, экранирует его блейд при выводе.

`alt` уезжает на сервер вместе с файлом и ложится в запись сразу, как и сам
файл: сохранять запись после загрузки не надо. Тот же `alt` правится и в форме,
под кнопками поля, — вот там он ждёт «Сохранить», как остальные поля.

Картинка не сохраняется, пока не заполнены оба поля — имя и `alt`. Кнопка
«Сохранить» до этого не появится. «Обрезать» появляется всегда: рамке имя с
подписью ни к чему.

### Текст с картинками и вставками

В тексте записи можно ставить подстановки и теги magic-компонентов:

```html
<x-magic::img :img="#img1#" width="400" mobile="2" />
<iframe src="#urlYoutube#"></iframe>
```

Выводится такое поле через хелпер, он их и разворачивает:

```blade
{!! MproHelper::feedText($item, 'body') !!}
```

`#code#` — значение поля записи, `#code.key#` — ключ внутри него. Атрибут с
двоеточием получает значение как есть, массив остаётся массивом; без двоеточия —
текстом. Поля нет в записи — метка остаётся буквами, а незаполненный ключ вроде
`#img1.alt#` даёт пусто.

Текст без меток и тегов хелпера не требует, хватит `{!! $item->body !!}`.

Какие компоненты есть и что они принимают — `docs/ru/components/use.md`.

### Создание и правка

```php
$item = Feed::where('code', 'products')->first()
    ?->items()
    ->create([
        '__visible' => true,       // иначе запись не покажется
        'title'     => 'Сыр',
        'price'     => 100,
    ]);

$item->update(['price' => 120]);
```

Создавать через ленту, а не `FeedItem::create()`: новой записи неоткуда узнать
схему, пока у неё нет ленты.

### Удаление

```php
try {
    $item->delete();   // вместе с записью уходят её файлы
} catch (\RuntimeException $e) {
    // на запись ссылаются из другой ленты, она не удаляется
}
```

### Готовые куски кода

В админке на экране ленты есть вкладка **Билдер**: рецепты «Запись по id»,
«Создать запись», «Изменить запись по id», «Удалить запись по id» и конструктор
списка с условиями, сортировкой и пагинацией. Код там собирается по схеме
открытой ленты, с её настоящими именами полей, и копируется целиком.

## Через API

Одна точка: `POST /a_dmin/api/feed`, за middleware `magic.auth`. Команда едет в
теле запроса вместе с параметрами:

```json
{ "command": "itemsList", "feedId": 2, "page": 1, "perPage": 20 }
```

Ответ всегда одной формы:

```json
{ "status": true, "errorMsg": "", "data": {}, "request": {} }
```

При ошибке `status: false` и текст в `errorMsg`. У ошибки проверки полей
добавляется `errors` — разбор по полям, `{"title": ["..."]}`.

### Команды

- группы: `groupsList`, `groupCreate`, `groupSave`, `groupMove`, `groupDelete`
- ленты: `feedsList`, `feedGet`, `feedCreate`, `feedSave`, `feedMove`,
  `feedClear`, `feedDelete`
- схема: `schemaGet`, `schemaSave`
- записи: `itemsList`, `itemGet`, `itemCreate`, `itemSave`, `itemMove`,
  `itemDelete`, `itemsDelete`, `itemLinks`, `itemsLookup`
- файлы: `imageUpload` (multipart), `imageCropUpload` (multipart), `imageDelete`
- прочее: `uploadFormat`, `mdToHtml`

### Список записей

```json
{
  "command": "itemsList",
  "feedId": 2,
  "page": 1,
  "perPage": 20,
  "orderBy": "__position",
  "direction": "desc",
  "filter": [{ "field": "title", "op": "like", "value": "сыр" }]
}
```

Операции фильтра: `like` (проценты сервер ставит сам), `=`, `<>`, `>`, `>=`, `<`,
`<=`. Поле — логическое имя, и только слот.

`orderBy` и `direction` в запросе — про этот запрос. Порядок, с которого список
открывается в админке, живёт в схеме ленты (`orderBy`, `orderDir`) и задаётся на
экране колонок списка: строковое поле или дата, вверх или вниз. Не задан — свой
порядок ленты.

Запись приходит так:

```json
{
  "id": 6,
  "feedId": 2,
  "slug": "syr",
  "position": 0,
  "visible": true,
  "created_at": "...",
  "updated_at": "...",
  "fields": { "title": "Сыр", "price": 100 }
}
```

### Что стоит помнить

- `itemSave` сохраняет запись целиком: присылать надо все поля формы, а не
  изменённые. `visible` и `slug` идут отдельными параметрами, это системные
  колонки.
- `slug` в `itemSave` имеет смысл только у ленты без источника в схеме. Если
  источник задан, присланное значение всё равно будет пересчитано из поля.
- `itemDelete` возвращает `false`, а не ошибку, если на запись ссылаются. Кто
  именно держит — покажет `itemLinks`.
- `itemsDelete` удаляет группой: убирает что может и возвращает
  `{deleted, skipped}`, где `skipped` — удержанные ссылками.
- `itemsLookup` отдаёт не больше 20 записей: это список для выпадашки поля связи,
  а не способ выгрузить ленту.
- `imageUpload` кладёт файл как прислали, `imageCropUpload` — перекодирует его в
  `RESIZE_FORMAT`. Это разные команды, а не флаг: обрезанный кусок и обычный файл
  требуют разного обращения. `uploadFormat` отвечает, чем слать кроп, — png или
  jpeg.
- Обе команды загрузки принимают `alt` рядом с файлом и пишут его в запись.
  Не прислали — остаётся прежний. Кавычки и угловые скобки сервер вырезает сам.
- `schemaSave` проверяет схему целиком. Переименовать `code` поля нельзя, если в
  ленте уже есть записи.

## Чего делать не надо

- Писать в `magicPro_feed_items` напрямую SQL: мимо модели не посчитается
  `__position`, не проверятся связи и не уйдут файлы.
- Искать по полю из `__data`.
- Править сгенерированные файлы в `storage/dataMagicPro/` — они перезаписываются.
