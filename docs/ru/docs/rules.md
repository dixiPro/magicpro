# Правила документации

## Документация хранится

docs/ru

Ссылка на любую документация должна быть в файле `docs/ru/index.json`

## Обязательные документы

Внутри папки обязателенн файла:

- `about.md` — назначение модуля;
- `use.md` — использование снаружи;
- `inside.md` — внутреннее устройство.

Кроме перечисленных могут присутсвовать и другие документы.

## Структура данных

- **Структура данных — самая важная часть описания.** Документация любой подсистемы обязана описывать все таблицы с колонками и типами, содержимое полей, значения по умолчанию при создании записи и связи между таблицами. Если базы нет, описать заменяющую её структуру: формат файла, ключи ответа или структуру JSON.

## Источник истины

- **Источник истины — код, затем документация.** `CHANGELOG.md` не является
  источником истины: не определять по нему поведение, не сверять с ним код и
  документацию и не исправлять его заодно. Если код расходится с документацией,
  исправлять документацию по коду.
- **ТЗ описывает, что требуется сделать; документация — что уже сделано.** Не
  дописывать ТЗ задним числом по результатам работы.

## Ограничения

- **Ограничения значений описывать словами, а не регулярным выражением.** Например:
  «латинские буквы, цифры, дефис и подчёркивание». Регулярное выражение допустимо,
  когда документируется сама строка проверки, но рядом всё равно нужно объяснение
  словами.
- Не вписывать в документ собственные решения, о которых не договаривались. Такие
  предложения обязатеьлно сообщать.
- Баги, фитчи, задачи и находки обязательно сообщать.
- Команды записывать в документацию. Не оставлять их только в чате для ручного переноса.

## Язык

Язык документации используется без отката на другой язык. Если
`docs/<language>/index.json` отсутствует, документации на этом языке нет. Сейчас
поддерживается только `ru`.

`docs/ru/helpers/use.md` нельзя редактировать вручную. Он создаётся командой
`php artisan magicpro:docs` из PHPDoc класса `MproHelper`: описание класса
становится вступлением, описания методов — справочником.

MCP-агент читает эту же документацию: `list-docs` возвращает оглавление, а
`get-doc` — содержимое файла. У него нет доступа к репозиторию и shell, поэтому
документация является для него единственным источником сведений о проекте.
