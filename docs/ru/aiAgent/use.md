# AI-агент: как пользоваться

## Что нужно на сервере

1. `tmux` — сеанс агента живёт в нём.
2. Сам агент, установленный и работающий из командной строки от того же
   пользователя, от которого работает php.
3. MCP, добавленный агенту руками, — от того же пользователя, от которого
   работает php (см. «Права и HOME»).
4. Правила агента — файл `AGENTS.md` в его рабочей папке. Без него раздел агента
   не запустит: агент без правил — это агент, которому можно всё, а ему дают
   shell на сервере.

   Образец лежит в пакете, `docs/ru/aiAgent/AGENTS.example.md`. Скопировать в
   рабочую папку под именем `AGENTS.md` и переписать под свой сайт. Что в нём
   написано, MagicPro не разбирает — это правила агента, а не настройка: он
   только смотрит, что файл есть.

   Рабочая папка задаётся ключом `cwd`. Поменял `cwd` — правила должны переехать
   вместе с ней.

Есть ли `tmux`, показывает главная страница админки: раздел «Проверено», строка
`tmux на месте`. Проверка появляется только когда лежит `configAI.php`.

## Права и HOME

Агент запускается от пользователя php — обычно `www-data`. Логин, настройки и
список MCP агент держит у себя в домашнем каталоге, а у `www-data` это
`/var/www`, и по умолчанию он ему не принадлежит. Отсюда `Permission denied` в
первой же строке вывода.

Свой дом ему, а не доступ в чужой: делиться собственным `~/.codex` — значит
отдать веб-серверу свой логин в OpenAI.

Один раз на сервере:

```bash
# дом, в который агенту можно писать
sudo mkdir -p /var/www/.codex
sudo chown -R www-data:www-data /var/www/.codex
sudo npm install -g @openai/codex

# логин; codex напечатает ссылку — открыть её в своём браузере
sudo -u www-data -H codex login

# MCP этого сайта, от того же пользователя
sudo -u www-data -H codex mcp add magicpro -- php artisan mcp:start magicpro

# проверка: агент должен подняться и показать себя
sudo -u www-data -H codex
```

`sudo -u www-data` работает, хотя в `passwd` у него `/usr/sbin/nologin`: `sudo`
без `-s` и `-i` логин-шелл не спрашивает. `-H` ставит `HOME=/var/www` — тот же,
что увидит агент, запущенный из админки.

Обновлять самого агента из окна сеанса нельзя: `npm install -g` пишет в
системный `node_modules` и в кеш `/var/www/.npm`, а `www-data` туда не пустят —
предложение обновиться надо пропускать. Обновление делается из обычной консоли,
`sudo npm install -g @openai/codex`. Разделу всё равно, какая версия лежит: он
зовёт то, что написано в `startCommands`.

Правила агента (`CODEX.md`, `AGENTS.md` — что он читает) лежат в рабочей папке,
то есть в корне проекта, и от прав не зависят.

## configAI.php

Файл `storage/app/private/ai-sessions/configAI.php`. Руками его класть не надо:
установка копирует туда образец из пакета — `src/Config/configAI.php`, — если
файла нет. Дальше сайт правит свою копию, пакет к ней больше не прикасается.

Копия приходит с пустым паролем, то есть с выключенным разделом: `MCP` покажет
«пароль пустой, задайте пароль в файле» и адрес файла. Пустой пароль — это
выключатель, а не забытая настройка: раздел даёт shell на сервере.

```php
<?php

return [
    'password' => '09674',

    'agents' => [
        [
            'name' => 'codex',
            'cwd' => '/var/www/site',
            'env' => [
                'HOME' => '/var/www',
            ],
            'startCommands' => [
                ['Продолжить (рекомендуется)' => 'codex resume --last'],
                ['Выбрать сеанс' => 'codex resume'],
                ['Заново' => 'codex'],
            ],
            'exitCommands' => [
                ['завершить' => '/exit'],
            ],
        ],
    ],

    'poll_interval' => 1000,        // как часто браузер спрашивает новый вывод, мс
    'session_timeout' => 600,       // молчит столько секунд — сеанс закрывается
    'session_kill_timeout' => 720,  // молчит столько секунд — сеанс убивается
];
```

Ключи:

- **password** — дополнительный пароль, его спрашивают при каждом запуске. Пустой
  пароль запрещает запуск и выключает раздел: он даёт shell на сервере, и входа
  в админку для этого мало.
- **agents** — список агентов. Агент один — можно писать его одного ключом
  `agent`, без списка.
- **name** — имя агента. Из него собирается имя сеанса, поэтому в нём остаются
  только латинские буквы и цифры, остальное выбрасывается.
- **cwd** — рабочая папка агента. Пусто или нет ключа — корень проекта. В ней
  агент ищет свои правила (`AGENTS.md`, `CODEX.md`) и в ней же работает.
- **env** — переменные окружения сеанса. Php отдаёт агенту своё окружение, а оно
  почти пустое: `HOME` от `www-data`, `PATH` службы. Что агенту нужно другое —
  пишется сюда. Имя переменной — латинские буквы, цифры и подчёркивание,
  остальные ключи пропускаются; значение любое.
- **startCommands** — чем запускать, подписью и командной строкой. Первая в
  списке предлагается по умолчанию.
- **exitCommands** — чем завершать. Первая из них уходит агенту, когда сеанс
  закрывает уборка.
- **poll_interval** — не быстрее 200 мс.
- **session_timeout**, **session_kill_timeout** — считаются от последнего
  запроса браузера за новым выводом, а не от начала сеанса.

Командные строки в браузер не попадают: экран показывает только подписи, а
обратно шлёт номера.

## Работа

`/a_dmin/mcp`, раздел `MCP` в левой колонке. Открыт администратору.

1. **старт** — выбрать агента и команду запуска.
2. **Запустить** — ввести дополнительный пароль.
3. Открывается окно сеанса: история вывода, поле команды, кнопки.

В окне:

- **Перечитать** — показать не только экран, но и всё, что ушло вверх за его
  край. Нужно для длинного ответа: окно агента — пятьдесят строк, остальное
  уезжает в буфер прокрутки.
- **поле команды** — три строки, растёт под текст. `Enter` переносит строку,
  отправляет `Ctrl+Enter` или кнопка **Отправить**.
- **Завершить** — команд завершения одна, уходит сразу; несколько — сперва
  спросят, какая.

Когда агент кончился, кнопки пропадают, а история остаётся на экране до ухода со
страницы.

### Промпты

То, что набирают агенту чаще одного раза: имя и текст. Кнопка «Промпты» есть на
экране до запуска и рядом с «Отправить» в живом сеансе.

В редакторе: «Добавить промпт» заводит строку сверху, корзина убирает,
«Сохранить» пишет весь список разом. Пока не нажал «Сохранить», ничего не
потеряно — поэтому подтверждения на удаление нет.

В сеансе кнопка «Промпты» открывает список названий. Клик **вставляет** текст в
поле команды, а не отправляет: в промпте почти всегда остаётся дописать имя
статьи или номер записи. Поле не затирается — если в нём уже что-то есть, промпт
приписывается с новой строки, — и список остаётся открытым: два промпта нередко
нужны подряд.

Список общий на сайт, а не свой у каждого администратора: их немного, а удачный
промпт полезнее общим. Лежит он в
`storage/app/private/ai-sessions/commands.json`.

### Убить мои сеансы

Кнопка на странице, когда живого сеанса на экране нет. Убивает всех агентов,
запущенных этим администратором, — и тех, чьи вкладки давно закрыты.

Нужна она вот зачем. Агент, продолжающий прежний разговор (`codex resume
--last`), держит его открытым, и второй такой же запуск получает отказ: тред уже
занят. Если вкладка с первым сеансом закрыта, завершить его по-хорошему некому —
только этой кнопкой или дождавшись уборки.

Чужие сеансы кнопка не трогает.

## Что нужно знать

**Сеанс живёт, пока открыта вкладка.** Имя сеанса нигде не хранится. Перезагрузили
страницу — к прежнему агенту не вернуться, откроется чистый экран.

**Забытый агент закрывается сам.** Крон раз в минуту смотрит, когда браузер в
последний раз спрашивал экран. Молчит дольше `session_timeout` — агенту уходит
команда завершения, дольше `session_kill_timeout` — сеанс убивается.

Всё, что уборка сделала, пишется в `storage/logs/aiSession.log`: что за сеанс,
что с ним сделали и сколько он молчал. Это и есть способ проверить, что забытый
агент действительно убран, — рядом с ним пропадает файл
`storage/app/private/ai-sessions/poll/<сеанс>.log`.

**Крон нужен.** Нет крона — забытые агенты остаются на сервере навсегда.

**Пустые строки схлопнуты.** Агент отбивает ими блоки, но отбивает щедро: подряд
идущие пустые строки показываются одной, а сверху экрана не показываются вовсе.

**Вопрос выделен жирным.** Codex ставит перед набранным `›`, и на странице такая
строка идёт жирной: в потоке ответа её иначе не найти.

**Показывается экран агента, а не лента вывода.** Агент не печатает строки, он
перерисовывает своё окно, и на странице оно так и показано: целиком, как его
видит `tmux`. Цветов и рамок нет — только текст, — но строки стоят на своих
местах.

**Буфер прокрутки — 10000 строк.** На экране всегда последние 200, «Перечитать»
показывает всё, что помнит буфер. Что ушло выше, не вернуть.

**Одновременных сеансов сколько угодно.** Каждый запуск — свой сеанс и свои
файлы; в имя входит время, поэтому два запуска подряд не сталкиваются.
