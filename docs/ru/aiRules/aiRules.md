# MagicPro package

**MagicPro** is a CMS that combines the speed of a CMS with the flexibility of Laravel 13.
Controllers, Blade views, routes, pages, menus and settings are managed through a single
database structure (Articles) and an admin panel instead of scattered files.

This file only says where to read. Nothing is imported here: the documentation changes on
its own, this file stays.

**Read before touching the code**

**Читать перед любой правкой кода. Это приказы, а не пожелания.**

## Документация

- Описана в файле docs\ru\index.json
- Читай ее
- Поле "agent": true относится к MCP агенту

Порядок и имена разделов задаёт [`docs/ru/index.json`](../index.json). Обход папок
не определяет ни порядок, ни человеческие названия. Новый файл нужно добавить в
индекс, иначе он не появится в разделе документации админки.

Запись или группа в индексе с `"agent": true` доступна MCP-агенту через
`list-docs`. Без этой пометки страница остаётся только в админке. Для каждой новой
страницы нужно заполнить `about` — краткое описание, по которому агент выбирает,
что читать.

У проекта есть собственный MCP-сервер `magicpro`. Задачу, которую можно выполнить
его инструментом, выполнять инструментом, а не ручной правкой файлов.

- Документацичя docs\ru\index.json ->"name": "МСП"

## Ленты

- Не писать напрямую SQL в `magicPro_feed_items`: в обход модели не рассчитывается
  `__position`, не проверяются ссылки и не удаляются файлы.
- Записи создавать через ленту (`$feed->items()->create()`), а не через
  `FeedItem::create()`: без ленты новая запись не знает своей схемы.
- Искать и сортировать можно только по слотам. Поля из `__data` для этого не
  подходят: у них нет отдельных колонок.
- Запись, на которую ссылаются, нельзя удалить. Кольца связей запрещены.
- Новый слот требует новой миграции, константы в `FeedItem` и индексов. Старую
  миграцию не менять.
- Любое изменение схемы проводить через сохранение ленты, иначе не увеличится
  `schemaGeneration` и разойдутся устаревшие карты.

### Структура файлов

Для каждого модуля используется отдельная папка по названии системы, примеры

```text
docs/ru/mainUse/   сборка сайта: статьи, маршруты, вёрстка
docs/ru/mainDev/   разработка пакета: ядро, установка, поиск ошибок
docs/ru/feed/      ленты
docs/ru/image/     ресайзер
docs/ru/mail/      почтовая система
docs/ru/mcp/       MCP-сервер
docs/ru/helpers/   MproHelper
```
