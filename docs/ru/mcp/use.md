# MCP MagicPro: руководство пользователя

MCP-сервер даёт ИИ-агенту доступ к сайту через ограниченный набор инструментов
MagicPro. Агент не получает shell от сервера, но доступ всё равно
привилегированный: он может менять Blade и PHP-контроллеры статей, записи лент
и некоторые файлы.

В текущей реализации зарегистрировано 18 инструментов. Все они доступны одному
и тому же токену; серверных ролей «только чтение» и «чтение с записью» нет.

## Перед первым подключением

1. Войдите в админку пользователем с ролью `admin`.
2. Откройте `/a_dmin/mcp`.
3. Нажмите «Получить токен» и сразу скопируйте его: второй раз открытый токен
   сайт не покажет.
4. Адрес МСП — на той же странице, вида `https://example.com/mcp/magicpro`.

Перед тем как пустить агента, сделайте экспорт `root` (правый клик по root в
дереве → «Экспорт») и сохраните файл: полный импорт этого файла вернёт дерево
статей. Ленты и обычные файлы он не возвращает — для них ночной дамп.

## Подключение агента на Windows

На странице `/a_dmin/mcp` кнопка **install.zip** — готовая папка агента:

| Файл | Зачем |
| --- | --- |
| `runClaude.bat`, `runCodex.bat` | спрашивают токен и запускают агента; токен живёт только в переменной `MAGICPRO_TOKEN` этого окна |
| `runClaudeContinue.bat`, `runCodexContinue.bat` | то же, но продолжают прошлый разговор (`claude --continue`, `codex resume --last`) |
| `.mcp.json` | адрес МСП для Claude Code, уже вписан |
| `.codex/config.toml` | адрес МСП для Codex, уже вписан |
| `AGENTS.md` | три строки: работать через МСП и первым делом прочитать правила с сайта — страницу «Правила МСП-агента» (`mcp/agent.md`); `CLAUDE.md` отсылает к нему |
| `readme.md` | как установить |

Распаковать в любую папку, запустить `.bat`, ввести токен. При первом запуске
Claude Code спросит, подключать ли сервер из `.mcp.json`, Codex — доверять ли
папке; оба раза — да. Протух токен — взять новый и перезапустить `.bat`.

Токен ни в один файл не пишется. Архив собирается на лету из заготовки
`docs/mcp-install/`; нет PHP-расширения `zip` — страница вместо кнопки говорит
об этом. Архива для Linux пока нет.

## Локальное подключение через stdio

Если Codex и Laravel-проект находятся на одной машине, можно запустить тот же
сервер через Artisan:

```bash
codex mcp add magicpro-local -- \
  php /absolute/path/to/project/artisan mcp:start magicpro
```

Эквивалентная ручная настройка:

```toml
[mcp_servers.magicpro-local]
command = "php"
args = ["artisan", "mcp:start", "magicpro"]
cwd = "/absolute/path/to/project"
```

Локальному входу токен не нужен. Он работает с полномочиями процесса Laravel и
не проходит через `TokenMiddleware`. Поэтому локальные MCP-вызовы не попадают в
MCP-журнал, а автор сохранения статьи в архиве будет иметь `userId = 0`.

## Срок жизни и отзыв токена

Токен имеет вид `<user_id>___<случайная строка>`. Сайт хранит только его
SHA-256-хеш.

| Свойство | Поведение |
| --- | --- |
| Кто может получить | только пользователь админки с ролью `admin` |
| Количество | один токен на пользователя |
| Бездействие | один час после последнего принятого HTTP MCP-запроса |
| Полный срок | одни сутки от выдачи независимо от активности |
| Привязка | точное значение IP, увиденное Laravel при выдаче |
| Новый токен | сразу заменяет прежний |
| Отзыв | кнопка «Отозвать» на `/a_dmin/mcp` |

Понижение роли или удаление пользователя гасит его токен сразу: при каждом
вызове проверяется, что владелец существует и он администратор, иначе 403.

## Работа агента со статьями

Порядок начала сессии, чтение статей, навигация по дереву, создание,
сохранение, перемещение и подтверждение удаления описаны в
[руководстве МСП-агента](../mainUse/mcp.md). Правила самой статьи — в
[руководстве по сайту](../mainUse/use.md).

## Служебные инструменты и документация

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `get-project-name` | нет | строка `config('app.name')` |
| `get-version` | нет | строка `MAGIC_VERSION`, как в заголовке админки |
| `list-docs` | нет | `docs`: доступные агенту страницы текущего языка |
| `get-doc` | `path` | исходный Markdown одной страницы |

`list-docs` возвращает объект `docs`: список с полями `section`, `name`,
`about` и `path`. Путь для `get-doc` берите из этого ответа. Инструмент
проверяет наличие страницы в индексе её языка, разрешение `agent: true`
и существование файла. Произвольный путь или неразрешённая страница отклоняются.

## Ленты: чтение

Все команды чтения идут через один инструмент:

```json
{
  "command": "itemsList",
  "params": { "feedId": 3, "page": 1, "perPage": 50 }
}
```

| Команда | Параметры | Ответ |
| --- | --- | --- |
| `feedsList` | `groupId?` | `results`: ленты с `id`, `code`, `title`, `groupId`, `position`, `itemsCount` |
| `feedGet` | `id` или `code` | лента и полный `schema` |
| `itemsList` | `feedId`, `page?`, `perPage?`, `orderBy?`, `direction?`, `filter?` | `items`, `page`, `perPage`, `total`, `lastPage` |
| `itemGet` | `id` | одна запись |

Сначала вызовите `feedsList`, затем `feedGet`: логические коды и типы полей
определяет схема конкретной ленты, угадывать их нельзя.

Запись имеет форму:

```json
{
  "id": 15,
  "feedId": 3,
  "slug": "example",
  "position": 0,
  "visible": true,
  "created_at": "...",
  "updated_at": "...",
  "fields": {
    "title": "Пример"
  }
}
```

`perPage` всегда не меньше 1, а MCP ограничивает максимум числом 250. Значение
по умолчанию внутри Feed API — 20. Направление — `asc` или `desc`, любое другое
значение превращается в `asc`.

`filter` — список условий `{field, op, value}`. Допустимы `like`, `=`, `<>`,
`>`, `>=`, `<`, `<=`. Логические поля, лежащие внутри `__data`, нельзя
фильтровать и сортировать. Для обычной работы используйте логические коды схемы
и системные поля `id`, `created_at`, `updated_at`, `__position`, `__visible` и
`__slug`.

## Ленты: запись

Через `feed-api-write` доступны только три команды.

### itemCreate

```json
{ "command": "itemCreate", "params": { "feedId": 3 } }
```

Создаёт в конце ленты скрытую запись с умолчаниями схемы. Значения этим вызовом
не принимаются.

### itemSave

```json
{
  "command": "itemSave",
  "params": {
    "id": 15,
    "fields": {
      "title": "Новый заголовок",
      "price": 1200
    },
    "visible": true
  }
}
```

**Частичное обновление**: меняются только переданные коды, остальные поля
сохраняются — присылайте только то, что меняется. `visible` и `slug` — отдельные
системные параметры. Если в схеме задан `slugFrom`, модель пересчитает slug из
поля и перезапишет присланное значение.

Поля типа `image` не передавайте даже без изменения: MCP откажет всему
`itemSave`, если встретит код картинки. Изображения меняются только через
загрузку и кроппер админки.

Валидация текущей реализации применяется только к присланным полям. При
создании записи самостоятельно проверьте правила `validation` в схеме и не
делайте запись видимой, пока все обязательные значения не заполнены.

### itemDelete

Сначала запросите предварительный просмотр:

```json
{
  "command": "itemDelete",
  "params": { "id": 15, "confirm": false }
}
```

Ответ содержит `confirmRequired` и `willDelete`: идентификатор, ленту, первый
читаемый заголовок и `holders` — записи, которые ссылаются на удаляемую.
Повторный вызов с `confirm: true` удаляет одну запись и её media-файлы. Если на
неё всё ещё ссылаются, API откажет.

## Ленты: структура

Инструмент `feed-api-schema` создаёт ленты и настраивает их: группы, код,
название, схему. Записи по-прежнему пишет `feed-api-write`.

**Пока в ленте нет записей, с ней можно всё. Появилась первая запись — лента для
МСП закрыта:** `feedSave` и `schemaSave` отказывают с текстом
`The feed N has records: its structure is changed only in the admin panel.`
Код, название, группу и схему заполненной ленты меняет человек в админке.
Поэтому структуру доводят до конца до первого `itemCreate`.

| Команда | Параметры | Что делает |
| --- | --- | --- |
| `groupsList` | — | группы лент |
| `groupCreate` | `title` | новая группа в конце списка |
| `feedCreate` | `groupId` | пустая лента со сгенерированным кодом |
| `feedSave` | `id`, `code?`, `title?`, `groupId?` | код, название, группа; меняется только присланное |
| `schemaGet` | `feedId` | схема как хранится |
| `schemaSave` | `feedId`, `schema` | схема целиком, со всеми проверками админки |

Схема сохраняется **только целиком**: `schemaGet` → правка → `schemaSave` со
всем объектом. Проверки «слот занят один раз» и «код уникален» имеют смысл
только на полном наборе полей. Формат схемы и слоты — в
[документации лент](../feed/use.md#работа-в-админке).

Порядок:

```text
groupsList → groupCreate (если нужна новая) → feedCreate → feedSave (code, title)
→ schemaSave → itemCreate / itemSave
```

Удалять, очищать и перемещать ленты и группы через МСП нельзя.

## Обычные файлы

Контракт инструментов:

| Инструмент | Аргументы | Ответ |
| --- | --- | --- |
| `read-file` | `fileName` | `fileData` |
| `save-file` | `fileName`, `fileData` | `status: 1` |
| `list-dir` | `path` (необязателен) | `path`, `items` |
| `make-dir` | `folderName` | `created` |

Разрешённые расширения: `txt`, `rtf`, `csv`, `css`, `js`, `json`, `xml`, `sql`,
`md`. `save-file` не создаёт файл и заменяет существующий целиком. Статьи через
эти инструменты не редактируются.

Файл должен находиться внутри `public/` + `PUBLIC_UPLOAD_DIR`. Например,
при стандартном каталоге загрузок передавайте `fileName: "/design/site.css"`.
Проверка отклоняет `..`, отсутствующий корень или файл, каталог вместо файла
и путь, который после `realpath()` оказался вне разрешённого дерева.
Перед `save-file` прочитайте актуальный файл через `read-file`: запись заменяет
его содержимое целиком и не использует атомарную замену временным файлом.

`list-dir` отдаёт содержимое одной папки: сначала папки, потом файлы; у каждого
элемента `name`, `type` (`dir` или `file`), `mime`, `size`, `mtime`, у картинок
ещё `width` и `height`. Без `path` показывается сам каталог загрузок, и его путь
возвращается в ответе — агенту не нужно знать настройку `PUBLIC_UPLOAD_DIR`.

`make-dir` создаёт папку внутри того же каталога, недостающие родительские папки
создаются по пути. Уже существующая папка — ошибка, ничего не перезаписывается.
Удаления и переименования через МСП нет.

## Проверка результата и восстановление

- Проверку статей и дерева выполняйте по [порядку работы со статьями](../mainUse/mcp.md).
- Запись ленты после сохранения перечитайте через `itemGet`.
- Изменённую страницу запросите обычным HTTP и убедитесь, что она не отвечает
  500.
- Ошибка инструмента останавливает цепочку, но сейчас не гарантирует rollback.
  В частности, сбой записи файлов при `save-article` может произойти
  после сохранения текста в базе; `warning` означает отказ публикации контроллера. После ошибки перечитайте объект и проверьте страницу до
  любых следующих действий.

Архив статьи создаётся при `save-article`, но не является общей резервной
копией. Экспорт `root` возвращает статьи целиком, однако не возвращает ленты и
обычные файлы. Удаление и восстановление выполняет человек из админки.

## Частые проблемы

### `401 no token`

Переменная `MAGICPRO_KEY` отсутствует в окружении процесса Codex либо клиент не
отправляет заголовок `Authorization: Bearer ...`. Задайте переменную и
перезапустите клиент.

### `401 unknown token`

Токен отозван или заменён новым. Получите новый на `/a_dmin/mcp`.

### `401 the token expired`

Прошёл час без принятого запроса или сутки от выдачи. Получите новый токен.

### `401 the token was issued for another address`

Laravel увидел разные IP при выдаче и при MCP-запросе. Проверьте VPN, прокси,
Cloudflare и настройку доверенных прокси приложения. Выдавайте токен по тому же
сетевому пути, которым пользуется агент.

### Сервер есть, но документации нет

Вызовите `list-docs`. Если нет индекса текущего языка, переключите `LANGUAGE` на
`ru`; английского дерева документации в этой ревизии нет.

### Что записывается в журнал

Только удалённый HTTP-вход пишет принятые и отклонённые запросы в датированные
файлы `storage/logs/mcp-YYYY-MM-DD.log`, хранящиеся 14 дней. В журнале есть IP,
user id, JSON-RPC-метод и имя инструмента, но нет токена и аргументов. Локальный
stdio-вход в этот журнал не пишет.
