# МСП: назначение

MCP-сервер проекта: через него ИИ-агент работает с сайтом напрямую.

## Зачем он

Админка и её API живут за middleware `magic.auth`, то есть за сессией браузера.
Агент из консоли туда не попадёт: у него нет ни куки, ни браузера. А работать ему
надо ровно с тем же — со статьями, их блейдами и контроллерами.

Ходить в базу напрямую нельзя: сохранение статьи не запись строки, оно
перегенерирует файлы и пересчитывает дерево. Значит нужен вход, который делает то
же, что админка, со всеми её проверками, но без http и без сессии. Это и есть
МСП.

Побочная выгода — агенту не надо объяснять правила словами. Инструмент, которого
нет, вызвать нельзя, а описание каждого инструмента едет вместе с ним.

## Что он умеет

- читать статьи: по id, по имени, поиском по телу и контроллеру;
- ходить по дереву: ветка, дети, предки, соседи;
- создавать статью, сохранять её, переносить по дереву;
- читать ленты: список, схему, записи страницами;
- заводить, править и удалять записи лент;
- читать и писать файлы через файловый менеджер.

Всё это — поверх тех же контроллеров админки, что обслуживают браузер.

## Чего он не умеет

Удаления статей нет, и это осознанно: агент удаляет молча, а восстановления нет.

У лент нельзя менять схему и заводить сами ленты — это структура, её делает
человек. Картинки в ленту тоже не попадают: файл идёт через загрузку и кроппер
админки. Что ещё не входит и почему — `docs/toDo/TZ_Lenta_mcp_write.md`.
