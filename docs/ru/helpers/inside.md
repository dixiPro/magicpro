# Хелперы: как устроено

Один файл — `src/Helpers/MproHelper.php`. Список методов и примеры в `use.md`,
здесь только то, что по вызову не видно.

## Подключение

```php
require_once __DIR__ . '/Helpers/MproHelper.php';   // MagicServiceProvider
```

Класс объявлен **без namespace** и подключается через `require_once` в
`MagicServiceProvider`. Ни фасада, ни алиаса в `config/app.php` для него нет.
Отсюда и короткий вызов в блейдах: `MproHelper::` работает где угодно и в любом
пространстве имён.

Плата за это — класс нельзя автозагрузить по PSR-4 и нельзя завести второй такой
же. Имя занято глобально.

## Тонкие входы

Половина методов не содержит логики и существует ради короткого вызова из блейда:

| Метод | Куда уходит |
| --- | --- |
| `imageReduceX`, `imageReduceY` | `MagicProSrc\Image\ImageJob::make()` |
| `imageCacheClear` | `ImageJob::clear()` |
| `sendMail` | `API_Mail::run('sendNow')` |
| `verifyRecapture` | `API_Auth::run('checkGoogleCapture')` |

Логику правят там, а не здесь. Здесь меняют только подпись вызова.

`sendMail` вдобавок глотает исключения: `API_Mail` бросает, а страницы ждут
массива `status / errorMsg / data`. Обе ветки, удачная и нет, пишутся в лог
`mail` — иначе о неудачной отправке никто не узнает, раз исключение не вышло
наружу.

## Логи

`addLog` каждый раз создаёт свой `Monolog\Logger` с `RotatingFileHandler` на
14 дней и уровнем `Info`. Имя лога — оно же имя файла в `storage/logs/`.
Собственной конфигурации в `config/logging.php` не заводится: лог нужен рядом с
местом вызова, а не в общем канале.

Массив раскладывается в строки `ключ: значение`. Вложенные массивы и объекты
уезжают в JSON с `JSON_UNESCAPED_UNICODE`, `bool` печатается словом, `null` —
словом `null`. Сделано ради читаемости глазами: лог чаще открывают, чем парсят.

## getDoc

Страница документации пакета, отрендеренная в html.

Файл ищется как `docs/{$lang}/{$name}.md` от корня пакета. Оба куска пути
приходят параметрами маршрута, поэтому оба проверяются: в имени допустимы только
латинские буквы, цифры, дефис и подчёркивание, в языке — латинские буквы и дефис.
Не подошло — в лог `doc` и пустая строка, без исключения.

**Следствие: слеша в имени быть не может.** `getDoc` видит только плоские файлы в
`docs/{язык}/`, до вложенных папок вроде `docs/ru/main/use.md` он не дотянется.
Это надо учитывать при перекладывании документации.

Перевода нет — подставляется `DOC_SOURCE_LANG`, то есть русский оригинал: лучше
исходный язык, чем пустая страница.

Результат кешируется `Cache::rememberForever`, но в ключ входит `filemtime`
файла. Поправили markdown — ключ другой, страница пересоберётся сама, чистить
кеш не надо.

С `$renderHtml = false` возвращается сырой markdown. Это для выгрузки и для
задания на перевод.

## mdToHtml и доверие к источнику

Два метода рендерят markdown, и они разные не случайно:

- `getDoc` читает файлы пакета — источник свой, html внутри проходит как есть;
- `mdToHtml` рендерит текст, который оператор написал в записи ленты — источник
  чужой, поэтому `html_input => strip` и `allow_unsafe_links => false`.

Один и тот же метод зовут админка через API и сайт напрямую, чтобы предпросмотр
и страница показывали одно и то же.

## Шифрование

`crypt` кладёт случайный IV в первые 16 байт результата, поэтому строка
самодостаточна: `decrypt` берёт IV оттуда же. Алгоритм `AES-256-CBC`, ключ
передаётся вызывающим, в хелпере не хранится.

`decrypt` при неверном ключе или битых данных возвращает пустой массив. Токен из
ссылки — данные извне, и падать на них страница не должна.

## Дерево статей

Запросы прямые, без кеша и без моделей-обёрток. `getChildren*` отбирают
`menuOn = true` и сортируют по `npp` — они писались под меню, а не под обход
дерева целиком.

Мелкое расхождение, о котором стоит знать: `getChildrenById` возвращает ещё и
`npp`, а `getChildrenByName` — нет. Если сортируете руками, берите первый.

`getPathToRootById` идёт вверх циклом с потолком в 100 шагов и ловит `Throwable`,
отдавая то, что успел собрать. Битая ссылка на родителя не должна вешать страницу.

## Как добавлять метод

1. Только если это нужно на страницах. Внутреннее место — модуль, а не хелпер.
2. Логику — в модуль, сюда вход в одну строку.
3. Исключения наружу не выпускать: вызывающий — блейд, ему нечем их ловить.
4. Дописать строку в `use.md`.
