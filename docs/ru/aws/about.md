# AWS: назначение

Настройка почты Amazon — SES и SNS — консольными командами, без хождения по
консоли AWS.

## Что они делают

Две команды над одним ini-файлом:

| Команда | Что делает |
| --- | --- |
| `magicpro:aws-setup` | настраивает сайт целиком: IAM-пользователь, права, ключ, SMTP-пароль — и топик, подписку, набор конфигурации с событиями |
| `magicpro:aws-status` | показывает, как всё настроено сейчас; ничего не меняет |

Настройка одна, потому что файл настроек один и ключ настройки вводится один
раз. Делить её на «отправку» и «события» значило помнить про вторую команду
через полгода — а не помнит никто.

Первая нужна раз на сайт и при каждом переезде, вторая — когда непонятно, что
происходит.

## Из чего состоит

| Что | Где |
| --- | --- |
| общее: чтение ini, ввод ключа, клиенты AWS, метки, `.gitignore` | `src/Console/Aws/AwsCommand.php` |
| пользователь, ключи, топик, подписка, события | `src/Console/Aws/SetupCommand.php` |
| состояние | `src/Console/Aws/StatusCommand.php` |
| подписки топика: чтение, ожидание, отписка | `src/Console/Aws/Subscriptions.php` |
| приём событий от SNS | `src/Mail/AwsHookHandler.php` |

## Чего они не делают

Не подтверждают домен и адрес: это записи в DNS, их публикует человек. Команда
только проверяет, что подтверждение уже есть.

Не выводят аккаунт из песочницы — это заявка в поддержку AWS.

Не правят `.env_mpro`: боевой `.env` правит человек, команда лишь готовит блок
для копирования.

Не шлют тестовое письмо. Отправка — отдельная задача, ей нужны ключи, а хранить
их негде.
