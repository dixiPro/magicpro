# Картинки: как пользоваться

## Вызов

```php
$img = MproHelper::imageReduceX($file, 800);   // по ширине
$img = MproHelper::imageReduceY($file, 400);   // по высоте

MproHelper::imageCacheClear($file);            // снести производные исходника
```

`$file` — абсолютный путь к существующему файлу. Вторая сторона считается по
пропорциям, картинка не обрезается. Исходник меньше запрошенного — увеличивается.

Третий и четвёртый аргументы необязательны: формат и качество. Без них берутся из
настроек.

```blade
<img src="{{ $img['path'] }}"
     width="{{ $img['width'] }}"
     height="{{ $img['height'] }}">
```

Размеры стоит проставлять в атрибуты: без них страница прыгает при загрузке.

## Что возвращается

| Ключ | Что в нём |
| --- | --- |
| `path` | путь от `public`, со слэшем: `/storage/magic/images/…`. Годится и в `src`, и обратно в хелперы через `public_path()`. При ошибке — пусто |
| `width`, `height` | фактические размеры результата, прочитанные из файла |
| `size` | вес файла в байтах |
| `ms` | сколько занял вызов; из кеша это доли миллисекунды |
| `rotated`, `rotateMs` | разворачивали ли снимок по exif и сколько это стоило |
| `cmd` | команда, которой кодировали; пусто — ответ пришёл из кеша |
| `errorMsg` | пусто, если всё вышло |

Исключений не бросается никогда: битый файл не должен ронять страницу. Не вышло —
`path` пустой, причина в `errorMsg`, а что показывать вместо картинки, решает
блейд.

Ошибка `busy: имя_файла` означает, что этот же файл прямо сейчас делает соседний
запрос и мы не дождались очереди. На следующей загрузке страницы всё будет.

## Форматы

| Формат | Чем кодируется |
| --- | --- |
| `webp` | `cwebp` |
| `iwebp` | тот же webp, но кодирует `vipsthumbnail` — для сравнения |
| `avif`, `jpg`, `png` | `vipsthumbnail` |

`cwebp` читает только png, jpeg, tiff и webp. Исходник другого формата — а это
обычный случай, `RESIZE_FORMAT` по умолчанию avif, и в лентах лежат avif, — webp
делает `vipsthumbnail`, тот же путь, что у `iwebp`. Снаружи ничего не меняется:
формат `webp`, расширение `.webp`.

Разворот по exif: `vipsthumbnail` делает его сам, `cwebp` не умеет — там снимок
разворачивается заранее через gd. На трёхтысячном снимке это порядка полусекунды,
и видно её отдельно, в `rotateMs`.

## Настройки

Группа `RESIZE`, экран `/a_dmin/setup`.

| Поле | Что задаёт |
| --- | --- |
| `MAX_RESIZE` | потолок размера, 10–10000; больший запрос режется до него молча |
| `RESIZE_FORMAT` | формат производных |
| `UPLOAD_FORMAT` | чем кроппер ленты шлёт обрезанный кусок на сервер: png или jpeg |
| `WEBP_DEF_QUALITY`, `AVIF_DEF_QUALITY`, `JPG_DEF_QUALITY` | качество, 10–100 |
| `PNG_COMPRESSION` | у png не качество, а уровень сжатия, 0–9 |
| `IMAGE_ERROR` | svg-заглушка. Ресайзер её больше не подставляет: при ошибке `path` пустой, а что показывать — решает блейд |

Читается как `MagicGlobals::$INI['RESIZE']['MAX_RESIZE']`.

`MAX_RESIZE` действует только на путь хелпера. Кроппер ленты им не ограничен: там
кадрирует браузер, сервер только перекодирует, и размер остаётся тот, что прислали.

## Кеш

Производные лежат в `storage/app/public/magic/images/`, наружу отдаются как
`/storage/magic/images/…`. Symlink `public/storage` — условие установки, его
создаёт заход на `/a_dmin`.

Имя файла — то, что просили: `photo_x800.webp` для `imageReduceX($file, 800)`,
`photo_y400.webp` для `imageReduceY($file, 400)`.

Кеш годен, пока он новее исходника. Заменили картинку под тем же именем — все её
производные пересоздадутся сами. А вот поменяли настройки качества — не
пересоздадутся, файл-то новее исходника; тут нужен `imageCacheClear()`.

Снести кеш целиком можно из админки: `/a_dmin/setup`, внизу страницы кнопка
«Очистить кеш картинок». Она убирает все производные всех исходников и говорит,
сколько файлов ушло. Терять там нечего: каждая копия делается заново при первом
же обращении, первая страница после чистки просто соберётся медленнее.

## Чистка сирот

Годность производной считается сравнением со временем исходника. Удалили
исходник — сравнивать стало не с чем, и производные остаются в кеше навсегда.
Собирает их `imageCacheCleanup()`:

```php
$res = MproHelper::imageCacheCleanup();
```

| Ключ | Что в нём |
| --- | --- |
| `files` | сколько производных удалено |
| `bytes` | сколько байт освободилось |
| `kept` | у скольких исходник на месте |
| `skipped` | сколько не проверялось |

Никакой таблицы соответствий нет и не нужно: путь производной сам называет
исходник. `magic/images/p/storage/magicFeed/11/photo_x800.avif` — это `p`, то
есть `public`, каталог `storage/magicFeed/11` под ним и файл с именем `photo`.
Есть в этом каталоге хоть один `photo.*` — производная нужна.

`skipped` — файлы из папки `x/`: исходник лежал вне проекта, каталог назван
хешем, обратно путь не разворачивается. Они не удаляются никогда. Туда же
попадает всё, что положил в кеш не ресайзер, — имя без суффикса размера.

Сравниваются имена **без расширения**: заменили `photo.jpg` на `photo.png` — все
`photo_x*` считаются живыми. Перебор намеренный, лишний файл в кеше дешевле
удалённого нужного.

Опустевшие подпапки убираются тем же проходом.

Проверка идёт по диску и о причинах ничего не знает: дерево исходников переехало
или диск не примонтирован — сиротами окажутся все файлы разом. Потерять при этом
нечего, кеш пересоздаётся, но час-другой сайт будет собирать картинки заново.

### Из админки

`/a_dmin/setup`, внизу страницы, раздел «Кеш картинок»:

| Строка | Кнопка | Что делает |
| --- | --- | --- |
| Удалить из кеша неиспользованные файлы | «Удалить» | `cleanup()`, сироты |
| Полностью очистить кеш картинок | «Очистить» | `clearAll()`, весь кеш |

Обе спрашивают подтверждение и говорят, сколько файлов ушло и сколько это в
килобайтах.

### Из крона

Ради этого метод и живёт в хелпере: задача крона зовёт публичный метод
контроллера статьи, а в контроллере он пишется без `use`, одной строкой.

```php
public function task(array $params): array
{
    return MproHelper::imageCacheCleanup();
}
```

Расписание — раз в сутки ночью: обход читает каждый каталог исходников, и делать
это ежеминутно незачем. Подробности про задачи — `docs/ru/cron/use.md`.

## Готовый компонент

Руками собирать `<picture>` каждый раз незачем — есть компонент `x-magic::img`:

```blade
<x-magic::img :img="#img1#" width="700" />
<x-magic::img :img="#img1#" width="340" mobile="2" />
```

Он берёт место на странице, а файлы считает сам: avif, webp и jpg в обычном и
двойном размере, `sizes`, честные ширины в `srcset` и крупная копия в `src` для
поиска. Параметры и подробности — `docs/ru/components/use.md`.

## Кроппер ленты

В поле-картинке ленты обрезка делается в браузере. Обрезанный кусок уходит на
сервер в формате `UPLOAD_FORMAT` (png или jpeg 0.95), и уже сервер кодирует его в
`RESIZE_FORMAT`. Загрузка без обрезки сохраняет файл как есть, со своим форматом.

Со стороны страницы это обычное поле картинки, с готовыми размерами в ответе, —
`docs/ru/feed/use.md`.
