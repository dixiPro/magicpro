# Картинки: как пользоваться

Этот документ описывает методы, которые нужны при выводе изображений:

- `MproHelper::imageReduceX()` — получить производную заданной ширины;
- `MproHelper::imageReduceY()` — получить производную заданной высоты;
- `MproHelper::imageCacheClear()` — удалить все производные одного исходника;
- `MproHelper::imageCacheCleanup()` — убрать производные, у которых исходник
  пропал.

Оригинал ни один из этих методов не изменяет. Производные создаются по первому
обращению и хранятся отдельно в кеше.

**Базы у модуля нет.** Ни таблиц, ни записей, ни таблицы соответствий: всё, что
он знает, лежит на диске именами файлов. Поэтому кеш можно снести в любой
момент, рассинхронизировать нечего.

Настройки — группа `RESIZE` на `/a_dmin/setup`.

## Подготовка пути

Ресайзеру нужен **абсолютный путь в файловой системе**. URL вида
`/storage/magicFeed/11/photo.jpg` напрямую передавать нельзя.

Если путь пришёл из поля картинки ленты, преобразуйте его через `public_path()`:

```php
$source = public_path($item->img1['path'] ?? '');
```

Если абсолютный путь уже известен, передавайте его без преобразования:

```php
$source = storage_path('app/public/photos/photo.jpg');
```

Для одного исходника используйте один и тот же вид абсолютного пути. Один и тот
же файл, переданный как путь внутри `public` и как его реальный путь внутри
`storage`, попадёт в разные ветки кеша.

| Откуда картинка                         | Что у тебя в руках        | Путь для хелпера                                              |
| --------------------------------------- | ------------------------- | ------------------------------------------------------------- |
| Файловый менеджер админки               | url `/design/…`           | `public_path($url)`                                           |
| Поле-картинка записи ленты              | массив, url в `['path']`  | `public_path($item->photo['path'])`                           |
| Путь написан в блейде руками            | `/design/images/logo.png` | `public_path('design/images/logo.png')`                       |
| Файл, который положил свой код          | путь от `storage`         | `storage_path('app/…')`                                       |
| Любой файл на сервере, даже вне проекта | абсолютный путь           | как есть                                                      |
| Данные другого пакета                   | что угодно                | найти в данных url или путь и привести к одному из видов выше |
| Внешний адрес `https://…`               | url чужого сайта          | не передавать ресайзеру                                           |

Файловый менеджер кладёт загрузки в `public/` плюс `PUBLIC_UPLOAD_DIR` из
настроек — по умолчанию это `/design`, поэтому url загруженного файла
начинается с `/design/`. Если на сайте настройка другая, начало будет другим, а
правило то же: url от корня сайта → `public_path()`.

Определяйте вид пути по источнику данных, а не по одному начальному `/`:
и URL от корня сайта, и абсолютный путь Linux начинаются с косой черты.
Ресайзер не скачивает внешние `https://…` изображения. Для ресайза сначала нужен
локальный файл; прямой вывод внешнего URL через `<img>` обходится без ресайзера.

## Ресайз по ширине

```php
MproHelper::imageReduceX(
    string $file,
    int $width,
    ?string $format = null,
    ?int $quality = null,
): array
```

Пример:

```php
$img = MproHelper::imageReduceX(
    public_path($item->img1['path'] ?? ''),
    800,
);
```

Ширина результата будет равна запрошенной ширине с учётом `MAX_RESIZE`. Высоту
кодировщик рассчитает по пропорциям исходника. Обрезки и изменения соотношения
сторон нет. Если исходник меньше, он увеличивается.

Масштаб по ширине удобен для колонок, карточек, слайдов и текста статьи.
Если исходник меньше запрошенного, не увеличивайте его без необходимости:
размеры исходного изображения в поле ленты — `x` и `y`.

## Ресайз по высоте

```php
MproHelper::imageReduceY(
    string $file,
    int $height,
    ?string $format = null,
    ?int $quality = null,
): array
```

Пример:

```php
$img = MproHelper::imageReduceY(
    public_path($item->img1['path'] ?? ''),
    400,
);
```

Высота результата будет равна запрошенной высоте с учётом `MAX_RESIZE`. Ширина
будет рассчитана по пропорциям.

Масштаб по высоте удобен для ряда логотипов, превью одной высоты и баннера
в фиксированной полосе.

## Формат и качество

Третий и четвёртый аргументы необязательны:

```php
$img = MproHelper::imageReduceX($source, 800, 'avif', 50);
$img = MproHelper::imageReduceX($source, 800, 'webp', 82);
$img = MproHelper::imageReduceX($source, 800, 'jpg', 70);
$img = MproHelper::imageReduceX($source, 800, 'png', 6);
```

Поддерживаются точные имена форматов в нижнем регистре:

| Формат  | Кодировщик                                                 | Четвёртый аргумент   |
| ------- | ---------------------------------------------------------- | -------------------- |
| `webp`  | `cwebp`; для неподдерживаемого исходника — `vipsthumbnail` | качество `10–100`    |
| `iwebp` | `vipsthumbnail`, экспериментальный вариант WebP            | качество `10–100`    |
| `avif`  | `vipsthumbnail`                                            | качество `10–100`    |
| `jpg`   | `vipsthumbnail`                                            | качество `10–100`    |
| `png`   | `vipsthumbnail`                                            | уровень сжатия `0–9` |

Если формат не передан, используется `RESIZE_FORMAT`. Если не передан четвёртый
аргумент, берётся настройка выбранного формата:

- `WEBP_DEF_QUALITY` для `webp` и `iwebp`;
- `AVIF_DEF_QUALITY` для `avif`;
- `JPG_DEF_QUALITY` для `jpg`;
- `PNG_COMPRESSION` для `png`.

Аргументы публичного хелпера не нормализуются. Передавайте формат в нижнем
регистре и значение из шкалы выбранного кодировщика. Для PNG число вроде `82`
не означает качество и является неверным уровнем сжатия.

## Ответ

Оба метода ресайза возвращают один и тот же массив:

| Ключ       | Тип      | Значение                                                                      |
| ---------- | -------- | ----------------------------------------------------------------------------- |
| `path`     | `string` | URL от `public`, например `/storage/magic/images/…`; при ошибке пустая строка |
| `width`    | `int`    | фактическая ширина результата                                                 |
| `height`   | `int`    | фактическая высота результата                                                 |
| `size`     | `int`    | размер результата в байтах                                                    |
| `ms`       | `float`  | длительность вызова в миллисекундах                                           |
| `rotated`  | `bool`   | разворачивался ли JPEG по EXIF перед `cwebp`                                  |
| `rotateMs` | `float`  | время предварительного разворота в миллисекундах                              |
| `cmd`      | `string` | команда кодировщика; пустая строка при ответе из кеша                         |
| `errorMsg` | `string` | пустая строка при успехе, иначе причина ошибки                                |

В ответе нет ключей `x`, `y` и `mime`.

## Вывод в Blade

Проверяйте `path`: заглушку ресайзер не подставляет.

```blade
@php
    $img = MproHelper::imageReduceX(
        public_path($item->img1['path'] ?? ''),
        800,
    );
@endphp

@if ($img['path'] !== '')
    <img
        src="{{ $img['path'] }}"
        width="{{ $img['width'] }}"
        height="{{ $img['height'] }}"
        alt="{{ $item->img1['alt'] ?? '' }}"
    >
@else
    <span class="image-unavailable" aria-hidden="true"></span>
@endif
```

`width` и `height` берите из ответа, а не из запроса: размер мог быть ограничен
настройкой `MAX_RESIZE`, а вторую сторону округляет внешний кодировщик.

Отсутствующее поле превращается в пустой путь через `?? ''`: ресайзер
вернёт ошибку, а шаблон покажет выбранную заглушку. Для квадратной заглушки
в сайте с Bootstrap можно использовать `<div class="ratio ratio-1x1 bg-light rounded"></div>`.

## Ошибки

Обычные ошибки исходника и кодировщика возвращаются в массиве:

```php
if ($img['errorMsg'] !== '') {
    // Choose the fallback in the calling view.
}
```

Частые значения:

- `not an image: …` — файла нет или `getimagesize()` не распознал изображение;
- `unknown format: …` — передан неподдерживаемый формат;
- `busy: …` — другой запрос кодирует ту же производную, а ожидание превысило
  пять секунд;
- текст внешней утилиты — кодировщик завершился с ошибкой.

При ошибке `path` пустой, а `width`, `height` и `size` равны нулю. Решение о
заглушке принимает вызывающий Blade-шаблон.

## Как работает кеш

Производные лежат в `storage/app/public/magic/images/` и доступны снаружи через
`/storage/magic/images/…`.

Имя отражает ось, запрошенный размер и формат:

```text
photo_x800.webp
photo_y400.avif
photo_x800.iwebp.webp
```

Готовая производная используется, пока время её изменения не меньше времени
изменения исходника. Замена исходника под тем же именем автоматически делает
старую производную негодной.

Качество в имени кеша не записывается. После изменения качества или параметров
кодировщика удалите производные исходника вручную.

## Очистка производных исходника

```php
$removed = MproHelper::imageCacheClear($source);
```

Метод удаляет производные всех размеров и форматов для указанного исходника и
возвращает число успешно удалённых файлов. Сам исходник остаётся на месте.

Передавайте тот же абсолютный путь, который использовался для ресайза. Файл уже
может быть удалён: для поиска производных достаточно его прежнего полного пути.

Очистка не ждёт выполняющийся кодировщик. Если она совпала с генерацией,
следующий запрос при необходимости создаст производную заново.

## Чистка сирот

`imageCacheClear()` убирает производные конкретного исходника. Но бывает
обратное: исходник **удалили**, и его производные остались в кеше навсегда —
годность считается сравнением со временем исходника, а сравнивать больше не с
чем.

Их собирает другой метод:

```php
$res = MproHelper::imageCacheCleanup();
```

Аргументов у него нет: он не чистит «производные такого-то файла», а обходит
весь кеш и у каждой производной проверяет, жив ли исходник.

| Ключ | Что в нём |
| --- | --- |
| `files` | сколько производных удалено |
| `bytes` | сколько байт освободилось |
| `kept` | у скольких исходник на месте |
| `skipped` | сколько не проверялось |

В `skipped` попадает то, что не удалось разобрать: ветка `x` — исходник лежал
вне проекта и каталог назван хешем, — неизвестная буква корня и имена не по
шаблону производной. Такие файлы не удаляются никогда.

### Чем запускать

**Кнопкой в админке.** `/a_dmin/setup`, раздел «Кеш картинок»: одна кнопка
убирает сирот, вторая сносит кеш целиком. Обе спрашивают подтверждение и
говорят, сколько файлов ушло.

**Кроном, если сироты копятся сами** — так бывает там, где регулярно удаляют
записи лент с картинками. Задача крона зовёт публичный метод контроллера статьи,
раз в сутки ночью достаточно; как заводить задачу — `docs/ru/cron/use.md`.

**Руками, из любого своего кода** — тем же вызовом.

Ни один из способов не обязателен. Сироты работе сайта не мешают, они занимают
место: это гигиена, а не жизнеспособность.

Считать сироты по диску безопасно, но грубо: переехало дерево исходников или не
примонтирован диск — сиротами окажутся все файлы разом. Терять нечего, кеш
пересоздастся, но час-другой сайт будет собирать картинки заново. Поэтому чистка
живёт под кнопкой и в кроне, а не в отдаче страницы.

## Ограничение имён исходников

В одном каталоге не должно быть двух исходников с одинаковым именем и разными
расширениями:

```text
photo.jpg
photo.png
```

Расширение исходника не входит в имя производной, поэтому оба файла использовали
бы один и тот же кеш.

## Примеры разметки

### Баннер из файлового менеджера

Оператор загрузил баннер в `/design/banners/` и дал ссылку:

```blade
@php
    $banner = MproHelper::imageReduceX(public_path('design/banners/spring.jpg'), 1200);
@endphp

@if ($banner['path'] !== '')
    <img src="{{ $banner['path'] }}" width="{{ $banner['width'] }}"
         height="{{ $banner['height'] }}" alt="Spring banner" class="img-fluid">
@endif
```

### Логотипы одной высоты

```blade
<div class="d-flex flex-wrap align-items-center gap-4">
    @foreach ($partners as $partner)
        @php
            $logo = MproHelper::imageReduceY(public_path($partner->logo['path'] ?? ''), 60);
        @endphp
        @if ($logo['path'] !== '')
            <img src="{{ $logo['path'] }}" width="{{ $logo['width'] }}"
                 height="{{ $logo['height'] }}" alt="{{ $partner->title }}">
        @endif
    @endforeach
</div>
```

Ширины у логотипов разные, высота одна — ровно то, что делает `imageReduceY`.

### Чёткость на телефоне: srcset

На экране с плотностью 2x картинка шириной 400 css-пикселей просит 800
настоящих. Делаем две производные и отдаём браузеру выбор:

```blade
@php
    $src = public_path($item->photo['path'] ?? '');
    $one = MproHelper::imageReduceX($src, 400);
    $two = MproHelper::imageReduceX($src, 800);
@endphp

@if ($one['path'] !== '')
    <img
        src="{{ $one['path'] }}"
        @if ($two['path'] !== '')
            srcset="{{ $one['path'] }} {{ $one['width'] }}w, {{ $two['path'] }} {{ $two['width'] }}w"
            sizes="(max-width: 576px) 100vw, 400px"
        @endif
        width="{{ $one['width'] }}"
        height="{{ $one['height'] }}"
        alt="{{ $item->photo['alt'] ?? '' }}"
        loading="lazy"
    >
@endif
```

`sizes` — обещание браузеру, **какой ширины будет место** на странице. Браузер
выбирает файл до вёрстки и проверить обещание не может: если в `sizes` написано
400px, а картинка на самом деле во весь экран, приедет мелкий файл и будет
мылить.

В `srcset` — ширины **из ответа**, не запрошенные: `MAX_RESIZE` мог срезать.

### Форматы: avif, webp и jpg для старых браузеров

```blade
@php
    $src  = public_path($item->photo['path'] ?? '');
    $avif = MproHelper::imageReduceX($src, 800, 'avif');
    $webp = MproHelper::imageReduceX($src, 800, 'webp');
    $jpg  = MproHelper::imageReduceX($src, 800, 'jpg');
@endphp

@if ($jpg['path'] !== '')
    <picture>
        @if ($avif['path'] !== '')
            <source srcset="{{ $avif['path'] }}" type="image/avif">
        @endif
        @if ($webp['path'] !== '')
            <source srcset="{{ $webp['path'] }}" type="image/webp">
        @endif
        <img src="{{ $jpg['path'] }}" width="{{ $jpg['width'] }}"
             height="{{ $jpg['height'] }}" alt="{{ $item->photo['alt'] ?? '' }}" loading="lazy">
    </picture>
@endif
```

Каждый `<source>` — под своим `@if`, чтобы не выводить пустой адрес
неудавшейся производной.

Такая разметка повторяется на многих страницах — это повод завести на сайте
свой компонент и держать её в одном месте.

### Фон блока

```blade
@php
    $bg = MproHelper::imageReduceX(public_path('design/hero/main.jpg'), 1920);
@endphp

<section class="py-5 text-white"
    @if ($bg['path'] !== '') style="background: url('{{ $bg['path'] }}') center / cover" @endif>
    …
</section>
```

### Письмо и превью ссылки: явный формат

Для письма или превью ссылки задавайте формат явно; пример использует `jpg`.
Для адреса изображения вне сайта нужен полный URL с доменом:

```php
// Link preview image.
$og = MproHelper::imageReduceX(public_path($item->photo['path'] ?? ''), 1200, 'jpg');

// Email image: use an absolute URL.
$mail = MproHelper::imageReduceX(public_path($item->photo['path'] ?? ''), 600, 'jpg', 80);
$src  = $mail['path'] !== '' ? url($mail['path']) : '';
```

## Стоимость первого запроса

Новая производная кодируется при первом обращении. Страница со множеством
новых изображений может открыться медленнее; следующие запросы используют кеш.
Если нужен прогрев большой галереи, её можно предварительно открыть обычным
запросом. Это запускает обработку файлов, а не проверку только чтением.
