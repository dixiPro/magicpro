# Как собирать сайт в MagicPro

Этот документ — практическое руководство для того, кто собирает сайт в
MagicPro: создаёт статьи, настраивает адреса, пишет Blade, добавляет PHP-логику,
собирает меню и переиспользуемые компоненты. Руководство общее для админа и
МСП-агента: интерфейсы работы различаются, устройство статьи одинаково.
Работа через инструменты описана в [МСП: работа со статьями](mcp.md).

## Основная идея

MagicPro не заменяет Laravel. Он хранит обычный Blade и обычный PHP-контроллер
рядом в одной записи — **статье** — и сам создаёт из неё рабочие файлы Laravel.

```text
статья в админке
├── name + isRoute + routeParams  → публичный адрес
├── body                          → Blade magic::name
├── controller                    → PHP-класс MagicProControllers\name
└── parentId + npp + menuOn       → дерево и меню
```

После сохранения статьи и успешной публикации рабочих файлов:

- `body` записывается в
  `storage/dataMagicPro/view/{name}.blade.php`;
- при включённом контроллере создаётся
  `storage/dataMagicPro/controller/{name}.php`;
- Blade доступен как `magic::{name}`;
- если включён `isRoute`, статья открывается по своему адресу.

База — источник истины. Файлы в `storage/dataMagicPro/` являются рабочими
копиями и при следующем сохранении или перегенерации будут заменены. Их нельзя
править вручную.

Статья может выполнять несколько независимых ролей:

- страница с публичным адресом;
- пункт меню;
- шаблон или фрагмент без собственного адреса;
- Blade-компонент;
- контейнер в дереве;
- контроллер с публичными служебными методами, например для cron;

Дерево статей и структура URL — не одно и то же. Родитель нужен для порядка,
меню и хлебных крошек, но не добавляется к адресу. Дочерняя статья `contacts`
внутри `company` всё равно открывается как `/contacts`, а не
`/company/contacts`.

## Первая страница

1. В дереве редактора выберите родителя и создайте дочернюю статью.
2. Задайте свободное имя, например `about`, и заголовок «О компании».
3. Включите `isRoute`, оставьте `useController` выключенным.
4. Запишите Blade и сохраните статью:

```blade
<h1>{{ $Env['title'] }}</h1>
<p>About our company.</p>
```

5. Откройте `/about` и проверьте результат.

Это самостоятельная страница без зависимости от шаблона. Для общего каркаса
сайта подключите статью-шаблон, как показано в разделе «Layout».

Создание записи ещё не создаёт рабочий Blade. Он появляется после сохранения.
Если сохранение вернуло `warning`, прочитайте его: новый текст мог сохраниться
в базе без публикации файлов. Подробности — [сохранение и публикация](#сохранение-и-публикация-статьи).

## Из чего состоит статья

Статьи хранятся в таблице `articles`.

| Поле                       | Кто управляет     | Что означает                                   |
| -------------------------- | ----------------- | ---------------------------------------------- |
| `id`                       | система           | Числовой идентификатор. У корня всегда `1`     |
| `parentId`                 | дерево редактора  | Идентификатор родителя; у корня `0`            |
| `npp`                      | дерево редактора  | Позиция среди детей одного родителя            |
| `name`                     | пользователь      | Уникальное имя статьи, Blade, класса и адреса  |
| `title`                    | пользователь      | Заголовок; автоматически в HTML не выводится   |
| `body`                     | пользователь      | Полный исходник Blade статьи                   |
| `controller`               | пользователь      | Полный исходник PHP-контроллера                |
| `templateName`             | не используется   | Старое поле совместимости                      |
| `directory`                | система           | Есть ли у статьи дети                          |
| `menuOn`                   | пользователь      | Включать ли статью в меню-хелперы              |
| `isRoute`                  | пользователь      | Доступна ли статья как публичный адрес         |
| `routeParams`              | редактор маршрута | Режим контроллера и правила входных параметров |
| `created_at`, `updated_at` | система           | Время создания и последнего изменения          |

### Три системные статьи:

- `root`, `id = 1` — корень дерева, не является главной страницей;
- `index` — главная страница `/`;
- `error404` — Blade ответа на неизвестный или недопустимый адрес.

`root` нельзя удалить или переименовать. Удаление другой статьи удаляет также
всё её поддерево и сгенерированные файлы.

## Сохранение и публикация статьи

Админ и МСП изменяют одну и ту же статью. Админ сохраняет её в редакторе,
МСП вызывает `save-article`; оба пути используют `saveById` API статей.
Прямой SQL не запускает публикацию файлов и архив. Положение в дереве
пересчитывает отдельная команда перемещения, а не сохранение текста.

Архив хранит JSON сохранённого состояния статьи в
`magicPro_article_versions.data`. Отдельных таблиц для шаблонов, include
и компонентов нет: это статьи. Типы колонок, умолчания и связи описаны
в [структуре ядра](../mainDev/use.md#структура-данных-статьи).

### Что означает результат сохранения

1. API проверяет и сохраняет переданные поля статьи в базе.
2. При включённом контроллере проверяет имя класса и синтаксис PHP.
3. Если проверка прошла, создаёт рабочие файлы.
4. Передаёт сохранённое состояние в архив версий.

| Результат           | Что произошло                                                      | Что делать                                                                  |
| ------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Успех без `warning` | API выполнил публикацию файлов                                     | Проверить страницу: синтаксическая проверка не проверяет работу PHP и Blade |
| Успех с `warning`   | Текст сохранён, проверка контроллера не прошла, файлы не обновлены | Исправить указанную ошибку и сохранить снова                                |
| Ошибка              | Операция не завершилась штатно; момент отказа имеет значение       | Перечитать статью и проверить фактическое состояние                         |

При `warning` ранее опубликованные файлы остаются на диске. Это не гарантирует
работу нового адреса после переименования или статьи, у которой раньше файлов
не было. База уже содержит новые значения.

Ошибка записи файлов не откатывает уже сохранённую статью. Ошибка записи архива
логируется отдельно и не превращает успешное сохранение в ошибку ответа.
Архив хранит сохранённый исходник, который не обязательно был опубликован.

### Совместная работа

Перед изменением прочитайте актуальную статью. Переданный `body` или
`controller` заменяет поле целиком, а пропущенные поля остаются прежними.
В `routeParams` сохраняются пропущенные ключи; `keysArr` заменяется целиком.

Перечитывание уменьшает риск затереть чужую правку, но не блокирует статью:
`saveById` не сравнивает присланную версию с текущей перед записью.

Положение в дереве меняется отдельной операцией перемещения. Сохранение текста
не принимает `parentId`, `npp` и `directory`.

### Если сайт показывает старую страницу

Сначала проверьте `warning`. Затем учтите статическую публикацию: генератор
снимает HTML-копию самой статьи, но не обновляет все страницы, которые включают
её как шаблон, меню или компонент. Порядок работы с копиями описан в
[статических страницах](static.md).

## Имя статьи и адрес

Обычное имя содержит латинские буквы, цифры, дефис и подчёркивание. Имя должно
быть уникальным. Переименование меняет URL, имя Blade и ссылки на класс: проверьте
обращения из других статей и внешние ссылки, включая поисковую выдачу. Если включён контроллер, допустимы только латинские буквы,
цифры и подчёркивание; первая позиция — буква или подчёркивание.

| Имя          | Адрес         |
| ------------ | ------------- |
| `index`      | `/`           |
| `about`      | `/about`      |
| `price-list` | `/price-list` |

## Маршрут статьи

Статья открывается по адресу `/<имя>`, если включён `isRoute`. Что этот адрес
принимает, решает `routeParams`:

| Параметр          | Что делает                                                           | Умолчание |
| ----------------- | -------------------------------------------------------------------- | --------- |
| `useController`   | `true` — сначала контроллер, потом блейд; `false` — сразу блейд      | `false`   |
| `adminOnly`       | только для вошедшего в админку                                       | `false`   |
| `utmParamsEnable` | пропускать UTM и рекламные метки (список — в Setup)                  | `true`    |
| `getEnable`       | принимать GET: `/page/key/value` или `/page?key=value`, всё в `$Get` | `false`   |
| `keysArr`         | какие ключи GET разрешены; пусто — любые                             | `[]`      |
| `bindKeys`        | ключи из `keysArr` по позиции в адресе                               | `false`   |
| `postEnable`      | принимать POST формы, тело — в `$Post`                               | `false`   |
| `livewire`        | статья — Livewire-компонент, а не страница, см. [Livewire](#livewire-компонент) | `false`   |

Лишний параметр, запрет `adminOnly` или неизвестная статья — страница
`error404` с кодом 404; чужой HTTP-метод — 405.

### Обычная страница

Всё по умолчанию. `/about` открывается, `/about?utm_source=fb` тоже, а
`/about?page=2` и `/about/page/2` — 404.

### Список с фильтрами

`getEnable: true`, `keysArr: ["category", "page"]`. Годятся обе записи:

```text
/catalog/category/books/page/2
/catalog?category=books&page=2
```

```blade
{{ $Get['category'] ?? '' }}  {{ (int) ($Get['page'] ?? 1) }}
```

Сегменты идут парами `ключ/значение`, нечётное число — 404. Ключ не из
`keysArr` — 404. Пустой `keysArr` пускает любые ключи.

### Карточка по адресу

`getEnable: true`, `bindKeys: true`, `keysArr: ["slug"]`:

```text
/product/red-chair   →   $Get['slug'] = 'red-chair'
```

Сегментов должно быть ровно столько, сколько ключей. Значение маршрутизатор не
проверяет: есть ли такая запись — решает контроллер, нет — задайте `$this->status = 404` и верните данные для своего Blade.
`abort(404)` внутри `process()` будет перехвачен базовым контроллером и станет
ответом 500; он не переключает страницу на `error404`.
Query string позиционный ключ не перебивает: `/product/red-chair?slug=x` даст
`red-chair`.

### Несколько позиционных параметров

`getEnable: true`, `bindKeys: true`, `keysArr: ["slug", "variant"]`:

```text
/product/red-chair/oak
```

```php
['slug' => 'red-chair', 'variant' => 'oak']
```

Query string тоже проверяется: допустимы ключи из `keysArr` и разрешённые
рекламные метки. В режиме пар порядок `ключ/значение` не важен; значение пути
имеет приоритет перед одноимённым query-параметром.

### UTM-параметры

Список разрешённых рекламных ключей задаёт `ENABLE_URL_PARAMS` в Setup,
а флаг `utmParamsEnable` действует отдельно на каждую статью. Принятые метки
остаются в `$Get`:

```blade
{{ $Get['utm_source'] ?? '' }}
```

Если выключены и UTM, и обычные GET-параметры, `/about?utm_source=ad` даст 404.
Для страницы вообще без параметров достаточно выключить `utmParamsEnable`
при остальных умолчаниях. При включённом GET метка может быть разрешена
обычными правилами GET.

### Форма

`postEnable: true`. Тело формы — в `$Post` (в контроллере — `$params['postParams']`),
GET-параметры и дополнительные сегменты пути в этом режиме не разбираются.
`GET` и `HEAD` допустимы; `POST` без `postEnable`, а также `PUT`, `PATCH`
и `DELETE` получают 405.

```blade
<form method="post" action="/feedback">
    @csrf
    <input name="email">
    <button>Отправить</button>
</form>
```

`@csrf` добавляет токен формы. Присланный токен проверяется, неверный даёт 419.
Однако текущий обработчик пропускает запрос без токена: обязательной CSRF-проверки
на этом маршруте нет. Для операций, которым она нужна, требуется изменение
серверной обработки разработчиком пакета. GET на тот же адрес открывает страницу с пустым
`$Post` — контроллер различает так:

```php
if (! $request->isMethod('post')) {
    return [];
}
```

### Закрытая страница

`adminOnly: true` — страница видна только тому, кто вошёл в админку MagicPro
(`auth('magic')`), остальным 404. Этот флаг не заменяет проверки прав
на конкретную бизнес-операцию внутри контроллера.

### Файл вроде `/robots.txt`

Назовите статью `robots___txt` — она откроется как `/robots.txt`. Прямой адрес
`/robots___txt` отвергается.

### Страница ошибки маршрута

В `magic::error404` передаются `$message`, `$file` и `$line`. Не выводите
внутренние пути и номера строк посетителю рабочего сайта.

## Blade статьи

Обычный Blade Laravel. Доступны директивы, циклы, секции, сервисы,
Eloquent и всё остальное, что доступно обычной Laravel-вью.

### Переменные страницы

Без контроллера Blade получает:

| Переменная | Содержимое                                                    |
| ---------- | ------------------------------------------------------------- |
| `$Env`     | Описание текущей статьи                                       |
| `$Get`     | Проверенные маршрутизатором параметры URL                     |
| `$Post`    | Тело запроса при включённом `postEnable`, иначе пустой массив |

`$Env` содержит:

```php
[
    'name' => 'catalog',
    'title' => 'Catalog',
    'artId' => 42,
    'parentId' => 1,
    'view' => 'magic::catalog',
]
```

### Шаблоны, include и компоненты

Способы подключения, примеры и правила находятся в [руководстве по вёрстке](layout.md).
Включение шаблона или фрагмента не запускает контроллер его статьи.

## Контроллер статьи

Контроллер готовит данные для Blade: выполняет выборки, проверяет входные
значения и возвращает массив переменных шаблона.

```php
<?php
namespace MagicProControllers;
use MagicProSrc\MagicController;
class Magic_Pro_Name_Controller extends MagicController
{
    protected function process(array $params): array
    {
        $request = $params['request'];
        $getParams = $params['getParams'] ?? [];
        $postParams = $params['postParams'] ?? [];

        // Read article attributes from the request.
        $env   = $request->attributes->all();
        $artId = $request->attributes->get('artId');

        return ['Post' => $postParams, 'a' => 'Result'];
    }
}
```

Для обычной страницы используйте
`class Magic_Pro_Name_Controller extends MagicController`.
Билдер заменяет `Magic_Pro_Name_Controller` именем статьи.

Базовый контроллер передаёт `$Env` и `$Get` в Blade автоматически. `$Post`
нужно вернуть самостоятельно, если шаблон его использует. Остальные ключи
массива из `process()` становятся одноимёнными переменными Blade. В примере
`{{ $a }}` выведет `Result`.

В `$params['request']` лежит настоящий `Illuminate\Http\Request`, поэтому
доступны заголовки, cookies, файлы и стандартная валидация Laravel.

Маршрутизатор создаёт контроллер через `new`, а не через контейнер Laravel.
Поэтому не добавляйте обязательные зависимости в конструктор. Получайте сервисы
внутри `process()`:

```php
$service = app(PriceService::class);
```

### Статус, заголовки и redirect

Контроллер может настроить статус, заголовки и редирект

```php
$this->status = 201;
$this->contentType = 'text/plain; charset=utf-8';
$this->headers['X-Result'] = 'created';
$this->redirect = '/success';
return [];
```

Redirect выполняется до рендера Blade.

Исключение внутри контроллера не попадает в `error404`: базовый контроллер
возвращает отдельный HTML-ответ с кодом 500. При `APP_DEBUG=true` в нём будет
trace.

### Статья-helper: общий метод для сайта

Когда одно и то же вычисление нужно в нескольких статьях — цена со скидкой,
формат телефона, выборка из ленты, — его не копируют в каждый блейд, а кладут
методом в одну статью-helper и зовут оттуда.

Статья: `priceTools`. Имя допустимо для PHP-класса: латинские буквы, цифры
и подчёркивание, не с цифры.
Контроллер включён.
Раут: выключен

```php
<?php

namespace MagicProControllers;
class Magic_Pro_Name_Controller
{
    public function withDiscount(float $price, int $percent): float
    {
        return round($price * (100 - $percent) / 100, 2);
    }
}
```

Из любого блейда или контроллера другой статьи:

```blade
{{ app(\MagicProControllers\priceTools::class)->withDiscount($item->price, 10) }}
```

- Метод должен быть `public`. Можно и `public static` — тогда
  `\MagicProControllers\priceTools::withDiscount(...)`.
- Вызов через `app()` не передаёт в метод запрос и `$Env` автоматически.
  Нужные значения передавайте аргументами; `handle()` и `process()` при таком
  вызове сами не запускаются.
- При переименовании обновите обращения к прежнему классу. `search-articles`
  ищет его имя в `body` и `controller` других статей.

Из другого класса пространства `MagicProControllers` можно использовать
короткое имя:

```php
$result = app(priceTools::class)->withDiscount(1200, 10);
```

## Экспериментальные компоненты

### Классовый компонент

Это опытный режим. Статья должна иметь имя, допустимое для PHP-класса, и
включённый `useController`. Контроллер наследуется от
`Illuminate\View\Component`, а его `render()` возвращает Blade той же статьи.

```php
<?php

namespace MagicProControllers;

use Illuminate\Contracts\View\View;
use Illuminate\View\Component;

class PriceBadge extends Component
{
    public function __construct(public string $label = '')
    {
    }

    public function render(): View
    {
        return view('magic::PriceBadge');
    }
}
```

### Livewire-компонент

Livewire — интерактив без JavaScript: кнопка вызывает метод PHP-класса на
сервере, и кусок страницы перерисовывается без перезагрузки. Документация
библиотеки — <https://livewire.laravel.com/docs>.

**Как сделать.**

1. Создайте статью, например `counter`.
2. В параметрах маршрута поставьте галку «Livewire-компонент». Она сама
   выключает маршрут и включает контроллер, остальные настройки маршрута
   прячутся: компонент — не страница, по адресу он не открывается.
3. В редакторе нажмите «Livewire контроллер». Подставится заготовка
   контроллера, а если Blade статьи пуст — и его разметка. Готовый Blade
   кнопка не трогает.

   ```php
   <?php

   namespace MagicProControllers;

   use MagicProSrc\Livewire\MagicProLivewire;

   // the builder replaces Magic_Pro_Name_Controller with the article name,
   // and MagicProLivewire renders the blade of this same article
   class Magic_Pro_Name_Controller extends MagicProLivewire
   {
       // a public property is the state of the component: it survives every
       // request and is visible in the blade as $count
       public int $count = 0;

       // a public method is called from the blade: wire:click="add"
       public function add(): void
       {
           $this->count++;
       }
   }
   ```

4. Blade статьи — разметка компонента, **ровно один корневой элемент**:

   ```blade
   {{-- exactly one root element: Livewire puts its wire:id on it --}}
   <div>
     {{-- calls the public method add() of the controller on the server --}}
     <button type="button" wire:click="add">+</button>

     {{-- the public property $count of the controller --}}
     {{ $count }}
   </div>
   ```

5. На любой странице:

   ```blade
   <livewire:magic::counter />
   ```

**Как это устроено.** `MagicProLivewire` сам рисует Blade своей статьи:
билдер называет класс именем статьи, а базовый `render()` берёт имя класса.
Поэтому имя блейда нигде не пишется, и переименование статьи ничего не ломает —
меняется только тег на страницах. Свой `render()` нужен, лишь когда в Blade
надо передать вычисленные данные; публичные свойства видны в Blade сами.

**Что важно помнить.**

- Состояние компонента — только его публичные свойства. Не объявил свойство —
  значение не переживёт следующий запрос.
- Каждое действие — запрос на сервер (`/livewire/update`). Для поля поиска
  используйте `wire:model.live.debounce.400ms`, иначе запрос уйдёт на каждую
  букву.
- Свойства видны в браузере: секреты и большие массивы в них не кладут.
- Подключение только тегом `<livewire:magic::имя />`; имя статьи должно
  годиться для PHP-класса — латиница, цифры, подчёркивание.
- Страницу с Livewire не отдают из статических HTML-копий: запечённая копия
  отдаст устаревшее состояние.
