# МСП: работа со статьями

МСП-агент собирает сайт по тем же правилам, что и админ. Его интерфейс —
инструменты MCP-сервера. Подключение не даёт ему доступ к исходникам пакета,
shell или возможность исправлять серверный PHP пакета.

## Начало работы

1. Вызвать `get-project-name` и сверить название проекта с поручением.
2. Вызвать `list-docs` и выбрать документы по полю `about`.
3. Прочитать нужные страницы через `get-doc`, передавая возвращённый `path`.
4. Прочитать статью и все связанные с задачей шаблоны или компоненты.

Формат ответов документации описан в [служебных инструментах](../mcp/use.md#служебные-инструменты-и-документация).
При ошибке отсутствующего индекса проверьте язык `LANGUAGE`: сейчас есть только `ru`.

## Чтение статей

| Инструмент | Аргументы | Что возвращает |
| --- | --- | --- |
| `get-article` | `id` | полную статью |
| `get-article-by-name` | `name` | полную статью по точному имени |
| `search-articles` | `text` | `results` с `id` и `title` |

`search-articles` ищет обычную подстроку только в `body` и `controller`.
Заголовок и имя не участвуют. Регистр зависит от collation базы.

Состав полной статьи — в [руководстве по сайту](use.md#из-чего-состоит-статья).
В старых записях `routeParams` может быть `null`; новые сохраняются с нормализованным
объектом. `templateName` — поле совместимости, через MCP не редактируется.

## Навигация по дереву статей

| Инструмент | Аргументы | Форма ответа |
| --- | --- | --- |
| `get-article-tree` | `id` | `tree`: список с веткой от корня к статье и прямыми детьми каждого уровня |
| `get-article-children` | `id` | `children`: прямые дети по `npp` |
| `get-article-parents` | `id` | `parents`: от прямого родителя вверх к корню |
| `get-article-siblings` | `id` | `siblings`: все дети того же родителя, включая исходную статью |

Корень имеет `id = 1`, `name = root` и `parentId = 0`. Короткая запись ребёнка
содержит `id`, `text` — это заголовок, `npp`, `parentId`, `menuOn`, `isRoute` и
`directory`. Полное содержимое после навигации читайте через `get-article`.

## Создание и сохранение статьи

### create-article

```json
{ "parentId": 1 }
```

Инструмент создаёт в конце списка детей скрытую от маршрутизации статью с
именем вида `art_1784214877114`, пустым `body` и контроллером по умолчанию.
Возьмите фактический `id` из ответа, не вычисляйте его самостоятельно.
Параметры маршрута получают умолчания модели: UTM включены, остальные флаги
выключены, `keysArr` пуст. Следующим вызовом задайте имя и содержимое
через `save-article`: создание записи ещё не публикует Blade.

### save-article

Аргументы вложены в объект `article`:

```json
{
  "article": {
    "id": 42,
    "name": "about",
    "title": "О компании",
    "body": "<h1>{{ $Env['title'] }}</h1>",
    "isRoute": true,
    "routeParams": { "useController": false }
  }
}
```

Обязателен только `article.id`. Не переданные верхнеуровневые поля остаются без
изменения. Переданные `body` и `controller` заменяются целиком. `routeParams`
берётся по ключам: не переданный ключ остаётся прежним, `keysArr` заменяется
целиком.

Разрешены `name`, `title`, `controller`, `body`, `menuOn`, `isRoute` и
`routeParams`. Ключи маршрута и их умолчания — в [маршруте статьи](use.md#маршрут-статьи).

Livewire-компонент: `routeParams.livewire = true` вместе с `isRoute = false` и
`routeParams.useController = true` — в админке галка ставит эти два значения
сама, через МСП их передают явно. Контроллер наследует `MagicProLivewire`, со
страницы компонент зовут тегом `<livewire:magic::имя />`; подробности — в
[Livewire-компоненте](use.md#livewire-компонент).

`parentId`, `npp` и `directory` намеренно игнорируются. Статья `id = 1` обязана
сохранить имя `root`. Имя любой статьи содержит только латинские буквы, цифры,
дефис и подчёркивание и должно быть уникальным. С `useController` имя ещё и имя
класса: без дефиса и не с цифры, иначе статья сохранится, а контроллер нет —
в ответе будет `warning`.

Перед записью перечитайте статью и отправляйте только изменяемые поля.
Для проверки свободного имени есть `get-article-by-name`; занятое имя
отклоняет модель до удаления рабочих файлов.

Прочитайте результат, включая `warning`: сохранённый исходник может ещё не
быть опубликован. Поведение ошибок подробно описано в
[сохранении и публикации](use.md#сохранение-и-публикация-статьи).
После записи перечитайте статью через `get-article` и проверьте страницу.

## Перемещение статьи

```json
{
  "id": 42,
  "newParentId": 7,
  "idBrotherUp": 31
}
```

- `newParentId` — будущий родитель;
- `idBrotherUp` — сосед, после которого надо поставить статью;
- `idBrotherUp = 0` означает первое место.

Сосед обязан быть ребёнком `newParentId`. Перенос под себя или собственного
потомка, перенос корня и установка после самого себя запрещены.

После каждого перемещения перечитайте `get-article-siblings`. При переносе
вниз текущий API учитывает освобождение прежней позиции: в ряду A B C D
перемещение A после C должно дать B C A D.

## Удаление статьи

Удаляется вся ветка. Вызов без подтверждения только показывает план:

```json
{ "id": 42, "confirm": false }
```

Ответ содержит `deleted: false`, саму статью, `goes_with`, общее `total` и
подсказку `next`. Покажите список человеку. Только после подтверждения выполните
второй вызов:

```json
{ "id": 42, "confirm": true }
```

Не допускайте изменений дерева между этими вызовами: второй вызов не связывается
с первым и удаляет ветку в её текущем состоянии. Корень удалить нельзя.

## Передача проблемы разработчику

Если инструмент не позволяет выполнить задачу или причина находится в коде
пакета, передайте разработчику описание: инструмент, несекретные аргументы,
`id` и имя статьи, фактический ответ, ожидаемый результат, адрес страницы.
Не подменяйте исправление пакета изменением сгенерированных файлов.

Для лент и других модулей выбирайте соответствующие страницы из `list-docs`.
Статьи сохраняются через `save-article`, а не через инструмент обычных файлов.
