# Изображения: ресайз на лету

Уменьшение картинок при выводе, с кешем. Оригиналы лежат как есть, производные
создаются по первому обращению.

## Как пользоваться

```php
$img = MproHelper::imageReduceX($file, 800);   // по ширине
$img = MproHelper::imageReduceY($file, 400);   // по высоте

MproHelper::imageCacheClear($file);            // снести производные исходника
```

`$file` — абсолютный путь к существующему файлу. Вторая сторона считается по
пропорциям, картинка не обрезается. Исходник меньше запрошенного — увеличивается.

Третий и четвёртый аргументы необязательны: формат и качество, без них берутся из
настроек.

```blade
<img src="{{ $img['url'] }}" width="{{ $img['width'] }}" height="{{ $img['height'] }}">
```

### Что возвращается

| Ключ | Что в нём |
| --- | --- |
| `url` | адрес для браузера; при ошибке — svg-заглушка как data-uri |
| `path` | путь от корня диска |
| `width`, `height` | фактические размеры результата, прочитанные из файла |
| `size` | вес файла в байтах |
| `ms` | сколько занял вызов; из кеша это доли миллисекунды |
| `rotated`, `rotateMs` | разворачивали ли снимок по exif и сколько это стоило |
| `cmd` | команда, которой кодировали; пусто — ответ пришёл из кеша |
| `errorMsg` | пусто, если всё вышло |

Исключений не бросается никогда: битый файл не должен ронять страницу.

## Форматы

| Формат | Чем кодируется |
| --- | --- |
| `webp` | `cwebp` |
| `iwebp` | тот же webp, но кодирует `vipsthumbnail` — для сравнения |
| `avif`, `jpg`, `png` | `vipsthumbnail` |

Разворот по exif: `vipsthumbnail` делает его сам, `cwebp` не умеет — там снимок
разворачивается заранее через gd, во временный файл. На трёхтысячном снимке это
порядка полусекунды, и оно видно отдельно в `rotateMs`.

Наличие обеих утилит проверяется на главной админки, в блоке «Обработка
изображений».

## Настройки

Группа `RESIZE`, схема в `src/Config/magicSchema.php`, правится на `/a_dmin/setup`.

| Поле | Что задаёт |
| --- | --- |
| `MAX_RESIZE` | потолок размера, 10–1000; больший запрос режется до него |
| `RESIZE_FORMAT` | формат производных |
| `UPLOAD_FORMAT` | чем кроппер ленты шлёт обрезанный кусок на сервер: png или jpeg |
| `WEBP_DEF_QUALITY`, `AVIF_DEF_QUALITY`, `JPG_DEF_QUALITY` | качество, 10–100 |
| `PNG_COMPRESSION` | у png не качество, а уровень сжатия, 0–9 |
| `IMAGE_ERROR` | svg, который отдаётся вместо картинки при ошибке |

Читается как `MagicGlobals::$INI['RESIZE']['MAX_RESIZE']`.

`MAX_RESIZE` действует только на путь хелпера. Кроппер ленты им не ограничен: там
кадрирует браузер, сервер только перекодирует, и размер остаётся тот, что прислали.

## Кеш

Лежит в `storage/app/public/magic/images/`, наружу отдаётся как
`/storage/magic/images/…`. Symlink `public/storage` — условие установки.

Папка по источнику: `p` — внутри `public`, `s` — внутри `storage`, `b` — внутри
корня проекта, `x` — чужой файл, вместо пути короткий хеш каталога. Абсолютный путь
сервера в кеш не переносится.

Имя — то, что просили: `photo_x800.webp` для `imageReduceX($file, 800)`,
`photo_y400.webp` для `imageReduceY($file, 400)`. Фактических размеров в имени нет:
имя нужно знать до кодирования, а вторую сторону до него не знает никто. У `iwebp`
метка остаётся в имени, а расширение настоящее: `photo_x800.iwebp.webp`.

Кеш годен, пока он новее исходника. Заменили картинку под тем же именем — все её
производные пересоздадутся сами. Поменяли настройки качества — не пересоздадутся,
файл-то новее; тут нужен `imageCacheClear()`.

Создание идёт под замком на 30 секунд, ожидание — до пяти. Не дождались — вместо
картинки заглушка, на следующей загрузке страницы всё будет нормально.

## Устройство

Два класса в `src/Image/`:

- `ImageJob` — задание на одно уменьшение. Всё вычисленное лежит в его полях:
  пути, url, ключ замка, качество. Он же проверяет кеш, берёт замок, зовёт энкодер
  и собирает ответ. Снаружи два статических входа — `make()` и `clear()`.
- `ImageEncoder` — запуск утилит. На каждый формат свой метод, общий только
  `run()`. Про кеш и настройки не знает, поэтому его можно звать напрямую, чтобы
  просто перекодировать файл в файл.

## Кроппер ленты

В поле-картинке ленты обрезка делается в браузере. Обрезанный кусок уходит на
сервер в формате `UPLOAD_FORMAT` (png или jpeg 0.95) командой `imageCropUpload`, и
уже сервер кодирует его в `RESIZE_FORMAT` тем же энкодером. Загрузка без обрезки
идёт прежней командой `imageUpload` и сохраняет файл как есть.
