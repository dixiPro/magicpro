# Почта: как пользоваться

Почтовая подсистема отправляет одно HTML-письмо одному получателю, сохраняет
историю в базе и умеет отложенную отправку с повторными попытками.

Есть три входа:

| Вход | Для чего |
| --- | --- |
| `MproHelper::sendMail()` | простая немедленная отправка со страницы или из контроллера |
| `API_Mail::run()` | полный API без HTTP: немедленная отправка, очередь, списки и удаление |
| `POST /a_dmin/api/mailSystem` | тот же полный API из админки; маршрут защищён `magic.auth` |

Письмо должно приходить уже собранным HTML. Подсистема не выбирает шаблон, не
делает массовую рассылку, не добавляет текстовую альтернативу и не поддерживает
вложения, CC или BCC.

Настройки почты — на `/a_dmin/setup`; что именно и как настраивается на стороне
Amazon — `docs/ru/aws/use.md`.

## Быстрая отправка через MproHelper

```php
$result = MproHelper::sendMail([
    'email'    => 'user@example.com',
    'subj'     => 'Ваш заказ принят',
    'html'     => '<h1>Спасибо за заказ</h1>',
    'replyTo'  => 'manager@example.com',
    'fromName' => 'Magic Shop',
]);
```

### Параметры

| Ключ | Обязателен | Что передавать |
| --- | --- | --- |
| `email` | да | адрес получателя |
| `subj` | да | тема длиной не меньше 8 символов |
| `html` | да | готовое HTML-тело длиной не меньше 16 символов |
| `replyTo` | нет | валидный адрес, на который должна вести кнопка «Ответить» |
| `fromName` | нет | отображаемое имя отправителя |

`fromName` меняет только имя перед адресом. Адрес отправителя берётся из
`config('mail.from.address')`, обычно из `MAIL_FROM_ADDRESS`.

Пустые `replyTo` и `fromName` равны отсутствующим. В этом случае Reply-To не
добавляется, а имя берётся из `config('mail.from.name')`. Лишние ключи хелпер
игнорирует.

Хелпер не позволяет переопределить адрес отправителя и не ставит письмо в
очередь. Для этого нужен полный API.

### Ответ хелпера

```php
[
    'status'   => true,
    'errorMsg' => '',
    'data'     => [
        'id'                  => 123,
        'mail_id'             => '...',
        'provider_message_id' => '...',
        'status'              => 'sent',
    ],
]
```

При ошибке:

```php
[
    'status'   => false,
    'errorMsg' => '...',
    'data'     => [],
]
```

`MproHelper::sendMail()` перехватывает исключения и возвращает ошибку в массиве.
Каждый вызов также записывает итог в лог `mail`.

Проверяйте `status`:

```php
$result = MproHelper::sendMail($mail);

if (! $result['status']) {
    MproHelper::addLog('orderMail', [
        'error' => $result['errorMsg'],
    ]);
}
```

Успешная отправка означает, что транспорт принял письмо. Доставку подтверждает
отдельное событие SES, после которого статус станет `delivered`.

## Полный API из PHP

```php
use MagicProSrc\Mail\API_Mail;

$result = API_Mail::run('sendLater', [
    'to'      => 'user@example.com',
    'subject' => 'Ваш заказ принят',
    'html'    => '<h1>Спасибо за заказ</h1>',
]);
```

Обратите внимание на другие имена обязательных ключей:

| MproHelper | API_Mail |
| --- | --- |
| `email` | `to` |
| `subj` | `subject` |
| `html` | `html` |

### Форма ответа API

При успехе:

```php
[
    'status'   => true,
    'errorMsg' => '',
    'data'     => [...],
    'request'  => [...],
]
```

При ошибке текущая реализация возвращает:

```php
[
    'status'   => false,
    'line'     => '/path/to/file.php 123',
    'errorMsg' => '...',
    'request'  => [...],
]
```

Ключа `data` в ветке ошибки сейчас нет, поэтому внутренний вызывающий должен
сначала проверять `status` или читать данные как `$result['data'] ?? []`.

`API_Mail::run()` сам исключение не пробрасывает: `AbstractMailApi` ловит
`Throwable` и собирает отрицательный ответ.

## Полный API через HTTP

Точка входа:

```text
POST /a_dmin/api/mailSystem
```

Маршрут использует middleware `magic.auth`; CSRF middleware для него отключён.
Команда и параметры передаются одним JSON-объектом:

```json
{
    "command": "sendLater",
    "to": "user@example.com",
    "subject": "Ваш заказ принят",
    "html": "<h1>Спасибо за заказ</h1>"
}
```

HTTP-ответ повторяет массив `API_Mail::run()` в JSON.

## Команды

| Команда | Назначение |
| --- | --- |
| `sendNow` | немедленно отправить письмо выбранным транспортом |
| `sendLater` | записать письмо в очередь |
| `sendQueue` | отправить все письма, срок которых наступил |
| `emailQueue` | получить очередь одного адреса |
| `messagesList` | получить страницу сообщений для админки |
| `addressesList` | получить страницу реестра адресов |
| `deleteEmail` | удалить одно сообщение |
| `deleteQueueByEmail` | удалить ожидающие письма одного адреса |

## sendNow

```php
$result = API_Mail::run('sendNow', [
    'to'       => 'user@example.com',
    'subject'  => 'Ваш заказ принят',
    'html'     => '<h1>Спасибо за заказ</h1>',
    'from'     => 'info@example.com',
    'fromName' => 'Magic Shop',
    'replyTo'  => 'manager@example.com',
]);
```

| Параметр | Обязателен | Поведение |
| --- | --- | --- |
| `to` | да | обрезается по краям и приводится к нижнему регистру |
| `subject` | да | строка не короче 8 символов |
| `html` | да | строка не короче 16 символов |
| `from` | нет | пустое значение заменяется `config('mail.from.address')` |
| `fromName` | нет | пустое значение заменяется `config('mail.from.name')` |
| `replyTo` | нет | непустое значение валидируется как email |

При успехе `data` содержит `id`, `mail_id`, `provider_message_id` и статус
`sent`.

Строка письма записывается до отправки, в статусе `sending`: не записалась —
письмо не уходит. После ответа транспорта статус становится `sent`.

Если транспорт вернул ошибку, сообщение получает статус `retrying`,
`attempts = 1`, первую запись в `errors`, и команда возвращает `status = false`.
Ошибка валидации, блокировка адреса или защита от дубля возникают раньше и
сообщение не создают.

Два одинаковых письма (тот же адрес и тема) в одну секунду не уйдут оба:
проверка дубля и запись строки идут под замком, второе получает
`duplicate email`.

### Выбор транспорта

`sendNow` проверяет `AWS_SesV2Client`:

- truthy-значение — Amazon SES API v2;
- пустое или false — SMTP-транспорт Laravel.

Очередь этот переключатель не использует и всегда отправляет через SMTP.

## sendLater

```php
$result = API_Mail::run('sendLater', [
    'to'           => 'user@example.com',
    'subject'      => 'Ваш заказ принят',
    'html'         => '<h1>Спасибо за заказ</h1>',
    'scheduled_at' => now()->addHour(),
]);
```

Параметры письма те же, что у `sendNow`. `scheduled_at` относится только к
очереди. Если он отсутствует или равен пустой строке, ставится время через 60
секунд.

Отдельной валидации формата `scheduled_at` нет: значение передаётся модели с
datetime cast. Из HTTP передавайте дату, которую понимает Laravel и база.

При успехе `data` содержит:

```php
[
    'id'           => 123,
    'status'       => 'queued',
    'scheduled_at' => '...',
]
```

`sendLater` не отправляет письмо и не проверяет транспорт. Без работающего
планировщика сообщение останется в `queued`.

## Очередь и повторные попытки

`MagicProSchedule` запускает `sendQueue` каждую минуту. Команда выбирает
сообщения со статусом `queued` или `retrying`, у которых `scheduled_at` пуст или
не позже текущего времени, — пачками по 50 и не дольше 240 секунд за проход;
остальное уходит следующей минутой. Каждое письмо перед отправкой забирается
(статус `sending`), поэтому одно письмо не уйдёт дважды.

Для обычного `sendLater` последовательность неудач такая:

| Неудачная отправка | Новое attempts | Результат |
| --- | --- | --- |
| первая | `1` | `retrying`, следующая попытка через 5 минут |
| вторая | `2` | `retrying`, следующая попытка через 10 минут |
| третья | `3` | `retrying`, следующая попытка через 30 минут |
| четвёртая | `4` | `failed`, новых попыток нет |

Неудачный `sendNow` сразу создаёт строку с `attempts = 1`, но без
`scheduled_at`. Поэтому она попадёт в ближайший минутный проход очереди. Если и
эта отправка не выйдет, `attempts` станет `2`, а следующая попытка будет
назначена через 10 минут.

Очередь защищена общим lock `API_Mail::sendQueue` на 300 секунд. Второй процесс
не ждёт lock: он возвращает нулевые счётчики.

Результат `sendQueue`:

```php
[
    'total'    => 12,
    'sent'     => 10,
    'failed'   => 2,
    'retrying' => 1,
    'stopped'  => 1,
]
```

`failed` — количество **неудачных отправок этого прохода**, поэтому `total`
всегда равен `sent + failed`. Что стало с этими письмами дальше, говорят два
последних числа: `retrying` получили новую дату, `stopped` исчерпали попытки и
больше не будут пытаться.

## Защита от дублей

Дубль определяется по паре нормализованный `to` + точный `subject`. Проверяется
последнее сообщение с такой парой:

- `queued` или `retrying` — новая команда получает `duplicate email`;
- у сообщения есть `sent_at` и с него прошло меньше `retryTimeEmail` секунд —
  новая команда получает `too frequent send to this address`;
- иначе новая отправка разрешена.

Значение `retryTimeEmail` по умолчанию — 60 секунд. Статусы `delivered`, `open`
и `failed` не блокируют повтор навсегда. У `failed` обычно нет `sent_at`, поэтому
после окончательного отказа письмо с той же темой можно создать снова.

Защита привязана к теме. Если разные виды писем не должны блокировать друг
друга, используйте разные темы.

## Реестр и блокировка адресов

При первом обращении адрес приводится к нижнему регистру и записывается в
`magicPro_email_addresses` вместе с IP текущего запроса.

События SES `Bounce` и `Complaint` ставят адресу блокировку. Следующий
`sendNow` или `sendLater` завершится ошибкой до создания строки сообщения. Текст
ошибки берётся из `block_reason`, а при пустой причине используется
`email blocked`.

Разблокировка отдельной командой `API_Mail` не реализована.

## Статусы сообщения

| Статус | Значение |
| --- | --- |
| `queued` | ожидает первой отправки |
| `retrying` | предыдущая попытка не удалась, письмо ещё будет отправляться |
| `sent` | транспорт принял письмо |
| `delivered` | SES сообщил о доставке |
| `open` | SES сообщил об открытии, прошедшем временной фильтр |
| `failed` | попытки закончились |
| `emailblocked` | SES сообщил Bounce или Complaint и адрес заблокирован |

Для списка админки `queued` и `retrying` относятся к разделу `queue`. Все
остальные статусы относятся к `sent`.

## Получение списков

### emailQueue

```php
$result = API_Mail::run('emailQueue', [
    'email' => 'user@example.com',
]);
```

Возвращает нормализованный адрес в `to` и массив `queue`. В выборку входят только
`queued` и `retrying`, сортировка — по `scheduled_at`, затем по `id`.

### messagesList

```php
$result = API_Mail::run('messagesList', [
    'section' => 'queue',
    'search'  => 'example.com',
    'count'   => 30,
    'offset'  => 0,
]);
```

| Параметр | Поведение |
| --- | --- |
| `section` | точное `queue` выбирает очередь, любое другое значение — остальные статусы |
| `search` | подстрока в `to_email`, без учёта регистра переданного значения |
| `count` | по умолчанию 30, меньше 1 заменяется на 30, больше 200 срезается до 200 |
| `offset` | по умолчанию 0; отрицательное значение заменяется на 0 |

Потолок в 200 строк стоит на обеих командах списков: письма хранят html целиком,
и запрос «дайте всё» вытащил бы из базы всё.

Ответ содержит `section`, `total`, `count`, `offset` и `messages`. Поле `errors`
и полные `html`/`raw_message` входят в каждую выбранную строку.

### addressesList

```php
$result = API_Mail::run('addressesList', [
    'search' => 'example.com',
    'count'  => 30,
    'offset' => 0,
]);
```

Возвращает `total`, `count`, `offset` и `addresses`. Поиск выполняется по
подстроке email, сортировка — по email. Потолок тот же, 200.

## Удаление

### deleteEmail

По внутреннему ID:

```php
API_Mail::run('deleteEmail', ['id' => 123]);
```

По идентификатору сообщения:

```php
API_Mail::run('deleteEmail', ['MessageId' => $messageId]);
```

Допускается также ключ `message_id`. По строковому идентификатору сначала ищется
`provider_message_id`, затем `mail_id`. Ответ содержит `deleted = true` и `id`.

### deleteQueueByEmail

```php
API_Mail::run('deleteQueueByEmail', [
    'email' => 'user@example.com',
]);
```

Удаляет только `queued` и `retrying` этого адреса. Возвращает нормализованный
адрес в `to` и количество удалённых строк в `deleted`.

## Наблюдение за работой

- экран сообщений и адресов: `/a_dmin/mailSystem`;
- состояние планировщика видно на главной странице `/a_dmin`;
- вызовы `MproHelper::sendMail()` пишутся в лог `mail`;
- входящие SNS-запросы, кроме диагностического ping, пишутся в основной лог
  Laravel;
- настройка AWS SES и SNS описана отдельно в `docs/ru/aws/`.
