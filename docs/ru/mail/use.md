# Почта: как пользоваться

## Со страницы

Простой случай — отправить прямо сейчас:

```php
$res = MproHelper::sendMail([
    'email' => 'user@example.com',
    'subj'  => 'Тема письма',
    'html'  => '<h1>Привет</h1>',
]);

if (! $res['status']) {
    MproHelper::addLog('myLog', ['error' => $res['errorMsg']]);
}
```

Исключений не бросает, возвращает `status / errorMsg / data`. Каждая попытка,
удачная и нет, пишется в лог `mail`.

Всё остальное — через API.

## Через API

Одна точка: `POST /a_dmin/api/mailSystem`, за middleware `magic.auth`. Команда
едет в теле запроса вместе с параметрами:

```json
{ "command": "sendLater", "to": "user@example.com", "subject": "…", "html": "…" }
```

Ответ всегда одной формы:

```json
{ "status": true, "errorMsg": "", "data": {}, "request": {} }
```

При ошибке `status: false` и текст в `errorMsg`.

Из кода вызывается тем же способом, без http:

```php
API_Mail::run('sendLater', ['to' => $email, 'subject' => $subj, 'html' => $html]);
```

### Команды

| Команда | Что делает |
| --- | --- |
| `sendNow` | отправить немедленно |
| `sendLater` | положить в очередь |
| `sendQueue` | разобрать очередь; обычно её зовёт крон |
| `emailQueue` | что стоит в очереди на один адрес |
| `messagesList` | список писем для админки, с разделами и пагинацией |
| `addressesList` | реестр адресов |
| `deleteEmail` | удалить письмо по `id` или `MessageId` |
| `deleteQueueByEmail` | вычистить очередь одного адреса |

### Параметры письма

Общие для `sendNow` и `sendLater`:

| Параметр | Обязателен | Замечание |
| --- | --- | --- |
| `to` | да | приводится к нижнему регистру |
| `subject` | да | не короче 8 символов |
| `html` | да | не короче 16 символов |
| `from`, `fromName` | нет | без них берётся `mail.from` из конфига |
| `replyTo` | нет | если есть, проверяется как email |
| `scheduled_at` | нет | только `sendLater`; без него — через минуту |

`sendNow` возвращает `id`, `mail_id`, `provider_message_id` и статус. `sendLater`
— `id`, статус и `scheduled_at`.

### Списки

`messagesList` принимает `section` (`queue` или `sent`), `search` — подстрока по
адресу, `count` (по умолчанию 30, максимум 200) и `offset`. Ошибки письма
отдаются сразу, чтобы модалка не делала второй запрос.

`emailQueue` и `deleteQueueByEmail` ждут параметр `email`.

## Статусы письма

| Статус | Что значит |
| --- | --- |
| `queued` | ждёт отправки |
| `sent` | транспорт принял письмо |
| `delivered` | доставлено, пришло вебхуком |
| `open` | открыто получателем, вебхуком |
| `retrying` | отправка не вышла, будет ещё попытка |
| `failed` | попытки кончились |
| `emailblocked` | адрес заблокирован |

Для админки `queued` и `retrying` — это «очередь», всё остальное — «отправленные».

## Что стоит помнить

**Письмо всегда попадает в базу.** Даже неудачное: у него появится строка со
статусом `retrying` и первой ошибкой. Ошибки не перезаписываются, а копятся
списком, так что вся история доставки лежит в одном поле.

**Дубли отсекаются.** Пара «адрес + тема» проверяется по последнему такому
письму: если оно ещё не отправлено — `duplicate email`; если отправлено меньше
`retryTimeEmail` секунд назад (по умолчанию 60) — `too frequent`. Для писем с
одинаковой темой это важно: подтверждение регистрации и уведомление о заказе
лучше делать с разными темами.

**Заблокированный адрес не принимается.** Первое же обращение к незнакомому
адресу заводит его в реестре. Блокировка ставится вебхуком при `Bounce` и
`Complaint`, и после неё отправка на этот адрес падает с текстом причины.

**Очередь разбирает крон.** `sendLater` только кладёт письмо в базу. Дальше его
берёт `sendQueue`, которого раз в минуту зовёт планировщик. Крон не настроен —
письма будут лежать; статус планировщика видно на `/a_dmin`.

**Ретраи по нарастающей.** Попытка 1 — через 5 минут, 2 — через 10, 3 — через 30.
После третьей письмо становится `failed`.
