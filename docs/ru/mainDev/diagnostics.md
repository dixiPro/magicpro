# Как искать ошибки в MagicPro

Начните с наблюдаемого результата: адрес, HTTP-метод, параметры, статья или
инструмент, ожидаемое поведение и фактический ответ. Для сохранения отличайте
исходник в базе, рабочий файл, HTTP-ответ и статическую HTML-копию.

## От симптома к коду

| Симптом | Что проверить | Где читать |
| --- | --- | --- |
| Статья отвечает 404 | Имя, `isRoute`, `adminOnly`, допустимые ключи и число сегментов | `DynamicRouteHandler::checkFirts()`, `checkRout()` |
| Ответ 405 | Метод запроса и `postEnable` | `DynamicRouteHandler::checkMethod()` |
| Ответ 419 | Переданный токен и токен сессии | `DynamicRouteHandler::checkToken()` |
| Контроллер отвечает 500 | Исключение в `process()` или рендеринге, включая `abort()` | `MagicController::handle()`, `errorResponse()` |
| Сохранение вернуло `warning` | Имя PHP-класса и синтаксис; текст уже мог сохраниться | `saveById()`, `checkControllerName()`, `lintControllerText()` |
| Сохранён новый текст, виден старый | `warning`, рабочие файлы, HTML-копия и включение статьи на других страницах | `saveById()`, `createMpro()`, `forgetStaticHtml()` |
| После переименования не найден класс или Blade | Новое имя в базе, успешность публикации и ссылки по старому имени | API статей, генератор, вызывающие статьи |
| Не тот порядок дерева | Родитель, `npp`, выбранный сосед и диапазон сдвига | `moveWithinParent()`, `moveToAnotherParent()` |
| В Blade нет `$Post` | Возвращает ли его `process()` | `MagicController` разделяет только `Env` и `Get` |
| Нет новой версии архива | Отличается ли JSON от последней версии, нет ли ошибки архива в логе `api` | `ArticleArchive::add()`, `saveById()` |
| МСП не видит документ | Язык, наличие файла, запись в индексе и `agent` | `DocsTree`, `ListDocsTool`, `GetDocTool` |

Карта полных путей — в [устройстве ядра](use.md#карта-файлов).

## Анализ без изменения состояния

1. Прочитайте обработчик входа: маршрут админки, публичный маршрутизатор или MCP-инструмент.
2. Проследите вызовы до API, модели и генератора.
3. Сопоставьте реальные условия кода с переданными аргументами.
4. Проверьте границы транзакций и перехваты исключений.
5. Найдите другие вызовы изменяемого метода и сравните их предварительные проверки.
6. Отделите доказанное поведение от гипотезы, требующей воспроизведения.

Примеры поиска из корня хост-проекта:

```bash
rg -n 'saveById|createMpro|deleteMpro' packages/dixipro/magicpro/admin packages/dixipro/magicpro/src
rg -n 'ROUTE_PARAMS|routeParams\(' packages/dixipro/magicpro/database packages/dixipro/magicpro/src
rg -n 'warning|errorResponse|catch ' packages/dixipro/magicpro/admin/controller packages/dixipro/magicpro/src
```

Чтение логов и сгенерированных файлов помогает сопоставить результат с кодом.
Файлы `* copy.php` и `* copy.js` — резервные копии, а не образец текущего
поведения. `CHANGELOG.md` не заменяет чтение реализации.

Во время аудита исходники не меняются. Выводы записываются в документацию
или отчёт аудита. Перегенерация, cleanup, восстановление версии и повторное
сохранение меняют состояние; они не являются проверкой только чтением.

## Выбрать воспроизведение

Подбирайте сценарий к конкретной гипотезе. Для ошибки перемещения нужен
определённый исходный порядок и целевой сосед. Для ошибки публикации —
исходное имя, наличие прежних файлов, переданный PHP и ответ сохранения.

Запуск такого сценария может создавать записи, менять файлы и исполнять код
приложения. Сначала учитывайте разрешения проекта. Если выполнен только анализ
кода, так и укажите в результате; не называйте его проверкой в браузере.

## Записать находку

Отчёт о дефекте помещается в `toDo/` пакета и содержит:

- краткое название и затронутый механизм;
- условия, при которых возникает проблема;
- ожидаемый и фактический результат;
- файлы, методы и последовательность вызовов, подтверждающие вывод;
- последствие для админа или МСП;
- способ проверки и отметку, выполнялся ли он;
- оставшуюся неопределённость, если для вывода не хватает состояния сайта.

Не включайте токены, пароли и личные данные в примеры запросов. Предложение
исправления оформляется как предложение, а не как уже реализованное поведение.
После исправления документация описывает итоговый контракт системы.

## Матрица проверки изменения

Это набор сценариев для выбора по задаче, а не требование запускать всё
после любой правки. Ни один сценарий не считается выполненным только потому,
что перечислен здесь.


### Данные и генерация

- создать статью, сохранить и проверить появление Blade;
- включить контроллер и проверить PHP-файл;
- переименовать и убедиться, что старые файлы исчезли, новые появились;
- выключить контроллер и убедиться, что PHP-файл удалён;
- сохранить без изменений и проверить отсутствие новой версии;
- восстановить версию и проверить базу и оба файла;
- ошибка имени модели не удаляет прежние файлы;
- ошибка PHP даёт `warning`, сохраняет текст и не публикует новые файлы;
- отказ диска и отказ архива различаются по ответу и состоянию.

### Маршруты

- `/` → `index`;
- обычная статья без параметров;
- выключенный `isRoute` → 404;
- `adminOnly` до и после входа;
- пары `/key/value`;
- нечётный список сегментов → 404;
- query string;
- непустой whitelist и лишний ключ;
- bindKeys с точным и неверным числом значений;
- UTM включены и выключены;
- `postEnable` для GET, HEAD и POST;
- POST без разрешения и PUT/PATCH/DELETE дают 405; неверный токен — 419;
- отсутствие токена сейчас пропускается, это отдельный сценарий;
- `robots___txt` через `/robots.txt` и прямой URL с подчёркиваниями;
- исключённый префикс и обычный Laravel route.

### Рендеринг

- direct Blade видит Env/Get/Post;
- controller видит request/getParams/postParams;
- controller возвращает данные в Blade;
- redirect, status, headers и Content-Type;
- обычное исключение внутри обработчика маршрута даёт 404 article;
- `HttpException` маршрутизатора сохраняет свой код, включая 405 и 419;
- исключение process, включая `abort(404)`, даёт 500 MagicController;
- layout и include не запускают чужой controller;
- анонимный, классовый и Livewire-компоненты;
- чужой Livewire-компонент проходит через parent registry.

### Дерево

- создание последним ребёнком;
- перестановка первым, в середину и последним;
- перенос между двумя родителями;
- очистка `directory` у опустевшего родителя;
- копия без детей;
- рекурсивное удаление и плотные `npp`;
- запрет удаления root;
- меню видит только `menuOn`.

### Статика и админка

- crawler видит внутренние и внешние ссылки;
- redirect и non-200 отражаются ошибкой;
- staging содержит ожидаемые имена;
- публикация заменяет весь public-каталог;
- после изменения или удаления статьи её static HTML снимается `forgetStaticHtml()`
  (вызывается из `deleteMpro()`), и nginx отдаёт запрос в php;
- неавторизованный API получает 401, неверная роль — 403.
