# Импорт: как пользоваться

`/a_dmin/import_tab`, раздел «Import» в левой колонке. Открыт администратору.

## Формат файла

То, что отдаёт экспорт: список статей, у каждой поля статьи и `parentName` —
имя родителя.

```json
[
  {
    "npp": 1,
    "name": "about",
    "title": "О нас",
    "controller": "",
    "body": "<p>...</p>",
    "directory": false,
    "menuOn": true,
    "isRoute": true,
    "routeParams": { "useController": false },
    "parentName": "root"
  }
]
```

Идентификаторов в файле нет и быть не должно: на другом сайте они значат другое.
Родитель пишется именем — это единственное, о чём два дерева договариваются.

Статья, чьего родителя в файле нет, — **верхушка**. Верхушек может быть
несколько: файл не обязан содержать одно поддерево.

## Два прохода

**Проверить** — первый проход. Не меняет ничего: разбирает файл, проверяет его и
говорит то, что стоит сказать. Пока проверка не прошла начисто, кнопка «Импорт»
не работает.

**Импорт** — второй проход. Те же проверки заново, потом работа. Строки отчёта
те же, справа у каждой появляется «сделано».

В отчёт идут только ошибки и коллизии — то есть то, что сайт теряет. «Статья
такая-то поднимается из файла» не пишется: это и есть импорт, читать там нечего.
Полный импорт сносит дуб целиком, поэтому при исправном файле его отчёт пуст.

Файл на сервере не сохраняется: он читается браузером и уходит с каждым
нажатием.

Что проверяется: файл — список; у каждой записи есть имя; имя из латинских букв,
цифр, дефиса и подчёркивания; имена в файле не повторяются; статьи не ссылаются
друг на друга по кругу; для частичного импорта — что статьи `root` в файле нет.

## Частичный импорт

Берёза цепляется к дубу:

- родитель верхушки есть в дубе — цепляем к нему;
- нет — цепляем к корню последним листом.

Родитель, которого импорт сам же и удаляет, за родителя не считается: такая
верхушка уходит к корню, и отчёт об этом говорит.

Совпало имя — статья дуба удаляется со всем своим поддеревом. В отчёте это две
строки:

```text
Статья about есть в берёзе и в дубе — дубовая будет удалена
Родитель about: берёза не имеет статьи about_old, есть в дубе, будет удалена
```

Вторая строка — про то, что уйдёт заодно. Если такое нужно сохранить, дерево
готовит человек, до импорта.

Третья строка, которая бывает, — про место. Файл вешает верхушку на статью,
которой на сайте нет или которую импорт сам же и удаляет; верхушка уходит в
корень, и отчёт об этом говорит: приземлилась она не туда, куда сказано в файле.

`npp` берётся из файла: берёза рулит. Исключение — верхушка: она встаёт
последней среди детей своего нового родителя, потому что её номер приехал из
чужого дерева.

Файл со статьёй `root` частичным импортом не поднимается: это файл всего сайта,
и вешать его в угол другого сайта незачем. Экспорт поддерева `root` в файл не
кладёт — такой файл для частичного импорта и годится.

## Полный импорт

1. Снимок дуба, если стоит галка.
2. Дуб сносится.
3. Берёза поднимается целиком.
4. Генерятся блейды и контроллеры.

Корень дуба, `id = 1`, удалить нельзя ни моделью, ни админкой. Поэтому сносится
всё, кроме него, а `root` берёзы вливается в существующий корень: заголовок,
тело и флаги берутся из файла, имя `root` остаётся.

Нет в файле `root` — верхушки цепляются к корню, всё остальное сносится
одинаково.

## Сохранённые состояния

Снимок — это экспорт всего дерева, тот же файл, что даёт правая кнопка на
корне. Лежит в `storage/app/private/magic/articles/`.

Имя вписывается руками, рядом с кнопкой. Страница предлагает `root_` и дату до
минуты — `root_2026-01-30_18-36`, — а дальше это обычное поле: через полгода
`before_the_shop` скажет больше, чем дата. Из вписанного на диск попадают только
латинские буквы, цифры, дефис и подчёркивание, остальное отбрасывается;
расширение `.json` дописывается само. Имя уже занято — спросим, перезаписывать
ли.

Кто его делает:

- **Сохранить состояние** — кнопка, когда захотелось;
- сам, перед вторым проходом, если стоит галка «сохранить состояние перед
  импортом». Галка действует на частичный импорт и на полный; к восстановлению
  отношения не имеет.

Список снимков внизу страницы, у каждого три действия:

- **скачать** — тот же файл, что и экспорт;
- **восстановить** — полный импорт из снимка: сайт сносится и поднимается из
  файла. Спрашивается подтверждение. Снимка перед восстановлением не делается:
  ради этого состояния и сохраняли, а снимок того, что решили выбросить, никто
  никогда не откроет;
- **удалить** — сразу и насовсем, корзины нет.

Снимок, который делается сам, имя не спрашивает: `root_` и дата до минуты.

Снимки копятся и сами не чистятся. Сколько их держать — забота администратора.

## Что нужно знать

**Импорт меняет базу разом.** Вся работа идёт в одной транзакции: упало на
середине — не изменилось ничего.

**Файлы генерятся после.** Блейды и контроллеры перегенерируются одним прогоном
по всему дереву, после того как база записана. Пока идёт импорт, на сайте живут
старые файлы.

**Ограничения на размер файла нет.** Упирается в настройки PHP, не в MagicPro.
