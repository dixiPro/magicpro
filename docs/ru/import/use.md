# Импорт статей: руководство администратора

Импорт переносит дерево статей MagicPro из JSON-файла экспорта.

Откройте:

```text
/a_dmin/import_tab
```

Операции API доступны только пользователю MagicPro с ролью администратора.

## Главное предупреждение

JSON статьи содержит исходники Blade и PHP-контроллера. После импорта MagicPro записывает их в
рабочие файлы сайта. Импортируйте только файл, происхождение и содержимое которого вы доверяете:
такой файл фактически способен добавить исполняемый PHP-код.

Полный импорт удаляет все статьи, кроме системной записи `root` с `id = 1`. Перед операцией:

1. сделайте экспорт `root` и сохраните файл у себя — это и есть точка отката: полный импорт
   этого файла вернёт дерево;
2. проверьте файл в нужном режиме непосредственно перед нажатием «Импорт» — смена режима
   сбрасывает проверку;
3. после выполнения проверьте страницы и контроллеры, а не только зелёное сообщение.

## Откуда взять файл

### Экспорт статьи или поддерева

В редакторе статей выберите экспорт нужной статьи. Файл содержит выбранную статью и всех её
потомков.

- Экспорт `root` содержит нормальное полное дерево сайта.
- Экспорт другой статьи подходит для частичного переноса поддерева.
- Технические идентификаторы не экспортируются.
- Родитель верхней статьи записывается именем, даже если он находится за пределами экспорта.

## Формат JSON

Верхний уровень — непустой JSON-массив. Каждый элемент — объект одной статьи.

Полный пример:

```json
[
  {
    "npp": 1,
    "name": "about",
    "title": "О нас",
    "controller": "",
    "body": "<h1>About</h1>",
    "directory": false,
    "menuOn": true,
    "isRoute": true,
    "routeParams": {
      "useController": false,
      "adminOnly": false,
      "utmParamsEnable": false,
      "getEnable": false,
      "postEnable": false,
      "bindKeys": false,
      "keysArr": []
    },
    "parentName": "root"
  }
]
```

### Поля статьи

| Поле | Ожидаемый тип | Если отсутствует у новой статьи | Назначение |
| --- | --- | --- | --- |
| `name` | string | импорт запрещён | Уникальное имя статьи и ключ переноса |
| `parentName` | string или `null` | верхняя статья | Имя родителя; не является полем таблицы |
| `npp` | integer | `0` | Позиция среди детей импортированного родителя |
| `title` | string | `''` | Заголовок |
| `controller` | string | `''` | Исходник PHP-контроллера |
| `body` | string | `''` | Исходник Blade |
| `directory` | boolean | `false` | Заявленный признак наличия детей |
| `menuOn` | boolean | `false` | Участие в меню |
| `isRoute` | boolean | `false` | Доступность как публичного маршрута |
| `routeParams` | object | `null` | Параметры маршрута и контроллера |

Значения по умолчанию выше относятся к создаваемым статьям. При полном импорте строка `root`
обновляет существующий корень: отсутствующие в JSON поля корня сохраняют прежнее значение.

Поля `id`, `parentId`, `templateName`, `created_at`, `updated_at` и любые неизвестные ключи
игнорируются. Не используйте их для передачи данных.

### Имя статьи

`name` обязательно, обрезается по краям и должно содержать только латинские буквы, цифры, дефис
и подчёркивание. После обрезки имена в одном файле не должны повторяться.

Если используется PHP-контроллер, правило строже: имя класса должно начинаться с латинской
буквы или подчёркивания, а дальше содержать только латинские буквы, цифры и подчёркивание.
Например, `orderForm` подходит, а `order-form` и `2026report` — нет.

Текущая кнопка «Проверить» это более строгое правило не проверяет. Ошибка может обнаружиться
только после изменения базы, во время генерации контроллера.

### Родитель

Связь задаётся через `parentName`, а не через ID:

- родитель присутствует в файле — статья создаётся под ним;
- родителя в файле нет — статья считается верхней;
- верхних статей может быть несколько;
- пустой `parentName`, `null` или отсутствие поля также означает верхнюю статью.

Для частичного импорта верхняя статья пытается присоединиться к статье сайта с именем из
`parentName`. Если такого родителя нет либо он сам будет удалён импортом, статья присоединяется к
`root` последней.

Для полного импорта все внешние родители исчезают, поэтому верхние статьи присоединяются к
`root`.

### `routeParams`

Передавайте полный объект:

```json
{
  "useController": false,
  "adminOnly": false,
  "utmParamsEnable": false,
  "getEnable": false,
  "postEnable": false,
  "bindKeys": false,
  "keysArr": []
}
```

Импорт не дополняет отсутствующие ключи и почти не проверяет типы. Маршрутизатор читает часть
полей без fallback, поэтому повреждённый или неполный объект способен сломать открытие статьи.

## Что делает «Проверить»

Кнопка отправляет файл на сервер, но не сохраняет его и не изменяет базу. Проверяются:

- JSON разбирается в массив;
- верхний массив является списком;
- список не пуст;
- каждый элемент является JSON-объектом/массивом данных статьи;
- у каждой записи есть непустое допустимое `name`;
- имена внутри файла не повторяются;
- связи `parentName` внутри файла не образуют кольцо;
- частичный импорт не содержит статью `root`.

Для частичного режима сервер также читает текущее дерево и строит отчёт о столкновениях и
переносе верхних статей к корню.

### Чего проверка не делает

Зелёный результат не означает полную готовность файла. Сейчас не проверяются:

- типы и размеры остальных полей;
- полнота `routeParams`;
- синтаксис Blade;
- синтаксис и имя класса PHP-контроллера;
- пригодность `name` для PHP-класса при включённом контроллере;
- отрицательные, повторяющиеся или слишком большие `npp`;
- соответствие `directory` фактическому наличию детей;
- ограничения размера запроса, PHP, web server и базы;
- изменение дерева другим процессом между проверкой и импортом.

Поэтому перед импортом нужно просматривать сам файл, особенно `controller`, `body`,
`routeParams`, `npp` и `directory`.

## Отчёт проверки

Ошибки блокируют кнопку импорта. Коллизии не блокируют: они предупреждают о данных сайта,
которые будут потеряны.

Возможные ошибки:

| Сообщение | Причина |
| --- | --- |
| Файл не разбирается как JSON | Синтаксическая ошибка JSON или скаляр вместо структуры |
| В файле не список статей | Верхний JSON object имеет ключи вместо последовательного массива |
| В файле нет статей | Массив пуст |
| Строка не является статьёй | Элемент массива не object/array |
| Нет имени | `name` отсутствует либо пуст после trim |
| Недопустимое имя | В имени есть другие символы |
| Имя встречается дважды | Две строки имеют одно имя после trim |
| В файле есть `root` | Для такого файла выбран частичный режим |
| В файле кольцо | Цепочка родителей никогда не достигает верхней статьи |

Предупреждения частичного режима:

| Вид | Что произойдёт |
| --- | --- |
| Замена | Статья сайта с таким именем и всё её поддерево будут удалены |
| Удаление потомка | Потомок удаляемой статьи отсутствует в файле и не вернётся |
| Перенос к корню | Указанный внешний родитель отсутствует или сам удаляется |

Фраза «ошибок нет» означает лишь, что реализованные проверки пройдены. Она не гарантирует
валидность Blade/PHP и согласованность всех полей.

## Частичный импорт

Частичный режим добавляет дерево из файла к существующему дереву.

### Столкновение имён

Если `name` уже существует на сайте, версия из файла имеет приоритет:

1. существующая статья удаляется;
2. вместе с ней удаляется всё её текущее поддерево;
3. статья из JSON создаётся заново с новым ID;
4. возвращаются только потомки, которые отдельно присутствуют в JSON.

Это не слияние полей. Нельзя оставить старый `body`, добавив к нему новые `routeParams`.

### Позиция

- У статьи, чей родитель тоже импортируется, `npp` берётся из файла.
- Верхняя статья присоединяется к выбранному родителю последней: ей назначается текущий
  максимальный `npp` этого родителя плюс один.

Соседи не перенумеровываются. Импорт не исправляет повторяющиеся позиции и не пересчитывает
`directory` у существующих родителей.

### Пример

На сайте есть:

```text
root
└── catalog
    ├── old-a
    └── old-b
```

Файл содержит новую `catalog` и только `new-a`. Результат:

```text
root
└── catalog
    └── new-a
```

`old-a` и `old-b` исчезнут вместе со старой `catalog`. Чтобы сохранить статью, включите её в
файл либо перенесите её в безопасное место до импорта.

## Полный импорт

Проверка full-файла не требует наличия системных статей `index` и `error404`. Если их нет в
JSON, текущие версии будут удалены вместе с остальным деревом. Поэтому экспорт обычного
поддерева может пройти техническую проверку, но обычно не подходит для полного импорта.

Полный режим:

1. удаляет из `articles` все строки, кроме `id = 1`;
2. импортирует файл;
3. обновляет существующую запись `root`, если она присутствует в JSON;
4. присоединяет верхние статьи к `root`;
5. после коммита пересоздаёт рабочие Blade и PHP-файлы.

### Особое поведение `root`

Корень не удаляется и не переименовывается:

- `id` остаётся `1`;
- `name` остаётся `root`;
- `parentId` остаётся `0`;
- `npp` из файла игнорируется;
- переданные рабочие поля обновляются;
- отсутствующие поля сохраняют прежнее значение.

Если `root` в файле отсутствует, существующие поля корня полностью сохраняются, а все остальные
статьи сайта всё равно удаляются.

### Полный отчёт намеренно пуст

Для корректного файла полный режим не перечисляет удаляемые статьи. Это не означает, что сайт
ничего не теряет: режим по определению удаляет всё не-root дерево.

## Два нажатия

Обычный сценарий:

1. выберите файл;
2. выберите `Частичный` или `Полный`;
3. нажмите «Проверить»;
4. прочитайте весь отчёт;
5. нажмите «Импорт»;
6. подтвердите изменение сайта.

Сервер повторяет планирование перед записью. Смена режима после проверки сбрасывает её, и
кнопка «Импорт» закрывается до новой проверки.

Также не редактируйте статьи в другом окне между двумя нажатиями. Сервер построит новый план при
`run`, и фактический отчёт может отличаться от прочитанного.

## Граница транзакции

Только изменения таблицы `articles` выполняются в одной DB transaction, а рабочие
Blade/PHP-файлы генерируются после commit.

Следствия:

- ошибка записи статей откатывает изменения `articles`;
- ошибка генерации файлов не откатывает базу;
- генерация не останавливается на сбойной статье: остальные пишутся, а сбойные перечислены в
  отчёте строкой «файлы статьи не записаны» — такую статью достаточно поправить и сохранить,
  импорт повторять не нужно.

После любой ошибки во время второго прохода откройте список статей и фактические страницы. Не
повторяйте полный импорт вслепую: сначала определите, на каком этапе произошёл отказ.

## Что откат через экспорт `root` не возвращает

Экспорт `root`, импортированный обратно в режиме «полный», не восстанавливает:

- прежние числовые `id` статей, кроме `root = 1`;
- `created_at` и `updated_at`;
- архив `magicPro_article_versions` — старые версии остаются в своей таблице, но к статьям с
  новыми `id` не привязаны;
- cron-задачи, ленты, почту, пользователей и конфигурацию;
- статьи, которые из-за повреждённого `parentId` недоступны обходом от `root`.

Точное прошлое состояние всей базы — это ночной дамп, а не экспорт.

Cron-задачи хранят имя статьи, а не её ID. После полного импорта они останутся, но задача будет
работать только если статья с нужным именем и контроллером снова существует.

## Проверка результата

После частичного или полного импорта:

1. обновите редактор и проверьте фактическое дерево;
2. проверьте `root`, `index` и `error404`;
3. убедитесь, что позиции соседей и признаки каталогов выглядят правильно;
4. откройте публичные маршруты импортированных статей;
5. отдельно проверьте статьи с `useController = true`;
6. проверьте Blade-компоненты и статьи без публичного маршрута, на которые ссылаются другие
   страницы;
7. проверьте cron-задачи, использующие импортированные контроллеры;
8. при любой несогласованности остановите дальнейшие изменения и сохраните текущие данные для
   диагностики.

## Ограничения объёма

MagicPro не задаёт собственный предел размера файла или количества статей. Фактические пределы
задают браузер, web server, PHP, request body, память, timeout и база.

Файл целиком хранится в памяти браузера, целиком отправляется в JSON request и целиком
декодируется на сервере. Глубокая цепочка родителей планируется повторными проходами по списку,
а импорт и генерация выполняют много запросов/файловых операций. Для большого дерева сначала
проверяйте копию окружения и контролируйте время выполнения.

## Краткий безопасный сценарий

1. Экспортируйте нужное поддерево из источника.
2. Просмотрите JSON, особенно PHP/Blade и `routeParams`.
3. На целевом сайте сделайте экспорт `root` и сохраните файл у себя.
4. Выберите режим и файл.
5. Нажмите «Проверить» и прочтите отчёт о потерях.
6. Выполните импорт с осознанным подтверждением.
7. Проверьте дерево, страницы, контроллеры и cron.
8. Храните экспорт `root` до окончания проверки: откат — его полный импорт.
