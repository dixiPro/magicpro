# ТЗ. Модуль «Ленты» (Feeds). Список команд API

> Одно АПИ, одно действие. Если АПИ создает пустую запись, значит создает. Если обновляет значит обновляет.

## Группы используется в Админке

| Команда       | Что делает                                       | Параметры        |
| ------------- | ------------------------------------------------ | ---------------- |
| `groupsList`  | Список групп лент                                | —                |
| `groupCreate` | Создаёт пустую группу                            | —                |
| `groupSave`   | Переименовывает группу                           | `id`, `title`    |
| `groupMove`   | Меняет порядок групп                             | `id`, `position` |
| `groupDelete` | Удаляет группу. Группа по умолчанию не удаляется | `id`             |

## Список лент используется в Админке

| Команда      | Что делает                                                        | Параметры                        |
| ------------ | ----------------------------------------------------------------- | -------------------------------- |
| `feedsList`  | Плоский список лент: `id`, `code`, `title`, группа, число записей | `groupId` (необязательно)        |
| `feedGet`    | Лента целиком вместе со схемой                                    | `id` или `code`                  |
| `feedCreate` | Создаёт пустую ленту                                              | `groupId`                        |
| `feedSave`   | Меняет `code`, `title`, группу. Схему не трогает                  | `id`, `code`, `title`, `groupId` |
| `feedMove`   | Позиция ленты внутри группы или перенос в другую группу           | `id`, `groupId`, `position`      |
| `feedClear`  | Очистка: удаляет записи, описание ленты остаётся                  | `id`                             |
| `feedDelete` | Удаляет записи и, если не осталось ни одной, само описание        | `id`                             |

`feedClear` и `feedDelete` возвращают `true` или `false`. `false` означает, что часть
записей держат ссылки и лента осталась. Что именно осталось, админка читает отдельно —
командой, которая для этого предназначена.

## Схема ленты

| Команда      | Что делает                                   | Параметры          |
| ------------ | -------------------------------------------- | ------------------ |
| `schemaGet`  | Схема ленты                                  | `feedId`           |
| `schemaSave` | Сохраняет схему целиком, со всеми проверками | `feedId`, `schema` |

Схема сохраняется целиком, а не по одному полю: проверки «колонка занята ровно один раз» и
«`code` уникален» имеют смысл только на всём наборе.

## Записи, таблица `feed_items`

| Команда       | Что делает                                                | Параметры                                                     |
| ------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| `itemsList`   | Список записей ленты с фильтром, сортировкой и пагинацией | `feedId`, `filter`, `orderBy`, `direction`, `page`, `perPage` |
| `itemGet`     | Одна запись со всеми полями                               | `id`                                                          |
| `itemCreate`  | Создает новую запись                                      | `feedId`                                                      |
| `itemSave`    | Обновляет запись целиком                                  | `id`, `fields`, `visible`                                     |
| `itemMove`    | Позиция записи внутри ленты                               | `id`, `position`                                              |
| `itemDelete`  | Удаляет одну запись                                       | `id`                                                          |
| `itemLinks`   | Кто ссылается на запись — для рекурсивного окна удаления  | `id`                                                          |
| `itemsLookup` | Поиск записей ленты для выпадающего списка поля `link`    | `feedId`, `column`, `search`, `limit`                         |

`fields` в `itemSave` — логические имена полей. Запись уходит целиком, а не изменившимися
полями: оператор один, экономить не на чем. `visible` идёт отдельным параметром — это
системная колонка, а не поле ленты. `position` через `itemSave` не меняется, для этого
`itemMove`.

`itemDelete` возвращает `true` или `false`. `false` означает, что на запись ссылаются;
список держащих читается отдельно, командой `itemLinks`.

`column` в `itemsLookup` — физическая колонка целевой ленты, значение которой показывается
в списке. Она же лежит в `display_code` поля связи.

`filter` в `itemsList` — список условий «поле, операция, значение»:

```json
"filter": [
  { "field": "title", "op": "like", "value": "сыр" },
  { "field": "price", "op": "=",    "value": 990 }
]
```

Операции две: `like` — поиск подстроки, `%значение%`, и `=` — точное совпадение. Условия
складываются через `AND`, диапазонов и `OR` нет. `field` — логическое имя поля ленты; поля
из `__data` в фильтр не принимаются.

## Медиа

| Команда       | Что делает                                             | Параметры          |
| ------------- | ------------------------------------------------------ | ------------------ |
| `imageUpload` | Кладёт файл в поле записи, пишет метаданные в `__data` | `id`, `code`, файл |
| `imageDelete` | Удаляет файл поля и его метаданные                     | `id`, `code`       |

Одно поле — одно изображение, старый файл затирается. Файл приходит обычным
`multipart/form-data`, остальные команды — JSON.

## Реализация

У модуля свой абстрактный класс — `AbstractFeedApi`, и команды живут в его наследнике
`API_Feeds`.

Общий `MagicProSrc\Api\AbstractApi` не наследуется намеренно. Устроены они одинаково и,
скорее всего, годами будут совпадать буква в букву, но однажды понадобится поправить
диспетчер под ленты — и это не должно задевать авторизацию и почту. Так же в своё время
поступила почта: у неё свой `AbstractMailApi`. Плата — десяток продублированных строк, она
дешевле связанности.

Как это устроено:

- **`$map`** — таблица «команда → метод». Команды нет в карте или метод не реализован —
  исключение.
- **`run($command, $params)`** — вызывает метод, параметры передаются одним плоским
  массивом, туда же кладётся сам `command`. Исключений наружу не бросает: любая ошибка
  превращается в ответ со `status = false`.
- **`runOrFail($command, $params)`** — для внутренних вызовов, которые обязаны пройти:
  ошибка бросается дальше, а возвращаются только `data`.
- **`handle(Request)`** — точка входа для HTTP: берёт `command` из тела запроса, остальное
  считает параметрами, отдаёт `JsonResponse`.

Ответ всегда одной формы:

```json
{ "status": true, "errorMsg": "", "data": {}, "request": {} }
```

`request` — то, с чем команду позвали; удобно при разборе логов.

Форма ответа общая для всех API MagicPro — админка разбирает их одинаково, независимо от
того, чей это класс.

## Ошибки

Отдельных кодов нет. Любая неудачная проверка — исключение с человеческим текстом: какое
поле, что не так, какое значение пришло. `AbstractApi` кладёт его в `errorMsg`.

Исключение — ошибки валидации записи: они возвращаются разложенными по полям, иначе форма в
админке не сможет подсветить нужное поле.
