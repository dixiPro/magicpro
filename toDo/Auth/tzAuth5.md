# ТЗ v5: регистрация и вход на сайте

Пятая версия. Основа — `tzAuth4.md` с ответами владельца. Главное отличие от v4:
письмо регистрации уходит **без пароля**, пароль человек вводит на странице по
ссылке из письма. Чем меньше напрягаем пользователя, тем лучше.

## Сценарии

**Email не зарегистрирован.** Ввёл email → «Зарегистрировать?» → ушло письмо
`authLetter` со ссылкой → переход по ссылке на `authUrl` → ввод пароля →
регистрация, вход, письмо `postLetter`, переход на `postUrl`.

**Email зарегистрирован.** Ввёл email → ввёл пароль → вход, переход на `postUrl`.

**Забыл пароль.** «Забыли пароль?» → ушло письмо `resetPasswordLetter` со
ссылкой → переход по ссылке на `authUrl` → ввод нового пароля → смена пароля,
вход, переход на `postUrl`.

Перед любым действием с email — reCAPTCHA: сначала проверяем, что это человек.

## Принцип: без записей в базе

До перехода по ссылке в базе ничего не создаётся. Всё нужное лежит в самом
токене, зашифрованное ключом приложения.

Почему: человек отправил письмо дважды, получил оба и нажал на первое. С таблицей
заявок первое письмо было бы уже недействительным. Здесь любой не просроченный
токен работает, клиента не теряем. Хранить нечего.

Токены:

| Токен              | Что внутри              | Где живёт                      |
| ------------------ | ----------------------- | ------------------------------ |
| `emailToken`       | email, время создания   | в форме между шагами           |
| токен регистрации  | email, `postUrl`, время | в ссылке `authLetter`          |
| токен смены пароля | email, `postUrl`, время | в ссылке `resetPasswordLetter` |

Срок жизни каждого — в настройках (см. ниже). `postUrl` в токене — только путь
этого сайта, как сейчас `back` в `API_Auth`.

**Второй переход по ссылке регистрации** — пользователь уже создан первым
переходом: просто тихо входим.

## Настройки

Страница «Пользователи» в админке:

| Ключ                     | Что это                                                                 |
| ------------------------ | ----------------------------------------------------------------------- |
| `authUrl`                | страница регистрации и входа — одна на сайт; ссылки из писем ведут сюда |
| `postUrl`                | куда вести после регистрации или входа                                  |
| `authLetter`             | блейд письма подтверждения email                                        |
| `postLetter`             | блейд письма после регистрации                                          |
| `resetPasswordLetter`    | блейд письма смены пароля                                               |
| срок `emailToken`        | сколько живёт токен формы                                               |
| срок токена регистрации  | сколько живёт ссылка из `authLetter`                                    |
| срок токена смены пароля | сколько живёт ссылка из `resetPasswordLetter`                           |

Нет статьи `authUrl` — ссылки из писем никуда не ведут. Это обязанность сайта.

## API

### Два API вместо одного

- **Новое публичное API** — шесть команд ниже. Доступно по публичному
  HTTP-адресу для формы на странице и через `run()` из блейда.
- **Всё остальное** из нынешнего `API_Auth` (список пользователей, правка,
  смена пароля админом, «войти как», удаление, `currentUser`, `logout` и т. п.)
  уносится в другое API — не публичное по HTTP, но вызываемое из блейда
  через `run()`.
- Удачные решения нынешнего `API_Auth` переносятся в новое, из старого удаляются.

Ответ — как в остальных API пакета: `status`, `errorMsg`, `data`, `request`.
При ошибке в `data` — `errorCode`.

### Команды публичного API

| Команда                   | Параметры                          | В `data` при успехе         |
| ------------------------- | ---------------------------------- | --------------------------- |
| `checkEmail`              | `email`, `gToken`                  | `emailToken`, `emailActive` |
| `sendRegisterEmail`       | `emailToken`, `gToken`, `postUrl?` | —                           |
| `auth`                    | `emailToken`, `password`           | `postUrl`                   |
| `sendChangePasswordEmail` | `emailToken`, `gToken`, `postUrl?` | —                           |
| `registerUserByToken`     | `token`, `password`                | `postUrl`                   |
| `changePassword`          | `token`, `password`                | `postUrl`                   |

- **`checkEmail`** — reCAPTCHA, затем валидность email и есть ли он в базе.
  `emailActive` — есть ли пользователь.
- **`sendRegisterEmail`** — reCAPTCHA; письмо `authLetter`, в нём
  `$authLinkUrl` = `authUrl` + `/mode/regByToken/token/<token>`. Повтор на тот же
  адрес — не чаще раза в 10 минут.
- **`auth`** — вход по email из `emailToken` и паролю; 5 неудач подряд — минута
  паузы.
- **`sendChangePasswordEmail`** — reCAPTCHA; письмо `resetPasswordLetter`, в нём
  `$authResetPasswordUrl` = `authUrl` + `/mode/changePassword/token/<token>`.
  Повтор — не чаще раза в 10 минут.
- **`registerUserByToken`** — токен жив: пользователя нет — создать с этим
  паролем, email подтверждён, войти, отправить `postLetter`; пользователь уже
  есть — тихо войти.
- **`changePassword`** — токен жив: сменить пароль, войти.

Пароль — не короче 8 символов.

### `errorCode` — предложение

| Команда                   | Коды                                                                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `checkEmail`              | `captcha_failed`, `captcha_not_configured`, `bad_email`                                                                          |
| `sendRegisterEmail`       | `captcha_failed`, `token_invalid`, `token_expired`, `settings_missing`, `letter_already_sent`, `letter_failed`                   |
| `auth`                    | `token_invalid`, `token_expired`, `user_not_found`, `wrong_password`, `too_many_attempts`                                        |
| `sendChangePasswordEmail` | `captcha_failed`, `token_invalid`, `token_expired`, `user_not_found`, `settings_missing`, `letter_already_sent`, `letter_failed` |
| `registerUserByToken`     | `token_invalid`, `token_expired`, `bad_password`, `registration_failed`                                                          |
| `changePassword`          | `token_invalid`, `token_expired`, `user_not_found`, `bad_password`                                                               |

`settings_missing` — не заданы `authUrl` или блейд письма.

## Страница `authUrl`

Одна статья сайта, режим — параметрами адреса:

| Адрес                                     | Режим                                                           |
| ----------------------------------------- | --------------------------------------------------------------- |
| `/auth`                                   | форма: email → пароль или «Зарегистрировать?», «Забыли пароль?» |
| `/auth/mode/regByToken/token/<token>`     | поле пароля → `registerUserByToken` → переход на `postUrl`      |
| `/auth/mode/changePassword/token/<token>` | поле нового пароля → `changePassword` → переход на `postUrl`    |

Маршрут статьи: `getEnable: true`, `keysArr: ["mode", "token"]`,
`bindKeys: false` — тогда голый `/auth` тоже открывается.

Фронт — Alpine.js.

## Письма

Блейды писем — статьи сайта, их имена в настройках. Переменные подставляет API:

| Письмо                | Переменные                    |
| --------------------- | ----------------------------- |
| `authLetter`          | `$authLinkUrl`                |
| `postLetter`          | `$userEmail`, `$userPassword` |
| `resetPasswordLetter` | `$authResetPasswordUrl`       |

`$userPassword` передаётся, но выводить его сайт не обязан: можно написать
«пароль, указанный при регистрации».

Примеры — `authLetter.md`.
