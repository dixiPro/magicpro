# ТЗ v2: регистрация и вход на сайте

Вторая версия. Первая — `tzAuth.md` (разбор формы на Alpine из другого
проекта); её вопросы про Alpine, «забыли пароль» и `/loginRedirect` остаются на
потом.

## Решено

- Алгоритм регистрации и входа живёт в пакете, в `API_Auth`. Не в хелперах:
  хелперы только передают работу модулям.
- На сайте остаётся только то, что про вид: форма, текст письма, тексты
  страниц, куда вести после входа. Дистрибутив чистый — эти статьи сайт
  заводит сам.
- Основа — то, что уже работает на статьях раздела `Auth` (id 239): регистрация
  письмом со ссылкой, вход тем же шагом, если пользователь уже есть.

## Как сейчас

Раздел `Auth` на тестовом сайте:

| Статья | Роль | Что делает |
| --- | --- | --- |
| `Auth` | страница, `postEnable` | форма; шаг 1 зовёт `API_Auth::run('sendAuthEmail')` |
| `authForm` | include | email, пароль (кнопка активна от 8 символов), показать пароль |
| `google_capture` | компонент | reCAPTCHA v3: берёт токен, сам отправляет форму |
| `register_body` | блейд письма | ссылка `url($authPage . '/' . $key)` |
| `authNewUser` | страница `/authNewUser/<key>` | зовёт `processNewUser` |

Беда в том, что страница разбирает результат сама: API отвечает только
`status` и текстом `errorMsg`, по тексту не понять, что показать человеку.
`authNewUser` ждёт `data['situation']`, которого API не отдаёт, — поэтому её
надписи никогда не показываются.

Найдено при разборе:

1. **Подтверждение email обходится.** `sendAuthEmail` возвращает в ответе HTML
   письма со ссылкой-ключом, статья `Auth` выводит ответ `dump`-ом. Вводишь
   чужой email — видишь ссылку на экране — регистрируешь чужой адрес.
2. `decryptEmailPass` превращает «ссылка устарела» в общее «Auth key invalid»:
   просроченную ссылку не отличить от битой.

## Что сделать в пакете

### `sendAuthEmail`

Параметры — как сейчас: `token`, `email`, `password`, `blade`, `authPage`,
`back`, `subject`.

**HTML письма в ответе больше нет.** Ни при каком исходе.

Ответ всегда несёт `data.situation` — и при успехе, и при ошибке:

| `status` | `situation` | Когда |
| --- | --- | --- |
| `true` | `logged_in` | пользователь уже был, пароль верный — вошёл; в `data.back` — адрес возврата |
| `true` | `letter_sent` | пользователя не было — ушло письмо со ссылкой |
| `false` | `param_missing` | не передан `blade` или `authPage` |
| `false` | `captcha_failed` | нет токена, Google не ответил или не пропустил |
| `false` | `captcha_not_configured` | не задан `RECAPTCHA_SECRET_KEY` |
| `false` | `bad_email` | email не прошёл проверку (формат, DNS) |
| `false` | `bad_password` | пароль короче 8 символов |
| `false` | `wrong_password` | пользователь есть, пароль неверный |
| `false` | `too_many_attempts` | 5 неверных паролей подряд — минута паузы |
| `false` | `letter_already_sent` | письмо на этот адрес уже уходило меньше 10 минут назад |
| `false` | `letter_failed` | блейд письма не отрисовался или письмо не ушло |

### `processNewUser`

Параметр — `key`.

| `status` | `situation` | Когда |
| --- | --- | --- |
| `true` | `user_registered` | пользователя не было — зарегистрирован, вошёл, email подтверждён |
| `true` | `user_auth` | пользователь уже был — вошёл |
| `false` | `already_logged_in` | посетитель уже вошёл на сайт |
| `false` | `link_invalid` | ключ битый, не расшифровывается |
| `false` | `link_expired` | ключу больше 24 часов |
| `false` | `wrong_password` | пароль сменили после письма |
| `false` | `too_many_attempts` | 5 неверных паролей подряд |
| `false` | `registration_failed` | не удалось создать пользователя |

При успехе в `data.back` — адрес возврата (только путь своего сайта, как сейчас).

`errorMsg` остаётся — для лога и отладки. Решает страница по `situation`.

## Как будет выглядеть статья

```php
$res = API_Auth::run('sendAuthEmail', [
    'token'    => $Post['g-recaptcha-response'] ?? '',
    'email'    => $Post['email'] ?? '',
    'password' => $Post['password'] ?? '',
    'blade'    => 'magic::register_body',
    'authPage' => '/authNewUser',
    'back'     => '/',
    'subject'  => 'Регистрация на сайте ' . request()->getHost(),
]);

$situation = $res['data']['situation'] ?? '';
```

Дальше — выбрать текст по `situation`. Разбора `errorMsg` в статье нет.
