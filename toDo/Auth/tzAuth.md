# ТЗ: вход и регистрация на сайте

Черновик по заметкам `toDo/Auth/authAlpine.html` и `toDo/Auth/alpineauth.js` —
форма входа из другого проекта (шаблон Twig, Alpine.js, Bootstrap 4).
Задача — такая же форма для сайтов на MagicPro.

## 1. Что есть сейчас в MagicPro

Пользователи сайта — таблица `users` Laravel, guard `web`. Работа идёт через
`API_Auth::run('команда', [...])` из блейда или контроллера статьи
(`docs/ru/users/use.md`):

| Команда                                                 | Что делает                                                        |
| ------------------------------------------------------- | ----------------------------------------------------------------- |
| `currentUser`                                           | кто вошёл                                                         |
| `authEmailPassword`                                     | вход по email и паролю; 5 неудач — минута паузы                   |
| `logout`                                                | выход                                                             |
| `userInfo`                                              | есть ли пользователь с таким email                                |
| `checkGoogleCapture`                                    | проверка токена reCAPTCHA                                         |
| `sendAuthEmail`                                         | есть пользователь — вход; нет — письмо со ссылкой регистрации     |
| `processNewUser`                                        | переход по ссылке из письма: регистрация, вход, email подтверждён |
| `createUser`, `editUser`, `chagePassword`, `deleteUser` | служебные                                                         |

Готовых страниц входа нет, публичных HTTP-адресов для формы нет: всё вызывается
на сервере из статей.

## 2. Как работает форма из заметок

Один блок `#login-app`, экраны переключаются без перезагрузки:

| Экран             | Что видит человек                                | Что уходит на сервер                                             | Ответ                                          |
| ----------------- | ------------------------------------------------ | ---------------------------------------------------------------- | ---------------------------------------------- |
| `email`           | поле email, «Войти»                              | проверка на робота + email (`/apiAuthGoogleRecapture`)           | `emailToken`, `userExist`; или вопрос человеку |
| —                 | вопрос «антиробот», если reCAPTCHA не пропустила | ответ (`/apiAuthUserRecapture`)                                  | то же, пока не пропустит                       |
| `password`        | пароль, «Войти», «Забыли пароль?»                | email + пароль (`/api/sessauth/auth`)                            | вошёл / неверный пароль                        |
| `register`        | пароль, «Зарегистрироваться»                     | `emailToken` + пароль + `redirect` (`/apiAuthSendRegisterEmail`) | `passToken`, уходит письмо                     |
| `code`            | «письмо отправлено, проверьте ящик»              | —                                                                | —                                              |
| `forgot-password` | «Выслать пароль», повтор через 60 с              | `emailToken` + `redirect` (`/apiAuthRequestNewPass`)             | письмо ушло                                    |

Приёмы из заметок, которые стоит сохранить:

- **Сначала email, потом пароль.** Сервер сам говорит, вход это или регистрация;
  человек не выбирает между двумя формами.
- **`emailToken`** — выдаётся после проверки на робота и привязывает дальнейшие
  шаги к проверенному email.
- **Сохранение пароля браузером.** После удачного входа форма невидимо
  отправляется обычным POST на `/loginRedirect` с `username`, `password`,
  `redirect` — только так менеджер паролей браузера предлагает запомнить пароль;
  сервер редиректит на `redirect`.
- **Два уровня антиробота.** reCAPTCHA v3 невидимо; не пропустила — вопрос
  человеку, пока не ответит.
- Ошибки — плашками внутри блока, сами исчезают через 6 секунд.

## 3. Сопоставление: что есть, чего нет

| Шаг формы                                     | В MagicPro                                                |
| --------------------------------------------- | --------------------------------------------------------- |
| проверка на робота reCAPTCHA                  | есть: `checkGoogleCapture`                                |
| вопрос человеку, если reCAPTCHA не пропустила | нет                                                       |
| «email есть или нет» + `emailToken`           | частично: `userInfo` отвечает, токена нет                 |
| вход по паролю                                | есть: `authEmailPassword`                                 |
| регистрация письмом                           | есть: `sendAuthEmail` + `processNewUser` (ссылка, не код) |
| «забыли пароль»                               | нет                                                       |
| `/loginRedirect` для менеджера паролей        | нет                                                       |
| публичные адреса, куда стучится форма         | нет                                                       |
| выход                                         | есть: `logout`                                            |

## Вопросы

1. **Где живут адреса формы?** Маршруты пакета (как `/a_dmin/...`, но
   публичные) или статьи сайта с `postEnable`, контроллер которых зовёт
   `API_Auth` и отдаёт JSON?
2. **Где живёт сама форма?** Дистрибутив — три статьи, значит форма —
   статьи сайта. Отдавать её как пример (файл импорта, раздел доки) или только
   описанием?
3. **Регистрация: ссылка или код?** В MagicPro — ссылка из письма
   (`processNewUser`). В заметках экран `code` только говорит «проверьте ящик»,
   поле ввода кода в шаблоне не используется. Оставляем ссылку?
4. **«Забыли пароль»:** в заметках — «выслать пароль». Высылать новый пароль
   письмом или ссылку на смену пароля?
5. **Вопрос человеку (второй уровень антиробота)** — делаем? Откуда берутся
   вопросы и ответы?
6. **`emailToken`:** нужен ли он у нас, или шаги достаточно защищает reCAPTCHA
   и ограничение попыток?
7. **Вёрстка:** в заметках Bootstrap 4 (`mr-2`, `sr-only`,
   `input-group-append`, `close`). Переводим на Bootstrap 5?
8. **Alpine.js на страницах сайта.** Пакет требует Livewire 3, а он приносит
   Alpine с собой, если на странице есть `@livewireScripts`. Берём Alpine
   оттуда, или форма подключает его сама? (`alpinejs` в `package.json` пакета —
   это сборка админки, на сайт не попадает.)
