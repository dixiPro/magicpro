## Картинки: откуда бы ни пришли

Картинка на сайте MagicPro может лежать где угодно: её загрузили через файловый
менеджер админки, она пришла полем записи ленты, её положил чей-то код, её
принёс другой пакет со своей структурой данных. Угадывать заранее не нужно.

**Правило одно, для любого источника:**

1. получить **абсолютный путь файла на диске**;
2. отдать его `MproHelper::imageReduceX()` или `MproHelper::imageReduceY()`;
3. проверить ответ;
4. вывести `path`, `width` и `height` **из ответа**.

Всё остальное в этом файле — как сделать шаг первый для разных источников и
как не наступить на грабли на остальных. Полная справка по хелперам, форматам и
кешу — `image/use.md`.

#### Что делают хелперы

```php
MproHelper::imageReduceX(string $file, int $width,  ?string $format = null, ?int $quality = null): array
MproHelper::imageReduceY(string $file, int $height, ?string $format = null, ?int $quality = null): array
```

- `imageReduceX` — производная заданной **ширины**, высота по пропорции.
- `imageReduceY` — производная заданной **высоты**, ширина по пропорции.

Исходник не меняется. Производная делается при первом обращении, дальше
отдаётся из кеша. Обрезки нет, пропорции сохраняются.

Из ответа на странице нужны четыре ключа:

| Ключ       | Что                                                                           |
| ---------- | ----------------------------------------------------------------------------- |
| `path`     | url производной, например `/storage/magic/images/…`; при ошибке пустая строка |
| `width`    | настоящая ширина результата                                                   |
| `height`   | настоящая высота результата                                                   |
| `errorMsg` | пустая строка, если всё хорошо, иначе причина                                 |

Остальные ключи (`size`, `ms`, `cmd`…) — для отладки, см. `image/use.md`.

#### Ширина или высота

**`imageReduceX` — почти всегда.** Место на странице обычно задано шириной:
колонка, карточка, слайд, текст статьи.

**`imageReduceY` — когда задана высота.** Строка логотипов одной высоты,
превью в ленте фиксированной высоты, баннер, который должен лечь в полосу.

#### Шаг первый: откуда взять путь

Хелперу нужен **путь в файловой системе**, а не url. Url вида
`/storage/magicFeed/11/photo.jpg` он не найдёт и ответит `not an image`.

| Откуда картинка                         | Что у тебя в руках        | Путь для хелпера                                              |
| --------------------------------------- | ------------------------- | ------------------------------------------------------------- |
| Файловый менеджер админки               | url `/design/…`           | `public_path($url)`                                           |
| Поле-картинка записи ленты              | массив, url в `['path']`  | `public_path($item->photo['path'])`                           |
| Путь написан в блейде руками            | `/design/images/logo.png` | `public_path('design/images/logo.png')`                       |
| Файл, который положил свой код          | путь от `storage`         | `storage_path('app/…')`                                       |
| Любой файл на сервере, даже вне проекта | абсолютный путь           | как есть                                                      |
| Данные другого пакета                   | что угодно                | найти в данных url или путь и привести к одному из видов выше |
| Внешний адрес `https://…`               | url чужого сайта          | **никак**, см. ниже                                           |

Файловый менеджер кладёт загрузки в `public/` плюс `PUBLIC_UPLOAD_DIR` из
настроек — по умолчанию это `/design`, поэтому url загруженного файла
начинается с `/design/`. Если на сайте настройка другая, начало будет другим, а
правило то же: url от корня сайта → `public_path()`.

Как понять, что в руках: **начинается с `/` и открывается в браузере — это url**,
его в `public_path()`. Начинается с корня файловой системы (`/home/…`,
`/var/www/…`) — уже путь, отдавай как есть.

###### Внешний адрес

Ресайзер работает только с файлами на этом сервере. `https://чужой-сайт/pic.jpg`
он не скачивает. Два пути:

#### Примеры

###### Файл из файлового менеджера

Оператор загрузил баннер в `/design/banners/` и дал ссылку:

```blade
@php
    $banner = MproHelper::imageReduceX(public_path('design/banners/spring.jpg'), 1200);
@endphp

@if ($banner['path'] !== '')
    <img src="{{ $banner['path'] }}" width="{{ $banner['width'] }}"
         height="{{ $banner['height'] }}" alt="Proleće" class="img-fluid">
@endif
```

###### Поле записи ленты

Самый частый случай.

```blade
@php
    $img = MproHelper::imageReduceX(public_path($item->photo['path'] ?? ''), 600);
@endphp

@if ($img['path'] !== '')
    <img
        src="{{ $img['path'] }}"
        width="{{ $img['width'] }}"
        height="{{ $img['height'] }}"
        alt="{{ $item->photo['alt'] ?? '' }}"
        loading="lazy"
    >
@endif
```

Поля может не оказаться: `?? ''` превращает это в обычную ошибку `not an image`,
и `@if` просто ничего не выведет, вместо того чтобы уронить страницу.

###### Логотипы одной высоты

```blade
<div class="d-flex flex-wrap align-items-center gap-4">
    @foreach ($partners as $partner)
        @php
            $logo = MproHelper::imageReduceY(public_path($partner->logo['path'] ?? ''), 60);
        @endphp
        @if ($logo['path'] !== '')
            <img src="{{ $logo['path'] }}" width="{{ $logo['width'] }}"
                 height="{{ $logo['height'] }}" alt="{{ $partner->title }}">
        @endif
    @endforeach
</div>
```

Ширины у логотипов разные, высота одна — ровно то, что делает `imageReduceY`.

###### Чёткость на телефоне: srcset

На экране с плотностью 2x картинка шириной 400 css-пикселей просит 800
настоящих. Делаем две производные и отдаём браузеру выбор:

```blade
@php
    $src = public_path($item->photo['path'] ?? '');
    $one = MproHelper::imageReduceX($src, 400);
    $two = MproHelper::imageReduceX($src, 800);
@endphp

@if ($one['path'] !== '')
    <img
        src="{{ $one['path'] }}"
        @if ($two['path'] !== '')
            srcset="{{ $one['path'] }} {{ $one['width'] }}w, {{ $two['path'] }} {{ $two['width'] }}w"
            sizes="(max-width: 576px) 100vw, 400px"
        @endif
        width="{{ $one['width'] }}"
        height="{{ $one['height'] }}"
        alt="{{ $item->photo['alt'] ?? '' }}"
        loading="lazy"
    >
@endif
```

`sizes` — обещание браузеру, **какой ширины будет место** на странице. Браузер
выбирает файл до вёрстки и проверить обещание не может: если в `sizes` написано
400px, а картинка на самом деле во весь экран, приедет мелкий файл и будет
мылить.

В `srcset` — ширины **из ответа**, не запрошенные: `MAX_RESIZE` мог срезать.

###### Форматы: avif, webp и jpg для старых браузеров

```blade
@php
    $src  = public_path($item->photo['path'] ?? '');
    $avif = MproHelper::imageReduceX($src, 800, 'avif');
    $webp = MproHelper::imageReduceX($src, 800, 'webp');
    $jpg  = MproHelper::imageReduceX($src, 800, 'jpg');
@endphp

@if ($jpg['path'] !== '')
    <picture>
        @if ($avif['path'] !== '')
            <source srcset="{{ $avif['path'] }}" type="image/avif">
        @endif
        @if ($webp['path'] !== '')
            <source srcset="{{ $webp['path'] }}" type="image/webp">
        @endif
        <img src="{{ $jpg['path'] }}" width="{{ $jpg['width'] }}"
             height="{{ $jpg['height'] }}" alt="{{ $item->photo['alt'] ?? '' }}" loading="lazy">
    </picture>
@endif
```

Каждый `<source>` — под своим `@if`. `<source>` с пустым адресом браузер не
пропускает, а спотыкается на нём, и картинки не будет вовсе.

Такая разметка повторяется на многих страницах — это повод завести на сайте
свой компонент и держать её в одном месте.

###### Фон блока

```blade
@php
    $bg = MproHelper::imageReduceX(public_path('design/hero/main.jpg'), 1920);
@endphp

<section class="py-5 text-white"
    @if ($bg['path'] !== '') style="background: url('{{ $bg['path'] }}') center / cover" @endif>
    …
</section>
```

###### Письмо и соцсети: только jpg

Почтовые клиенты и превью в соцсетях avif и webp понимают не везде. Там, где
картинка уходит **за пределы сайта**, формат указывается явно:

```php
// og:image для превью ссылки
$og = MproHelper::imageReduceX(public_path($item->photo['path'] ?? ''), 1200, 'jpg');

// картинка в письме: нужен полный адрес, а не путь от корня сайта
$mail = MproHelper::imageReduceX(public_path($item->photo['path'] ?? ''), 600, 'jpg', 80);
$src  = $mail['path'] !== '' ? url($mail['path']) : '';
```

###### Файл, который положил свой код

```php
$img = MproHelper::imageReduceX(storage_path('app/public/reports/chart.png'), 900);
```

#### Ошибка и заглушка

При ошибке `path` пустой, `width` и `height` — ноль, причина — в `errorMsg`:

- `not an image: …` — файла нет или это не картинка. Чаще всего — url отдан
  вместо пути;
- `unknown format: …` — формат не из списка (`avif`, `webp`, `iwebp`, `jpg`,
  `png`) или не в нижнем регистре;
- `busy: …` — ту же производную уже кодирует другой запрос, ожидание дольше пяти
  секунд;
- текст внешней утилиты — кодировщик не справился.

Что показать вместо картинки, решает блейд. Иногда правильно — ничего. Иногда —
заглушка, чтобы вёрстка не поехала:

```blade
@if ($img['path'] !== '')
    <img src="{{ $img['path'] }}" width="{{ $img['width'] }}" height="{{ $img['height'] }}" alt="…">
@else
    <div class="ratio ratio-1x1 bg-light rounded"></div>
@endif
```

#### Грабли

**Url вместо пути.** Самая частая ошибка: хелпер получил `/storage/…` и ответил
`not an image`. Всё, что открывается в браузере, — через `public_path()`.

**Один файл — один вид пути.** `public_path('storage/magicFeed/…')` и
`storage_path('app/public/magicFeed/…')` — это один файл, но для кеша два
разных исходника: производные сделаются дважды и лягут в разные места. Выбери
один вид и держись его.

**Размеры — из ответа.** Не из запроса и не из поля записи: `MAX_RESIZE` мог
срезать ширину, а вторую сторону округляет кодировщик. Неверные `width` и
`height` на `<img>` — прыгающая страница или сплющенная картинка.

**Маленький исходник растянут.** Хелпер увеличивает то, что меньше запрошенного.
Исходник 300 пикселей, запрошено 1200 — будет мыло. Если размер исходника
известен (у поля ленты это `x` и `y`), не проси больше.

**Два файла с одним именем в одной папке.** `photo.jpg` и `photo.png` рядом
делят одну производную: расширение исходника в её имя не входит.

**Поменял качество — старые производные остались.** Качество в имени кеша не
записано, и готовые файлы продолжат отдаваться. После смены качества или
формата по умолчанию —
`MproHelper::imageCacheClear($source)` для нужных исходников или кнопка «Кеш
картинок» на `/a_dmin/setup`. Заменили сам файл под тем же именем — ничего
делать не надо, производная пересоберётся сама.

**Шкала качества у png другая.** Для `png` четвёртый аргумент — уровень сжатия
`0–9`, а не качество. `82` там — ошибка.

**Первый заход дорогой.** Производная кодируется при первом запросе. Страница со
ста новыми картинками первый раз откроется медленно, дальше — из кеша. Для
галерей на сотни файлов лучше прогреть кеш заранее, пройдя страницу один раз.
