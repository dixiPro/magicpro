# Вёрстка: как пользоваться

Как писать разметку на сайте MagicPro: блейды статей, компоненты, текст записей
ленты. Всё, что умеет Blade в Laravel, работает и здесь; ниже — то, что
специфично для MagicPro, и то, обо что спотыкаются.

Механика статей и маршрутов — `main/use.md`, общий список запретов —
`main/dont.md`, картинки — `imagesUse.md` рядом с этим файлом и
`image/use.md`, ленты — `feed/use.md`. Пути даны так, как их принимает
`get-doc`.

## Сначала: что именно верстаешь

Режимов два, и правила у них противоположные.

| | Блейд статьи | Текст записи ленты |
| --- | --- | --- |
| Что это | страница, шаблон, кусок, компонент | поле записи, которое заполняет оператор |
| Чем пишется | `save-article` | `feed-api-write`, команда `itemSave` |
| Что внутри | весь Blade: директивы, php, компоненты | html, метки `#поле#` и одиночные теги `<x-magic::… />` |
| Вёрстка | любая: сетка, карточки, свой css и js | только читаемый текст, без обёрток и стилей |
| Главная цель | чтобы работало и переиспользовалось | чтобы читалось человеком и поиском |

Сомневаешься, какой у тебя режим, — посмотри, куда пишешь. Пишешь в статью —
первый. Пишешь в поле записи — второй, даже если в записи лежит целая страница
текста.

## Общее для обоих

- **Не менять смысл исходного текста и не добавлять фактов от себя.** Вёрстка —
  это форма. Цены, сроки, свойства товара, обещания — только из исходника.
- **Bootstrap 5 подключён.** Сначала его классы, своё — только когда Bootstrap
  не справляется. В тексте ленты своего нет вообще, см. ниже.

## Блейд статьи

### Четыре роли статьи

Статья — это блейд в базе. Чем она работает, решает то, как её зовут.

| Роль | Как выглядит | Как подключается |
| --- | --- | --- |
| Шаблон | `<html>`, шапка, подвал, `@yield('content')` | `@extends('magic::шаблон')` |
| Страница | `@extends` + `@section('content')` | маршрутом, `isRoute` включён |
| Кусок | голая разметка, переменные приходят снаружи | `@include('magic::кусок', [...])` |
| Компонент | `@props([...])` первой строкой | `<x-magic::компонент … />` |

Префикс `magic::` обязателен везде, где стоит имя вью: без него Laravel ищет
файл в `resources/views` и не находит.

### Кусок или компонент

Оба нужны для переиспользования, но ведут себя по-разному.

**Если у блока есть входы, которые хочется называть и проверять, — это
компонент. Если блок просто вынесен, чтобы не мешался, — кусок.**

Кусок видит всю область вызывающего: удобно, пока всё на месте, и молча
ломается, когда какой-то переменной там не оказалось. Компонент видит только
свои пропсы, у них есть умолчания, и позвать его, забыв обязательный вход,
нельзя.

### Компонент

Отдельной сущности «компонент» в MagicPro нет: **любая статья — анонимный
компонент**. Статья `card` зовётся `<x-magic::card />`. Поэтому у статьи,
которая задумана компонентом:

- **`isRoute` выключен.** Иначе она откроется страницей по своему имени и
  покажет разметку без параметров.
- **Первой строкой `@props`.**
- **Сверху комментарий с примером вызова** и смыслом каждого параметра.
  Компонент зовут из других статей и из текста записей, туда за объяснениями
  никто не полезет.

```blade
@props(['data' => [], 'card', 'columns' => 4, 'id' => null])
```

Ключ без значения — обязательный вход, со значением — умолчание.

```blade
<x-magic::slider_column
  :data="$res['data']"
  card="magic::product_card"
  :columns="5"
/>
```

**Двоеточие — это выражение.** `:columns="5"` даёт число, `columns="5"` —
строку `"5"`. Для сравнений и арифметики это разные вещи.

**Дефис в атрибуте превращается в камелкейс.** `mobile-width="85"` внутри
компонента — это `$mobileWidth`. Проп, названный `$mobile_width`, придётся и
звать `mobile_width`, что читается чужеродно.

**Имя анонимного компонента — строчными.** Имя с Заглавной означает компонент
с контроллером, это другая механика (`main/use.md`, «ClassBased компонент»), и
статья должна называться точно так же. Перепутал регистр — получишь не то или
ошибку.

**Компонент нельзя подключить `@include`.** Директиве неоткуда взять
`$attributes` — ошибка про неопределённую переменную. Блок нужен и так и так —
делай его куском, или всегда зови как компонент.

**Функции в блейде объявлять нельзя.** `function make() {}` упадёт на втором
экземпляре компонента на странице: php не даст объявить функцию дважды.
Замыкание в переменной можно — у каждого рендера своя область.

**Класс снаружи — через `merge`:**

```blade
<div {{ $attributes->merge(['class' => 'card h-100']) }}>
```

Тогда `<x-magic::card class="mb-3" />` добавит класс, а не затрёт свой.

### Список: имя карточки вместо слота

Слот рендерится **один раз и в области вызывающего**: `$slot` внутри
компонента — уже готовый html. «Вот разметка одного элемента, повтори её для
каждого» слотом не делается — ни обычным, ни именованным.

Делается передачей имени блейда карточки:

```blade
{{-- вызов --}}
<x-magic::slider :data="$items" card="magic::product_card" />

{{-- внутри компонента --}}
@foreach($data as $item)
  <div class="slide">
    <x-dynamic-component :component="$card" :item="$item" />
  </div>
@endforeach
```

`<x-dynamic-component>` принимает имя в переменной и понимает `magic::`.

**Карточка получает ровно один проп — `item`**, один элемент массива, и всё
остальное достаёт из него сама. Как только разные списки начинают передавать
карточкам разные наборы параметров, подменить одну карточку другой уже нельзя.

### Несколько экземпляров на странице

Компонент с `id` или своими стилями обязан пережить два своих экземпляра на
одной странице.

```blade
@php
  $boxId = $id ?: 'box-' . \Illuminate\Support\Str::random(6);
@endphp
```

Все селекторы в стилях и скрипте — от этого `id`. Проп `id` оставляй: иногда за
компонент нужно зацепиться снаружи.

**Никаких глобальных селекторов в скриптах.** `new Swiper('.swiper')` берёт все
совпадения на странице, включая чужие блоки. Реальный случай: галерея
инициализировала своими настройками все слайдеры страницы, и они сломались
вместе с ней.

### Стили и скрипты

Страница отдаёт их шаблону стеками:

```blade
@push('styles')
  <link href="/design/include/thing.css?v=3" rel="stylesheet">
@endpush

@push('scriptsBottom')
  <script src="/design/include/thing.js?v=3"></script>
@endpush
```

Имена стеков задаёт шаблон сайта — посмотри в нём, какие `@stack` есть.

**Библиотеку, которую могут попросить несколько участников, — только с ключом:**

```blade
@pushOnce('scriptsBottom', 'swiper-js')
  <script src="/design/include/vendor/swiper/swiper-bundle.min.js"></script>
@endPushOnce
```

Ключ общий у всех, кто её просит. Без него на странице с двумя такими блоками
библиотека приедет дважды.

**Порядок в стеке — это порядок отрисовки**, а не порядок в шаблоне. Компонент,
отрисованный раньше владельца библиотеки, положит свой скрипт перед ней и упадёт
с `ReferenceError`. Лечится не перестановкой, а откладыванием:

```js
const start = () => {
  /* инициализация */
};
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', start);
} else {
  start();
}
```

**Инлайнового css — минимум.** `<style>` в компоненте оправдан, когда правила
зависят от пропов: ширина слайда, число колонок. Остальное — в css-файле сайта.
Меняется по ширине экрана — это медиазапрос, а не javascript; скрипт нужен,
только когда надо что-то создать или уничтожить.

### Данные в javascript

```blade
<div x-data="widget(@js($items), @js($title))">
```

`@js()` отдаёт безопасный javascript-литерал: кавычки и теги экранированы,
ставить в атрибут можно. Руками через `json_encode` — не надо.

### Переменные, которые есть всегда

`$Env` — имя текущей статьи, её `title`, `artId`, `parentId`, имя вью. Для
хлебных крошек, canonical, отладки. `$Get` и `$Post` — параметры запроса, если
маршрут их разрешает (`main/use.md`).

### Картинки

Откуда бы ни пришла картинка — из файлового менеджера, из поля ленты, из
чужого пакета, — её приводят к пути на диске и отдают
`MproHelper::imageReduceX()` или `MproHelper::imageReduceY()`. Размеры на
`<img>` — из ответа хелпера. Подробно и с примерами — `imagesUse.md`.

Помни, что `sizes` — это обещание браузеру о **ширине места на странице**:
браузер выбирает файл до вёрстки. Картинка стоит в слайде на 85% экрана, а в
`sizes` написано «четыре в ряд» — приедет мелкий файл и будет мылить.

### Экранирование

`{{ $x }}` экранирует, `{!! $x !!}` — нет. Второе — только для того, что
заведомо разметка: текст записи через `feedText`, описание из админки. Всё, что
пришло из формы или извне, — через первое.

## Текст записи ленты

Правила здесь **жёстче, чем в статье**. Поле записи — это текст для чтения, а
не место для вёрстки: где и как его показать, решает статья, которая выводит
ленту.

### Как он выводится

Статья выводит поле так:

```blade
{!! MproHelper::feedText($item, 'body') !!}
```

`feedText` подставляет метки `#поле#` и `#поле.ключ#` значениями полей записи и
рендерит одиночные теги `<x-magic::… />` — каждый отдельно. **Blade вокруг
тегов не исполняется**: `@if`, `{{ }}`, `@foreach` в тексте записи останутся
буквами.

Тег несуществующего компонента страницу не роняет: на его месте будет
`unsupported`, причина — в логе `feed`.

### Что можно

- `<p>` — абзацы. Длинный текст разбивай на короткие.
- `<strong>` — важные фразы.
- `<ul><li>` — перечисления. Всё, что в исходнике идёт через запятую или
  дефисами, почти всегда просится в список.
- `<h2>`, `<h3>` — только для смысловых разделов внутри текста.
- Классы Bootstrap — только если они действительно помогают читать.
- Одиночные теги компонентов сайта `<x-magic::имя … />` — если такой компонент
  на сайте есть; метки полей в атрибутах подставятся (`:img="#image#"`).
- Ссылки и кнопки — только если они есть в исходном тексте.

### Чего нельзя

- **`<h1>`.** Заголовок записи выводит статья, второй главный заголовок на
  странице — ошибка и для людей, и для поиска.
- **Контейнеры, карточки, колонки, фоновые блоки**, любая декоративная вёрстка.
- **Свой css и инлайновые стили** (`style="…"`).
- **`<html>`, `<head>`, `<body>`.**
- **`<div>` внутри абзаца.** Редактор кладёт теги внутрь `<p>`, и блочный
  элемент браузер выкинет наружу — разметка разорвётся. Отсюда же правило для
  компонентов, которые зовут из текста: их обёртка — `<span>`.
- **Blade-синтаксис** — он не выполнится.

### Результат

Возвращать готовый html: без пояснений, без markdown-обёртки ```` ```html ````.

## Грабли

**Собака в комментарии.** Блейд-комментарий вырезается до компиляции, а
директива в html-комментарии или в строке скрипта — компилируется. Название
директивы `push` со знаком собаки в пояснении роняет страницу:
`Undefined property: …::$startPush`. В комментариях названия директив пиши
словами.

**Шаблон может требовать переменных.** Шаблон читает, например, `$meta` без
проверки — страница без неё упадёт. Передавай вторым аргументом:
`@extends('magic::шаблон', ['meta' => [...]])`.

**Версия ассета живёт в статье.** Поправил css или js — подними `?v=` там, где
файл подключён, обычно в шаблоне. Иначе у посетителя останется старая копия.

**Переносы строк.** Файл с CRLF правится с CRLF. Иначе диффом пройдёт весь
файл, и настоящее изменение в нём не найти.

**Не рендерить блейды из консоли** — это для агента, у которого есть шелл на
сервере. `view(...)->render()` из tinker под другим пользователем кладёт
скомпилированный файл с чужим владельцем, php-fpm не может его перезаписать, и
страница падает с `touch(): Utime failed`. Проверять — запросом страницы.

## Порядок работы

1. Незнакомый модуль — сначала `list-docs`, потом `get-doc` нужного файла.
2. Перед правкой прочитать статью целиком (`get-article`): `save-article`
   заменяет тело целиком, и менять нужно то, что вернулось из базы, а не свой
   прошлый текст.
3. Компонент, который собираешься звать, — проверить, что он есть, и прочитать
   его `@props`.
4. Сделать правку.
5. Открыть затронутые страницы: отдают 200 и выглядят как задумано. Ошибка в
   директиве видна только при запросе.
6. Правился css или js — поднять версию и убедиться, что страница берёт новую.

## Чего не делать

- Копировать один и тот же css и js в две статьи «пока так, потом вынесем».
  Выносить сразу, либо прямо сказать, что это временно и почему.
- Ставить фиксированный `id` в компоненте, который может встретиться дважды.
- Решать javascript-ом то, что решается медиазапросом.
- Всё из `main/dont.md` — оно действует и здесь.
