# ТЗ v6: MagicImage — вызов компонента

Основа — `tzMagicImage5.md` с ответами владельца. Отличие от v5: **имени файла
в пропсах нет**, имена зашиты; кроппер показывается всегда.

## Как работает

1. Две кнопки: «Загрузить» — файл с диска, «Вставить» — картинка из буфера.
2. Настройка: яркость, контраст, насыщенность, уровни с гистограммой, резкость.
3. Потом **всегда** кроппер.
4. «Далее» — компонент отдаёт результат событием `save` и очищается.

Просто загрузить файл без обрезки этим компонентом нельзя: для этого хозяин
берёт другой.

## Три сценария

| Где     | Что дальше делает хозяин                                       |
| ------- | -------------------------------------------------------------- |
| Движок  | спрашивает имя файла, формат и качество (например, avif, webp) |
| Лента   | спрашивает имя файла, форматы уже определены                   |
| Магазин | не спрашивает ничего: имя и форматы определены                 |

Ни в одном сценарии имя не нужно **компоненту** — его назначает хозяин, когда
получит файлы.

## Решено

1. **Компонент независим.** Сам читает файл, сам читает буфер, сам
   обрабатывает, отдаёт готовые файлы. Куда их деть — забота хозяина.
2. **Кропер — `vue-advanced-cropper`.**
3. **Локализации нет:** подписи одним блоком в файле компонента.
4. **Иконки — потом**, отдельными файлами в `src/assets/icons/`.
5. **Кроппер всегда**, поэтому в ответе всегда две части: оригинал и обрезанное.
6. **Оригинал отдаётся всегда:** многим нужно хранить и его, чтобы потом
   обработать заново.
7. **Имена зашиты:** `original` и `crop`, расширение по формату. Пропсов с
   именем нет, компонент имя не спрашивает и не проверяет.
8. **`ratio` задан** — рамка держит пропорцию; **пусто** — режь как хочешь, лишь
   бы не меньше `minX` и `minY`.
9. **Кнопка своя.** Есть слот — работает слот (хозяин может назвать её
   «Продолжить»), нет слота — компонент рисует свою.
10. **Подачи файла снаружи нет:** ни `v-model`, ни методов.
11. **После `save` компонент очищается.**
12. **Событие одно — `save`.**
13. **Предел размера исходника.** Больше предела — уменьшаем перед обработкой,
    с сохранением пропорций. Мерить надо площадью, а не стороной: браузеры
    ограничивают именно её (Safari — около 16,7 Мп, то есть 4096×4096), а
    снимок 6000×4000 проходит любой предел по стороне и всё равно валит Safari.
    Предлагаю `maxPixels` в 12–16 Мп (или `maxSide` 4000–4500 — примерно то же).
14. **Живёт внутри MagicPro** (`admin/js/magic-image/`), собирается отдельно;
    песочница — в `public/magic-image/`, только для проверки. Позже папка уедет
    в свой репозиторий, магазин заберёт `src` сам.

## Как вызывается

```vue
<MagicImage
  :min-x="600"
  :min-y="600"
  ratio="16/9"
  format-clipboard="image/webp"
  :quality-clipboard="82"
  format-result="image/png"
  :quality-result="100"
  @save="onSave"
>
  <template #actions="{ canSave, apply }">
    <button v-if="canSave" @click="apply()">Продолжить</button>
  </template>
</MagicImage>
```

Минимальный вызов — только обработчик:

```vue
<MagicImage @save="onSave" />
```

## Пропсы

| Проп               | Тип    | Умолчание      | Что делает                                                  |
| ------------------ | ------ | -------------- | ----------------------------------------------------------- |
| `minX`             | number | `0`            | меньше по ширине не берём — ни исходник, ни обрезанное      |
| `minY`             | number | `0`            | то же по высоте                                             |
| `ratio`            | string | `'1/1'`        | пропорция рамки; пусто — свободная                          |
| `formatClipboard`  | string | `'image/webp'` | чем кодировать картинку из буфера: файла у неё нет          |
| `qualityClipboard` | number | `82`           | качество для буфера, 1–100                                  |
| `formatResult`     | string | `'image/png'`  | формат обрезанного: `image/png`, `image/jpeg`, `image/webp` |
| `qualityResult`    | number | `100`          | качество обрезанного, 1–100; у PNG не действует             |

Числа и булевы передаются с двоеточием: `:min-x="600"`. Без него прилетит
строка, а `"false"` — это истина.

## Событие `save`

```js
function onSave({ original, crop }) {
  // original: { file, width, height, format }
  // crop:     { file, width, height, format }
}
```

- **`original`** — что прочитали. Файл с диска уходит как есть, своим типом и
  байтами; картинка из буфера кодируется по `formatClipboard` и
  `qualityClipboard`. Имя файла — `original` плюс расширение по формату.
- **`crop`** — обрезанное и обработанное, в `formatResult`. Имя — `crop` плюс
  расширение.
- Обе части есть всегда: кроппер обязателен.

## Слот

`#actions="{ canSave, apply }"` — кнопка хозяина; нет слота, компонент рисует
свою. `canSave` — размеры проходят по `minX` и `minY`.

## Что компонент делает сам

- читает файл и буфер обмена;
- показывает размеры и не даёт продолжить, если меньше `minX` и `minY`;
- яркость, контраст, насыщенность, уровни с гистограммой, резкость;
- кроп с пропорцией или свободный;
- кодирует результат и собирает `File` с зашитым именем;
- очищается после `save`.

## Чего компонент не делает

- не ходит на сервер;
- не спрашивает и не проверяет имя файла;
- не знает, куда и в каком виде положат результат;
- не принимает файл снаружи;
- не отдаёт картинку без обрезки.

## Вопросы

1. **Ключ обрезанного в ответе.** В v5 он назывался `cliped`, а имя файла —
   `crop`. Оставляю `crop` в обоих местах, чтобы не расходилось. Так?
   > crop если из клипборда, если из файла, то у обоих файлов имя оригинала, что бы было легче редактировать имя файла в случае, напримр с движком или лентами.
2. **Исходник меньше минимума.** Показать его и не дать продолжить или сразу
   отказать при загрузке, с сообщением?
   > показать ошибку и одну кнопку отмена.
3. **Предел: число и имя пропа.** `maxPixels` (12–16 Мп) или `maxSide`
   (4000–4500)? 10000 по стороне не спасает: 6000×4000 — это 24 Мп, и Safari на
   нём падает.
   > maxPixels
4. **Что уезжает в `original`, если исходник уменьшили:** файл как был, полного
   размера, или уменьшенная копия? Полный честнее, но тогда `crop` берётся из
   уменьшенной картинки и выходит мельче, чем мог бы.
   > в исходник ВСЕГДА уезжает исходник
