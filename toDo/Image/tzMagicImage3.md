# ТЗ v3: MagicImage — независимый компонент

Основа — `tzMagicImage2.md` с требованиями владельца.

## Решено

1. **Компонент максимально независим.** Сам читает файл, сам читает буфер
   обмена, сам обрабатывает и отдаёт готовый `Blob`. Что с ним делать и в каком
   виде хранить — забота вызвавшего.
2. **Свой кропер.** Чужих пакетов не тянем, `vue-advanced-cropper` уходит.
3. **Локализации нет.** Все подписи лежат одним блоком в файле компонента,
   правятся руками.
4. **Иконки — потом**, отдельными файлами в `src/assets/icons/`.
5. **Имя файла компоненту безразлично.** Он отдаёт `Blob` и размеры; имя,
   расширение, перезапись и всё остальное — на стороне хозяина.
6. **Формат результата задаёт проп `format`** (`image/webp`, `image/png`,
   `image/jpeg`) и не зависит от того, что загрузили: любая правка — кроп,
   яркость, уровни, резкость — пересобирает картинку на canvas, а он отдаёт
   только то, что просят. «Тот же jpg» после обрезки не бывает.
7. **Живёт внутри MagicPro**, собирается отдельно; позже папка уезжает в свой
   GitHub-репозиторий, магазин потом заберёт `src` сам.

## Раскладка и сборка

```text
admin/js/magic-image/
├── src/
│   ├── MagicImage.vue     сам компонент
│   └── assets/icons/      иконки (позже)
├── App.vue                песочница
├── main.js                вход песочницы
├── index.html
├── package.json           свои зависимости и скрипты
├── vite.config.js         отдельный build
└── README.md              пропсы, события, примеры
```

- **Две сборки, независимые:** у MagicPro своя, у MagicImage своя.
- Сборка песочницы кладёт результат в `public/magic-image/` — это только для
  проверки; на боевом MagicPro её нет.
- В обычной сборке админки MagicPro берёт исходник прямо:
  `admin/js/magic-image/src/MagicImage.vue`. Отдельной установки пакета нет.
- `vue` в конфиге песочницы берётся алиасом из общего `node_modules`, `dedupe` —
  чтобы двух копий Vue не случилось.

## Как вызывается

```vue
<script setup>
import { ref } from 'vue';
import MagicImage from '@/magic-image/src/MagicImage.vue';

const source = ref(null); // File | null
const editor = ref(null);

function onSave({ blob, width, height, format }) {
  // имя и адрес придумывает хозяин, компонент про них не знает
}
</script>

<template>
  <MagicImage ref="editor" v-model="source" :min-x="600" :min-y="600" ratio="16/9" format="image/webp" @save="onSave">
    <template #actions="{ canSave, apply }">
      <button v-if="canSave" @click="apply()">Сохранить</button>
    </template>
  </MagicImage>
</template>
```

## Модель

`v-model` — **исходный файл**, `File` или `null`.

- Хозяин кладёт туда файл сам: перетаскивание, «взять прежнюю картинку».
- Компонент пишет в модель то, что выбрали в нём или вставили из буфера.
- `null` — экран чистый.
- Результат моделью не отдаётся: для него событие `save`.

## Пропсы

| Проп           | Тип      | Умолчание                             | Что делает                                      |
| -------------- | -------- | ------------------------------------- | ----------------------------------------------- |
| `minX`, `minY` | number   | `0`                                   | меньше — сохранять нельзя                       |
| `ratio`        | string   | `''`                                  | жёсткая пропорция кропа; пусто — свободная      |
| `ratios`       | string[] | `[]`                                  | список пропорций на выбор; пусто — выбора нет   |
| `format`       | string   | `image/webp`                          | формат результата: webp, png, jpeg              |
| `quality`      | number   | `0.95`                                | качество кодирования                            |
| `maxHeight`    | number   | `0`                                   | потолок превью по высоте; `0` — меряет по месту |
| `tools`        | string[] | `['light','levels','sharpen','crop']` | какие вкладки показывать                        |
| `paste`        | boolean  | `true`                                | ловить ли `Ctrl-V`, пока компонент на экране    |

## События

| Событие             | Что приносит                                              |
| ------------------- | --------------------------------------------------------- |
| `update:modelValue` | выбранный `File` или `null`                               |
| `loaded`            | `{ width, height, name, type, size }` — исходник прочитан |
| `save`              | `{ blob, width, height, format }`                         |
| `clear`             | редактор очищен                                           |

`name` есть только в `loaded`, как справка об исходнике: имя результата —
дело хозяина.

## Методы (`defineExpose`)

`apply()` — собрать результат и выдать `save`; `load(file)` — загрузить файл
снаружи; `clear()` — очистить.

## Слот

`#actions="{ canSave, apply }"` — кнопки хозяина.

## Что меняется против нынешнего MagicImage

- кропер свой, `vue-advanced-cropper` уходит;
- формат, качество, пропорции и набор вкладок — пропсы, а не константы;
- в `save` едет `Blob`, а не `dataURL` и не `File` с именем;
- `Ctrl-V` слушается, только пока компонент на экране;
- подписи — один блок в файле, без словаря языков.

## Границы задачи

Здесь только сам компонент и его песочница. Подключение к лентам и к файловому
менеджеру — отдельная задача, отдельное ТЗ: там диалог, имя файла, `alt`,
ограничения из схемы и отправка на сервер.

## Вопросы

1. **Предел размера исходника:** уменьшать перед обработкой или отказывать,
   если картинка слишком большая? (20 Мп — сотни мегабайт в памяти браузера, у
   Safari потолок около 16 Мп.)
2. **Свой кропер** — рамка с восемью ручками, перетаскивание, колесо для
   масштаба, пропорции. Этого набора хватит или нужно что-то ещё (сетка,
   поворот на 90°, отражение)?
3. **Песочница `App.vue`:** что в ней показываем — один редактор со всеми
   вкладками и выводом того, что пришло в `save`, или несколько наборов пропсов
   рядом (жёсткая пропорция, свободная рамка, только кроп)?
4. **`Blob` и предпросмотр результата:** после `apply()` компонент остаётся с
   картинкой на экране или очищается? Сейчас у магазина очищает обёртка.
5. **Вставка из буфера при двух компонентах на странице:** ловит тот, что
   последним оказался на экране, или нужен явный «активный» компонент?
6. **Сборка песочницы в `public/magic-image/`** — её кладём в `.gitignore`
   MagicPro или пусть лежит в репозитории?
7. **Нетронутый файл и `format: 'original'`.** `Blob` — не формат: внутри него
   всё равно png, jpeg или webp. Не кодировать заново можно только то, что не
   трогали. Варианты:
   - перекодировать всегда в `format` — один формат на выходе, но нетронутый
     файл лишний раз пережимается и теряет EXIF;
   - нетронутый отдавать как есть, `format` применять только к правленым;
   - добавить `format: 'original'` — «оставь как пришло»: не трогали — исходный
     `Blob`, тронули — кодируем в тип исходника (jpg → jpeg, png → png).
     Оговорка: canvas умеет только png, jpeg и webp, поэтому для heic, gif и
     avif нужен запасной формат — обычно webp.
