# ТЗ v7: MagicImage — вызов компонента

Основа — `tzMagicImage6.md` с ответами владельца.

## Как работает

1. Две кнопки: «Загрузить» — файл с диска, «Вставить» — картинка из буфера.
2. Настройка: яркость, контраст, насыщенность, уровни с гистограммой, резкость.
3. Потом **всегда** кроппер.
4. «Продолжить» — компонент отдаёт результат событием `save` и очищается.

Просто загрузить файл без обрезки этим компонентом нельзя: для этого хозяин
берёт другой.

## Три сценария

| Где     | Что дальше делает хозяин                                       |
| ------- | -------------------------------------------------------------- |
| Движок  | спрашивает имя файла, формат и качество (например, avif, webp) |
| Лента   | спрашивает имя файла, форматы уже определены                   |
| Магазин | не спрашивает ничего: имя и форматы определены                 |

Компоненту имя не нужно ни в одном из них — его назначает хозяин, когда получит
файлы.

## Решено

1. **Компонент независим.** Сам читает файл, сам читает буфер, сам
   обрабатывает, отдаёт готовые файлы. Куда их деть — забота хозяина.
2. **Кропер — `vue-advanced-cropper`.**
3. **Локализации нет:** подписи одним блоком в файле компонента.
4. **Иконки — потом**, отдельными файлами в `src/assets/icons/`.
5. **Кроппер всегда**, поэтому в ответе всегда две части: `original` и `crop`.
6. **В `original` всегда уезжает исходник:** файл с диска — как был, полного
   размера и своими байтами. Уменьшение перед обработкой его не касается.
7. **Имена зашиты:**
   - из файла — **оба файла получают имя исходного**, расширение по своему
     формату: `foto.jpg` → `original` = `foto.jpg`, `crop` = `foto.png`. Так
     хозяину проще править имя дальше — в движке и в лентах;
   - из буфера — имя `clipboard` у оригинала и `crop` у обрезанного: исходного
     имени там нет.
8. **`ratio` задан** — рамка держит пропорцию; **пусто** — режь как хочешь, лишь
   бы не меньше `minX` и `minY`.
9. **Исходник меньше минимума** — показываем его и оставляем одну кнопку
   «Отмена». Продолжить нельзя.
10. **`maxPixels`** — предел по числу пикселей. Больше — уменьшаем **перед
    обработкой**, с сохранением пропорций. Мерим площадь, а не сторону: её и
    ограничивают браузеры (Safari — около 16,7 Мп).
11. **Кнопка своя.** Есть слот — работает слот (хозяин может назвать её
    «Продолжить»), нет слота — компонент рисует свою.
12. **Подачи файла снаружи нет:** ни `v-model`, ни методов.
13. **После `save` компонент очищается.**
14. **Событие одно — `save`.**
15. **Живёт внутри MagicPro** (`admin/js/magic-image/`), собирается отдельно;
    песочница — в `public/magic-image/`, только для проверки. Позже папка уедет
    в свой репозиторий, магазин заберёт `src` сам.

## Как вызывается

```vue
<MagicImage
  :min-x="600"
  :min-y="600"
  ratio="16/9"
  :max-pixels="16000000"
  format-clipboard="image/webp"
  :quality-clipboard="82"
  format-result="image/png"
  :quality-result="100"
  @save="onSave"
>
  <template #actions="{ canSave, apply }">
    <button v-if="canSave" @click="apply()">Продолжить</button>
  </template>
</MagicImage>
```

Минимальный вызов — только обработчик:

```vue
<MagicImage @save="onSave" />
```

## Пропсы

| Проп               | Тип    | Умолчание      | Что делает                                                  |
| ------------------ | ------ | -------------- | ----------------------------------------------------------- |
| `minX`             | number | `0`            | меньше по ширине не берём — ни исходник, ни обрезанное      |
| `minY`             | number | `0`            | то же по высоте                                             |
| `ratio`            | string | `'1/1'`        | пропорция рамки; пусто — свободная                          |
| `maxPixels`        | number | `16000000`     | больше — уменьшаем перед обработкой                         |
| `formatClipboard`  | string | `'image/webp'` | чем кодировать картинку из буфера: файла у неё нет          |
| `qualityClipboard` | number | `82`           | качество для буфера, 1–100                                  |
| `formatResult`     | string | `'image/png'`  | формат обрезанного: `image/png`, `image/jpeg`, `image/webp` |
| `qualityResult`    | number | `100`          | качество обрезанного, 1–100; у PNG не действует             |

Числа передаются с двоеточием: `:min-x="600"`. Без него прилетит строка.

## Событие `save`

```js
function onSave({ original, crop }) {
  // original: { file, width, height, format }
  // crop:     { file, width, height, format }
}
```

- **`original`** — исходник. С диска — тот самый файл, нетронутый; из буфера —
  картинка, закодированная по `formatClipboard` и `qualityClipboard`.
- **`crop`** — обрезанное и обработанное, в `formatResult` и `qualityResult`.
- `width` и `height` — размеры именно этой части.
- Обе части есть всегда.

**Имена файлов:**

| Откуда          | `original`       | `crop`                                    |
| --------------- | ---------------- | ----------------------------------------- |
| файл `foto.jpg` | `foto.jpg`       | `foto.png` (расширение по `formatResult`) |
| буфер           | `clipboard.webp` | `crop.png`                                |

## Слот

`#actions="{ canSave, apply }"` — кнопка хозяина; нет слота, компонент рисует
свою. `canSave` — размеры проходят по `minX` и `minY`.

## Что компонент делает сам

- читает файл и буфер обмена;
- уменьшает картинку до `maxPixels` перед обработкой, оригинал не трогает;
- показывает размеры и не даёт продолжить, если меньше `minX` и `minY`;
- яркость, контраст, насыщенность, уровни с гистограммой, резкость;
- кроп с пропорцией или свободный;
- кодирует результат и собирает `File` с именем по правилу выше;
- очищается после `save`.

## Чего компонент не делает

- не ходит на сервер;
- не спрашивает и не проверяет имя файла;
- не знает, куда и в каком виде положат результат;
- не принимает файл снаружи;
- не отдаёт картинку без обрезки.

## Вопросы

1. **Совпадение имён.** Файл `foto.jpg`, `formatResult="image/jpeg"` — тогда у
   обеих частей имя `foto.jpg`. Хозяин различает их по ключам `original` и
   `crop`, но если он кладёт оба в одну папку, второй затрёт первый. Оставляем
   как есть (это забота хозяина) или к обрезанному дописывать суффикс?
   > да имена одинаковые пусть хозяин решает что делать, почему одинаковые, например загрузка файла в движок. Дизайнер уже сделал правильное имя, зачем его снова вбивать? незачем, исправить можно
2. **Уменьшение и `crop`.** Исходник 24 Мп, `maxPixels` 16 Мп: обработка и кроп
   идут по уменьшенной копии, поэтому `crop` мельче, чем мог бы быть. Так и
   задумано?
   > в начале работы компонента, уменьшаем и уменьшенную картинку уже настраиваем и кропаем.
