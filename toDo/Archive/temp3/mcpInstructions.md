# Инструкции МСП: что сервер рассказывает агенту сам

Агент, который подключён к сайту по https, файлов пакета не видит. Ни `CLAUDE.md`,
ни `docs/ru/`, ни исходников — только то, что отдаёт сервер в ответе на
`initialize` и в списке инструментов. Всё, чего там нет, ему придётся выяснять
пробами на живом сайте.

Пробы на живом сайте — это правки, которые потом кто-то разгребает.

## Три места, где живут правила

| Где                          | Что туда                                             | Когда читается                                |
| ---------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| `$instructions` сервера      | как устроен MagicPro и как здесь принято работать    | всегда, лежит в контексте с первого сообщения |
| `#[Description]` инструмента | правила этого вызова: что перезапишется, чего нельзя | в момент, когда агент выбирает инструмент     |
| доки по требованию           | подробности модуля                                   | когда агент сам решил посмотреть              |

Порядок именно такой. Правило, которое агент обязан соблюдать **всегда**, живёт в
`$instructions`; правило про один вызов — в его описании; всё остальное — в доках,
и туда он может не заглянуть.

Обратная сторона: `$instructions` уезжают с каждым запросом и стоят контекста.
Поэтому там только то, без чего агент напортит, — не учебник.

## Куда положить

`Laravel\Mcp\Server` держит текст в свойстве `$instructions`, по умолчанию там одна
строка: «This MCP server lets AI agents interact with our Laravel application».
Переопределяется в `src/Mcp/Servers/MagicProServer.php` рядом со списком
инструментов:

```php
class MagicProServer extends Server
{
    protected string $instructions = <<<'MARKDOWN'
        …текст ниже…
        MARKDOWN;

    protected array $tools = [ … ];
}
```

Текст один на оба входа — и на `local` через stdio, и на `web` через https.

## Текст

Дальше — то, что нужно вставить. Он общий для любого сайта на MagicPro: про
движок, а не про конкретный магазин. Правила самого сайта («не трогай почту»,
«вопрос — это не задача») живут в `AGENTS.md` рабочей папки агента, см.
`AGENTS.example.md` рядом.

---

MagicPro — CMS поверх Laravel 13. Страница сайта — это статья: её имя и есть
адрес (`about` открывается на `/about`), тело — блейд, рядом может лежать
контроллер. Статьи хранятся в базе, а файлы под `storage/dataMagicPro/` из них
генерируются: править их бессмысленно, при следующем сохранении перезапишутся.

**Порядок работы**

- Читать статьи: `get-article`, `get-article-by-name`, `search-articles`.
  Структура — `get-article-tree`, `get-article-children`, `get-article-parents`,
  `get-article-siblings`; они отдают короткие записи, полное тело берётся
  `get-article`.
- Писать статью только `save-article`. Он пишет тело **целиком**. Перед каждой
  правкой перечитай статью и меняй то, что вернулось из базы, а не текст своей
  прошлой правки: иначе затрёшь чужие изменения, сделанные тем временем в
  админке.
- Новая статья: `create-article` заводит пустую под указанным родителем и
  возвращает `id`, затем `save-article` даёт ей имя, заголовок и тело.
- Место в дереве меняется только `move-article`, в `save-article` его нет.
- Удаление — `delete-article`, и оно уносит всю ветку под статьёй. Первый вызов
  ничего не удаляет, а показывает, что уйдёт: покажи этот список человеку и
  спроси. Удаляет только повторный вызов с `confirm`. Обратного хода нет.
- Файлы сайта (css, js, изображения) — `read-file` и `save-file`; `save-file`
  заменяет файл целиком. Блейды статей сюда не относятся, они правятся только
  через `save-article`.
- Ленты — `feed-api` для чтения и `feed-api-write` для записи.
- Нет подходящего инструмента — значит задача так не решается. Скажи об этом.

**Что такое статья**

- `name` — имя и адрес: латиница, цифры, дефис, подчёркивание. Уникально.
- `isRoute` — публикуется ли статья маршрутом. Компоненты и куски разметки
  маршрутами не являются.
- `routeParams` — правила маршрута: `adminOnly` (видна только администратору),
  `useController` (управление идёт в контроллер, а не сразу во вьюху),
  `getEnable` и `keysArr` (какие GET-параметры принимаются), `bindKeys`
  (значения по позиции в адресе), `postEnable`, `utmParamsEnable`.
- `menuOn` — участвует ли в меню. `directory` — есть ли дети.
- `controller` — php-класс статьи. Класс **всегда** называется
  `Magic_Pro_Name_Controller`, настоящее имя подставит билдер. Переименуешь —
  сломается.

**Как писать блейд статьи**

- Другая статья подключается `@include('magic::имя')`, компонент —
  `<x-magic::имя>`. Префикс `magic::` обязателен, без него Laravel ищет файл
  в `resources/views`.
- Компонент объявляет входы через `@props([...])` и получает их атрибутами.
  Такой блейд нельзя подключить `@include` — директиве неоткуда взять
  `$attributes`, будет ошибка.
- Имя компонента можно передать переменной:
  `<x-dynamic-component :component="$card" :item="$item" />`. Префикс `magic::`
  в переменной работает.
- Слот компонента рендерится один раз и в области вызывающего: `$slot` — уже
  готовый html. Повторить его для каждого элемента списка нельзя. Список
  делается так: компонент получает имя блейда карточки, цикл живёт внутри
  компонента, карточка получает один элемент данных.
- Стили и скрипты страница отдаёт в стеки шаблона: `@push('styles')`,
  `@push('scriptsBottom')`. Если один и тот же файл подключают несколько
  участников страницы, используй `@pushOnce('stack', 'ключ')` с общим ключом,
  иначе библиотека приедет дважды.
- Порядок в стеке равен порядку отрисовки. Инлайновый скрипт компонента может
  оказаться раньше библиотеки, которую он ждёт, — откладывай инициализацию до
  `DOMContentLoaded`.
- Символ собаки внутри блейд-комментария компилируется как директива и роняет
  страницу целиком. Название директивы в комментарии пиши словами.

**Файлы сайта**

- Поправил css или js — подними номер версии там, где файл подключён
  (`?ver=`, `?v=`): это обычно шаблон-статья, а не сам файл. Не поднял — у
  посетителя останется старая копия из кеша.
- Не меняй переносы строк во всём файле. Если файл с CRLF, правка тоже должна
  быть с CRLF, иначе диффом пройдёт весь файл и настоящее изменение в нём
  утонет.

**Проверка**

Сделал — убедись, что затронутые страницы открываются и отдают 200, а не 500.
Блейды не компилируются «в уме»: ошибка в директиве видна только при запросе
страницы.

Подробности по модулям — `list-docs` и `get-doc`.

## Чего в этом тексте нет намеренно

- **Правил конкретного сайта.** Сервер один на все установки; «не трогай
  корзину» — это `AGENTS.md` рабочей папки, а не движок.
- **Описания инструментов.** Они и так приезжают в списке, дублировать —
  тратить контекст дважды.
- **Внутренностей модулей.** Для этого доки, которые берутся по требованию.
- **Тона и формата ответа.** Как агенту разговаривать — дело хозяина агента.

## Когда текст менять

Появился инструмент — строчка в разделе «Порядок работы». Поменялся контракт
(что-то перестало перезаписывать тело целиком, добавилось удаление) — правится
здесь же и в `#[Description]` инструмента одновременно. Всё остальное — в доки.
