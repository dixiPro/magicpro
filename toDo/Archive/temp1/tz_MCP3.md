## Задача

Агент работает с сайтом через инструменты МСП по https и больше никак. Шелла на
сервере у него нет — раздел с `tmux` для этого не годится, там агент живёт на
самом сервере.

Сервер и все пятнадцать инструментов не меняются: `src/Mcp/Servers/`,
`src/Mcp/Tools/` остаются как есть. Меняется транспорт и то, что стоит перед ним.

## Токен

### Что это

Случайная строка, живущая только в памяти. На сервере от неё остаётся хеш.

```php
$token = $userId . '___' . bin2hex(random_bytes(32));   // человеку, один раз
$hash  = hash('sha256', $token);                        // в файл
```

Номер пользователя в самом токене: файл открывается сразу, перебирать каталог не
надо. Секретом он не является — у кого токен, у того и так всё.

### Где лежит

Файл на пользователя: `storage/app/private/magic/mcpTokens/<user_id>.php`.
Миграции нет, таблицы нет. Имя файла — это и есть `user_id`.

Возвращает массив:

| Ключ           | Что                               |
| -------------- | --------------------------------- |
| `hash`         | `sha256` от токена                |
| `ip`           | адрес, с которого токен выдан     |
| `created_at`   | когда выдан                       |
| `last_used_at` | когда последний раз приняли вызов |

Один пользователь — один живой токен. Выдали новый — старый затёрт, это же и
кнопка «отозвать». Удалили файл — токен мёртв.

### Проверка вызова

Заголовок `Authorization: Bearer <token>`. Порядок:

1. файла нет — 401;
2. `hash_equals($file['hash'], hash('sha256', $token))` — не сошлось, 401.
   Сравнение только так, `==` подсказывает таймингом;
3. `ip` не совпал с адресом запроса — 401;
4. `last_used_at` старше часа — 401.

Прошло — `last_used_at = now()`, файл переписан, вызов идёт дальше.

Час считается **от последнего вызова**, а не от выдачи: пока агент работает,
токен живой; закрыл ноутбук — через час мёртв.

### 401 должен объяснять

Агент получает не пустоту, а внятное «токен протух, возьми новый в админке».
Иначе он начнёт гадать и чинить несломанное.

### Права

Токен один и может всё: получил — доступны все инструменты МСП. Роли появятся
после того, как это откатается на боевых продуктах.

## Транспорт

`src/Mcp/ai.php`, рядом с нынешней строкой:

```php
Mcp::local('magicpro', MagicProServer::class);
Mcp::web('/mcp/magicpro', MagicProServer::class)->middleware(McpToken::class);
```

Раздел выключен, пока токена нет: файла нет — адрес отвечает 401 всем и всегда.

## Локальная машина

Токен не попадает ни в конфиг агента, ни на диск. В конфиге стоит имя
переменной:

```json
"headers": { "Authorization": "Bearer ${MAGICPRO_KEY}" }
```

Windows 10, PowerShell 5.1, в `$PROFILE`:

```powershell
function mp {
  $s = Read-Host "ключ" -AsSecureString
  $b = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)
  $env:MAGICPRO_KEY = [Runtime.InteropServices.Marshal]::PtrToStringAuto($b)
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($b)
  claude
  Remove-Item Env:MAGICPRO_KEY -ErrorAction SilentlyContinue
}
```

Linux, в `.bashrc`:

```bash
alias mp='read -rsp "ключ: " MAGICPRO_KEY; echo; MAGICPRO_KEY="$MAGICPRO_KEY" claude'
```

Ввод скрыт, в историю не идёт, после выхода переменной нет.

Подстановку `${VAR}` в конфиге МСП проверить на своей версии агента до
реализации. Не работает — переменная подставляется обёрткой при запуске, схема не
меняется.

## Админка

Раздел `MCP`, кнопка «Получить токен»: генерация, запись файла с адресом
текущего запроса, показ токена один раз. Рядом — когда выдан и когда последний
раз использован, чтобы видеть, жив он или уже протух.

## Порядок работы

1. Админка, «Получить токен», скопировал.
2. `mp` на своей машине, вставил.
3. Агент зовёт инструменты, каждый вызов продлевает час.
4. Час без вызовов — за новым в админку.

## Что помнить

- **Запись файла на каждый вызов.** `last_used_at` обновляется всегда, значит
  каждый инструмент стоит одной записи в файл. Немного, но это есть.
- **`save-article` пишет контроллер статьи, то есть php, который сайт выполнит.**
  Пока токен один и умеет всё, это главный риск боевого сайта. Записано, чтобы не
  всплыло сюрпризом; решения «роли потом» не меняет.
- **Адрес умер — умер.** Смена ip убивает токен, берётся новый. IPv6 с его
  самоменяющимися адресами у нас редкость, ради этого случая ничего не городим.
- **`save-file` и `save-article` заменяют содержимое целиком.** Агент, не
  прочитавший файл перед записью, стирает его. На боевом это уже не учебная
  ошибка.
  > админ всегда может сделать сохранить дерево перед работой
