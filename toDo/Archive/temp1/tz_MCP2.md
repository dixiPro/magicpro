# МСП по http вместо tmux, версия 2

Первая версия — `tz_MCP.md`, там оценка идеи и то, чего она не решает. Здесь
только решённое и работы. Внизу вопросы, которых стало меньше.

## Решено

1. **Транспорт http.** `Mcp::web()` рядом с нынешним `Mcp::local()`. Сервер и все
   пятнадцать инструментов не меняются.
2. **Ключ протухает через час после последнего вызова.** Не от выдачи: пока агент
   работает, ключ живой, закрыл ноутбук — через час мёртв.
3. **Ключ едет переменной окружения.** В конфиге агента лежит имя переменной, а
   не ключ:

   ```json
   "headers": { "Authorization": "Bearer ${MAGICPRO_KEY}" }
   ```

   ```
   MAGICPRO_KEY=<ключ> claude
   ```

   На диск локальной машины ключ не попадает.

4. **Ключ один и может всё.** Получил ключ — доступны все инструменты МСП.
   Разделение по правам не делаем: роли появятся после того, как это откатается
   на боевых продуктах.

## Как это выглядит в работе

1. Админка, раздел `MCP`, кнопка «Получить ключ».
2. Ключ показан, его копируют.
3. На своей машине: `MAGICPRO_KEY=<ключ> claude`.
4. Агент зовёт инструменты по https, каждый вызов продлевает жизнь ключа на час.
5. Час без вызовов — ключ мёртв, за новым идут в админку.

## Работы

| №   | Что                                                         | Где                                   |
| --- | ----------------------------------------------------------- | ------------------------------------- |
| 1   | регистрация http-сервера, адрес, middleware                 | `src/Mcp/ai.php`                      |
| 2   | middleware: `Authorization: Bearer`, сверка, продление, 401 | `src/Mcp/`                            |
| 3   | выдача ключа: генерация, запись, отметка времени            | `src/Mcp/`                            |
| 4   | кнопка «Получить ключ» и показ ключа                        | `admin/js/app/mcpAdmin/`, `admin/api` |
| 5   | как подключить агента на своей машине                       | `docs/ru/mcp/use.md`                  |

Пункты 2 и 3 — это и есть задача, остальное механика.

## Что помнить при реализации

- **Час считается от последнего успешного вызова**, значит на каждый запрос идёт
  запись отметки времени. Это одна строчка на вызов, но она есть.
- **Протух — это 401, а не пустой ответ.** Агент должен получить внятное «ключ
  протух, возьми новый», иначе он начнёт гадать и чинить несломанное.
- **Раздел выключен, пока ключ не выдан.** По образцу `AiConfig`: нет ключа —
  адрес отвечает 401 всем и всегда.
- **`save-article` пишет контроллер статьи, то есть php, который сайт выполнит.**
  Пока ключ один и умеет всё, это остаётся главным риском боевого сайта. Записал,
  чтобы не всплыло сюрпризом; на решение «роли потом» не влияет.

### Ввод ключа с клавиатуры, Windows 10

Проверяется прямо сейчас, до всякого сервера: надо убедиться, что ключ вводится
скрыто, уезжает в дочерний процесс и никуда больше.

Открыть профиль PowerShell:

```powershell
notepad $PROFILE
```

Файла нет — создать (`New-Item -Path $PROFILE -Type File -Force`, потом снова
`notepad $PROFILE`). Вставить и сохранить:

```powershell
function mp {
  $s = Read-Host "ключ" -AsSecureString
  $b = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)
  $env:MAGICPRO_KEY = [Runtime.InteropServices.Marshal]::PtrToStringAuto($b)
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($b)

  # вместо агента — дочерний процесс, который печатает, что ему досталось
  powershell -NoProfile -Command 'echo "дочерний видит: $env:MAGICPRO_KEY"'

  Remove-Item Env:MAGICPRO_KEY -ErrorAction SilentlyContinue
}
```

Перечитать профиль и запустить:

```powershell
. $PROFILE
mp
```

Ввести что угодно, например `test123`. Что должно получиться:

| Проверка                      | Команда             | Ожидание                            |
| ----------------------------- | ------------------- | ----------------------------------- |
| ввод не виден                 | —                   | при наборе на экране пусто          |
| дочерний процесс получил ключ | —                   | напечатал `дочерний видит: test123` |
| после выхода ключа нет        | `$env:MAGICPRO_KEY` | пусто                               |
| в истории ключа нет           | `Get-History`       | только `mp` и `. $PROFILE`          |

Всё сошлось — значит боевой вариант это та же функция, где вместо строки с
`powershell -NoProfile` стоит `claude`.

## Вопросы

Придумал я, в тело ТЗ не пойдёт, пока не скажешь.

1. **Где хранить ключ.** Файл в `storage/app/private/magic/` по образцу
   `configAI.php` или таблица в базе? Файл проще: миграции не надо, а ключ
   всё равно живёт час.
2. **Ключ хранить хешем или открытым?** При часовой жизни открытым не страшно, и
   тогда его можно подсмотреть в админке, а не выдавать заново.
3. **Ключ один на сайт или их может быть несколько сразу?** Один означает, что
   выдача нового убивает предыдущий, — а это заодно и кнопка «отозвать».
4. **Лог вызовов.** Писать, какой инструмент когда звали? На боевом это
   единственный способ понять потом, что натворил агент.
5. **Ограничение по IP.** Пускать только с указанных адресов? Может мешать, если
   адрес плавающий.
6. **Судьба раздела `tmux`.** Остаётся для локальной разработки или убираем?
7. **Где включаем первым.** `mpro2.test` с боевой схемой подключения или сразу
   `new.magijasapuna.com`?
