# Найденные ошибки и расхождения

Исходные файлы не исправлялись. Ниже только подтверждённые расхождения,
обнаруженные при сверке документации с текущим кодом и деревом пакета.

## Документация

### 1. Несуществующий источник требований

`docs/ru/feed/about.md:45` называет источником истины
`docs/TZ_lenta/TZ_data.md`, но такого файла и каталога в пакете нет.

### 2. Неверная ссылка на документацию изображений

`docs/ru/feed/use.md:129` ссылается на `docs/ru/image.md`. Документация сейчас
находится в каталоге `docs/ru/image/`, пользовательский файл —
`docs/ru/image/use.md`.

### 3. Неверное утверждение о `FeedItem::create()`

`docs/ru/feed/use.md:198` утверждает, что напрямую создавать запись нельзя,
потому что она не узнает схему. Текущий `FeedItem::fill()` специально первым
устанавливает переданный `feed_id`, затем расширяет fillable логическими полями.
`FeedItem::save()` также сам открывает транзакцию для insert. Поэтому прямой
вызов поддержан при наличии корректного `feed_id`, хотя relation остаётся более
безопасным и понятным способом.

### 4. Безусловное обещание тихого обрезания строки

`docs/ru/feed/inside.md:302` говорит, что `varchar(255)` молча отрежет хвост.
Сервер не добавляет обязательный `max:255`, если это правило убрано из схемы, но
результат зависит от СУБД и режима: MySQL strict и PostgreSQL обычно возвращают
ошибку переполнения, а тихое усечение возможно лишь в отдельных нестрогих
режимах. Формулировка документации не переносима и не гарантируется кодом.

### 5. Неверное число и описание уникальных индексов

`docs/ru/feed/inside.md:454` говорит, что во всём модуле единственный уникальный
индекс — `magicPro_feeds.code`. Миграция
`create_magicPro_lenta_3_feed_items_slug.php` создаёт второй:
`UNIQUE (feed_id, __slug)`.

`docs/ru/feed/inside.md:555` одновременно заявляет о 19 вторичных индексах
таблицы `magicPro_feed_items` и включает в таблицу slug-индекс. В базовой
миграции создаётся 19 индексов, а следующая миграция добавляет двадцатый — slug.
`PRIMARY` в этот подсчёт не входит.

## Комментарии исходного кода

### 6. Устаревшее описание регистрации `FeedPathGenerator`

`src/Lenta/FeedPathGenerator.php:16-18` говорит о глобальной настройке Media
Library и условной регистрации, если её никто не менял. Фактически
`MagicServiceProvider` без такого условия вызывает
`PathGeneratorFactory::setCustomPathGenerators(FeedItem::class,
FeedPathGenerator::class)`: генератор зарегистрирован только для `FeedItem`.

### 7. Устаревшее имя ключа изображения

`admin/js/app/feedAdmin/dataImageField.vue:14` перечисляет ключ `url`. Текущий
API сохраняет `path`, а старый `url` явно удаляет при очередной загрузке.

### 8. Неверный источник значения видимости в комментарии API

`src/Lenta/API_Feeds.php:771-774` говорит, что модель сама устанавливает и
позицию, и видимость новой записи. Модель действительно считает
`__position`, но `__visible = false` обеспечивает default в миграции базы; в
`FeedItem` собственного default или creating-обработчика видимости нет.
