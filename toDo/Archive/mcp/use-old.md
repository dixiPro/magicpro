# МСП: как пользоваться

Сервер называется `magicpro`, инструменты видны агенту под своими именами.

## Чтение статей

| Инструмент | Параметры | Что отдаёт |
| --- | --- | --- |
| `get-article` | `id` | статью целиком |
| `get-article-by-name` | `name` | то же по имени |
| `search-articles` | `text` | статьи, где подстрока встречается в теле или контроллере |

## Дерево

| Инструмент | Параметры | Что отдаёт |
| --- | --- | --- |
| `get-article-tree` | `id` | ветку от указанной статьи |
| `get-article-children` | `id` | детей |
| `get-article-parents` | `id` | предков |
| `get-article-siblings` | `id` | соседей |

Верхний уровень сайта — `id = 1`.

## Запись

### create-article

Параметр один — `parentId`, и это **будущий родитель**, а не создаваемая статья.

Новая статья получает сгенерированное имя вроде `art_1784214877114`, пустое тело
и контроллер по умолчанию, следующий свободный `npp` под этим родителем; сам
родитель помечается как `directory`.

Имя, заголовок и содержимое проставляются следующим шагом, через `save-article`.

### save-article

Обязателен только `id`, остальные поля необязательны: что не прислали — осталось
как было.

| Поле | Что задаёт |
| --- | --- |
| `name` | имя, оно же маршрут: `name=about` даёт `/about`. Уникально |
| `title` | заголовок |
| `body` | блейд, уезжает в `storage/dataMagicPro/view/{name}.blade.php` |
| `controller` | php контроллера, в `storage/dataMagicPro/controller/{name}.php` |
| `isRoute` | публикуется ли маршрутом |
| `menuOn` | участвует ли в меню |
| `routeParams` | параметры маршрута объектом |

Внутри `routeParams`: `useController`, `adminOnly`, `utmParamsEnable`,
`getEnable`, `postEnable`, `bindKeys`, `keysArr`. Что они значат — в
`docs/ru/main/use.md`.

Две вещи, на которых легко споткнуться:

- **статья `id = 1` обязана сохранить имя `root`**;
- **`parentId`, `npp` и `directory` здесь не редактируются.** Положение в дереве
  меняет только `move-article`, а `directory` считает само дерево: это признак
  того, что у статьи есть дети.

### delete-article

| Параметр | Что значит |
| --- | --- |
| `id` | что удаляем |
| `confirm` | `true` — удалить; без него ничего не удаляется |

**Удаляет статью со всем, что под ней.** Уходит вся ветка, вместе с ней
пропадают сгенерированные блейды и контроллеры, а адреса этих страниц перестают
отвечать.

Работает в два шага, как `itemDelete` у лент. Первый вызов ничего не трогает: он
показывает статью и список всех, кто уйдёт вместе с ней. Удаляет только повторный
вызов с `confirm: true`.

Статью `id = 1` удалить нельзя.

Обратного хода нет: версии удалённой статьи остаются в архиве, но восстановить
её оттуда сейчас невозможно — восстановление ищет статью по id, а её больше нет.
Возврат даёт только сохранённое состояние дерева, и делает его человек в админке.

### move-article

| Параметр | Что значит |
| --- | --- |
| `id` | что переносим |
| `newParentId` | будущий родитель. Тот же самый — значит меняем только порядок |
| `idBrotherUp` | после какой статьи встать; должна быть ребёнком `newParentId`. `0` — стать первым |

Это единственный правильный способ поменять `parentId` или `npp`: он
перенумеровывает соседей с обеих сторон и держит флаг `directory` у старого и
нового родителя, всё одной транзакцией.

## Файлы

| Инструмент | Параметры |
| --- | --- |
| `read-file` | `fileName` |
| `save-file` | `fileName`, `fileData` |

Путь считается от каталога `public`, например `design/script/form.js`.

Расширения только те, что разрешает файловый менеджер: `txt`, `rtf`, `csv`,
`css`, `js`, `json`, `xml`, `sql`, `md`.

**`save-file` заменяет файл целиком и не создаёт новых.** Сначала `read-file`,
потом полное содержимое обратно; что не отправил — потеряно. Файла нет — команда
не сработает.

**Блейды и контроллеры статей — не файлы.** Их читают `get-article` и пишут
`save-article`, хотя на диске они и лежат файлами.

## Прочее

`get-project-name` — имя проекта, без параметров. Нужен, чтобы агент понимал, в
каком проекте оказался.

## Ленты

Два инструмента, оба с одинаковым вызовом: команда в `command`, её параметры
объектом в `params`.

```json
{ "command": "itemsList", "params": { "feedId": 3, "perPage": 20 } }
```

### feed-api — чтение

| Команда | Параметры | Что отдаёт |
| --- | --- | --- |
| `feedsList` | `groupId?` | ленты: `id`, `code`, `title`, `itemsCount` |
| `feedGet` | `id` или `code` | ленту вместе со схемой |
| `itemsList` | `feedId`, `page?`, `perPage?`, `orderBy?`, `direction?`, `filter?` | записи страницами, плюс `total` и `lastPage` |
| `itemGet` | `id` | одну запись целиком |

Порядок работы всегда один: `feedsList` — оператор называет ленту словами, а API
нужен номер; `feedGet` — коды полей, угадать их нельзя; и только потом записи.

Фильтр — список из `{field, op, value}`, операции `like`, `=`, `<>`, `>`, `>=`,
`<`, `<=`. Фильтровать и сортировать можно только по полям-слотам: у полей из
`__data` своей колонки нет.

`perPage` больше 250 инструмент срезает до 250, чтобы ответ не съел агенту весь
контекст. Длинную ленту он обходит страницами, `lastPage` показывает, сколько их.

### feed-api-write — запись

| Команда | Параметры |
| --- | --- |
| `itemCreate` | `feedId` |
| `itemSave` | `id`, `fields`, `visible?`, `slug?` |
| `itemDelete` | `id`, `confirm?` |

**`itemCreate` значений не принимает.** Он заводит скрытую запись в конце ленты с
умолчаниями схемы, а значения идут следующим шагом.

**`itemSave` пишет запись целиком:** чего нет в `fields`, того не будет и в
записи. Поэтому правка одного поля — это сначала `itemGet`, потом полный набор
обратно. `visible` и `slug` — системные колонки, идут отдельно от полей.

**`itemDelete` работает в два шага.** Без `confirm` он ничего не удаляет, а
показывает, что собирается: номер, заголовок и тех, кто на запись ссылается.
Удаляет только повторный вызов с `confirm: true`. Записей за раз — одна, списков
не принимает; вместе с записью уходят её файлы.

**Картинки этим путём не пишутся.** Поле-картинка в `fields` — ошибка: файл
попадает в ленту только через загрузку и кроппер админки.

### Что видно на первой же записи

Схема — это не только имена полей, но и обязательность. У блога, например,
обязательны не два поля, а четыре: заголовок, текст, дата публикации и краткое
описание. Не прислали — `itemSave` вернёт ошибку с разбором по каждому полю
отдельно, но заметить это лучше раньше, прочитав `validation` в схеме.

Слаг считать не надо. Если у ленты задан `slugFrom`, он посчитается из своего
поля сам, и присланный вручную всё равно будет переписан. Параметр `slug` нужен
только лентам без источника.

## Агент со своей машины

Всё, что выше, агент делает и с ноутбука: сервер тот же, инструменты те же.
Разница в одном — вместо запуска сервера у себя он ходит по https и предъявляет
токен.

### Быстрый старт

1. Админка, раздел `MCP`, кнопка «Получить токен». Он показывается один раз.
2. Там же, рядом, адрес сервера — скопировать.
3. Прописать адрес в конфиг своего агента, один раз (ниже про codex и Claude
   Code).
4. Запустить агента, отдав ему токен переменной окружения (ниже команды для
   PowerShell и bash).

Дальше подробности по каждому шагу.

### Токен

Админка, раздел `MCP`, кнопка «Получить токен». Токен показывается **один раз**:
на сайте от него остаётся хеш.

| Что | Как |
| --- | --- |
| сколько живёт | час от последнего вызова и сутки от выдачи, что раньше |
| откуда пускает | только с адреса, с которого его выдали |
| сколько штук | один на человека, новый затирает старый |
| как отозвать | кнопка «Отозвать» или выдача нового |

Час считается от последнего вызова, а не от выдачи: пока агент работает, токен
живой. Закрыл ноутбук — через час он мёртв.

Протух — агент получает 401 с объяснением, за новым идут в админку.

### Настройка агента

Файла настроек от MagicPro не существует: агенту нужен только адрес и токен.
Исходников сайта на локальной машине тоже не надо — агент видит сайт через
инструменты и больше никак.

Адрес сервера — `https://<сайт>/mcp/magicpro`, он же написан на странице выдачи
токена, с кнопкой «копировать».

В конфиг агента пишется **имя переменной**, а не сам токен.

Claude Code, `.mcp.json` в проекте:

```json
{
  "mcpServers": {
    "magicpro": {
      "type": "http",
      "url": "https://ВАШ-САЙТ/mcp/magicpro",
      "headers": { "Authorization": "Bearer ${MAGICPRO_KEY}" }
    }
  }
}
```

или одной командой:

```
claude mcp add --transport http magicpro https://ВАШ-САЙТ/mcp/magicpro \
  --header "Authorization: Bearer ${MAGICPRO_KEY}"
```

Codex, `~/.codex/config.toml`:

```toml
[mcp_servers.magicpro]
url = "https://ВАШ-САЙТ/mcp/magicpro"
bearer_token_env_var = "MAGICPRO_KEY"
```

Имена полей у codex от версии к версии менялись, и в части сборок для http нужен
ещё флаг вроде `experimental_use_rmcp_client = true`. Что понимает твоя — скажет
`codex mcp --help`. Смысл везде один: адрес плюс имя переменной с токеном.

Токен вводится при запуске и живёт в памяти процесса: на диск он не попадает ни
в каком виде, в историю команд тоже.

Windows 10, PowerShell, в `$PROFILE`:

```powershell
function mp {
  $s = Read-Host "токен" -AsSecureString
  $b = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)
  $env:MAGICPRO_KEY = [Runtime.InteropServices.Marshal]::PtrToStringAuto($b)
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($b)
  claude
  Remove-Item Env:MAGICPRO_KEY -ErrorAction SilentlyContinue
}
```

Linux и macOS, в `.bashrc`:

```bash
alias mp='read -rsp "токен: " MAGICPRO_KEY; echo; MAGICPRO_KEY="$MAGICPRO_KEY" claude'
```

Дальше `mp`, вставить токен — и агент видит сайт. Первым делом он обычно зовёт
`get-project-name`: это и есть проверка, что связь есть.

### Где спотыкаются

- **http против https.** Локальный сайт вроде `mpro2.test` идёт по http, и
  некоторые клиенты для не-https адресов ругаются или требуют явного
  разрешения. На боевом вопроса нет.
- **Токен привязан к адресу, с которого выдан.** Браузер ходит на сайт как
  `mpro2.test`, а агент как `127.0.0.1` — адрес запроса другой, и будет 401
  «issued for another address». Лечится тем, что оба ходят одинаково.

### Что помнить на боевом

- **`save-article` пишет контроллер статьи, а это php, который сайт выполнит.**
  Токен пока один и умеет всё, ролей нет.
- **`save-file` и `save-article` заменяют содержимое целиком.** Не прочитал файл
  перед записью — стёр его.
- **Каждое сохранение статьи агентом остаётся в архиве версий** — откат из
  редактора, кнопка с часами. Затёртый блейд возвращается оттуда.
- **Перед работой имеет смысл сохранить дерево** — снимок в разделе импорта.
- **Всё, что агент звал, лежит в `storage/logs/mcp.log`**, четырнадцать дней.
