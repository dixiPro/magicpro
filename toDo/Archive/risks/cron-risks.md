# Крон: незакрытые риски

Восемь свойств, которые следуют из кода. Часть из них — сознательный выбор, но
знать о них надо тому, кто будет менять подсистему.

Остальные тринадцать пунктов того разбора закрыты: гость больше не получает 500,
`handle` в задачу не проходит, сломанный json не превращается в пустые
параметры, устаревшие комментарии переписаны.

### 14. Автоматический путь не повторяет валидацию имени метода

`save`, `list` и `runNow` используют полный `CronTaskChecker`. Планировщик его
не вызывает: раннер проверяет только непустые части и наличие класса.

Старая или созданная вне API строка с `__construct`, `handle` либо другим
непредусмотренным публичным методом может быть вызвана автоматически, хотя
текущий UI такую новую строку не сохранит.

### 15. Ошибка логгера может выйти из CronTaskRunner

Успешный `self::log()` находится внутри основного `try`, но после его ошибки
ветка `catch` вызывает тот же логгер повторно без дополнительного перехвата.
Логирование обычной ошибки задачи устроено так же.

Если каталог логов недоступен или handler бросает исключение, `run()` не
вернёт обещанный массив `ms/error`. Laravel поймает ошибку scheduled event на
своём уровне, но в cron-логе записи не будет; HTTP `runNow` получит внешнее
исключение.

Та же граница есть в `MagicProSchedule`: логирование невалидного cron-выражения
выполняется уже внутри `catch` и не защищено повторным перехватом. Ошибка
логгера выйдет из регистрации и способна сорвать построение всего расписания,
включая ранее добавленные heartbeat, почту и AI cleanup.

### 16. Успешный лог сохраняет все параметры

> **ЗАКРЫТО** — в лог идут имена параметров, а не значения.

При включённом `CRON_LOG_SUCCESS` массив `params` сериализуется целиком. Токены,
пароли и персональные данные из параметров задачи окажутся в дневных логах и
будут храниться до ротации.

### 17. withoutOverlapping не гарантирует единственный запуск на кластере

Динамические события не используют `onOneServer()`. На нескольких серверах с
локальными cache stores одна задача выполняется на каждом узле.

Даже при общем cache `withoutOverlapping()` решает наложение по времени, а не
полную семантику единственного исполнителя для распределённой системы. После
освобождения mutex другой due-процесс может выполнить тот же callback.

### 18. Аварийный mutex может блокировать задачу сутки

`withoutOverlapping()` вызван без аргумента, поэтому expiry Laravel равен 1440
минутам. После штатного завершения lock снимается, но после жёсткого завершения
процесса задача может пропускаться до 24 часов.

### 19. Невалидное расписание создаёт запись в лог каждую минуту

> **ЗАКРЫТО** — жалоба на расписание пишется не чаще раза в час на задачу.

API не позволяет сохранить новую неправильную строку, но устаревшие или
изменённые вне API данные возможны. Такая enabled-задача остаётся в таблице, и
каждый новый `schedule:run` снова пишет ошибку `stage: register`. Автоматического
отключения и подавления повторов нет.

### 20. Ручной запуск не имеет mutex и держит HTTP-запрос

`runNow` не смотрит `enabled`, не получает lock и выполняется синхронно. Двойной
клик частично ограничивает локальный `apiActive` одной вкладки, но другой
браузер, вкладка или прямой API-запрос может запустить ту же работу параллельно
с расписанием.

Для долгой задачи добавляется риск таймаута веб-сервера или PHP, которого нет у
обычного консольного запуска.

### 21. Для cron-подсистемы нет выделенных автоматических тестов

В пакете не найдено тестов для `API_Cron`, `CronTaskChecker`,
`CronTaskRunner`, динамической регистрации, mutex и heartbeat. Ошибки на
границах ручного и автоматического путей сейчас обнаруживаются только чтением
кода или ручной проверкой.
