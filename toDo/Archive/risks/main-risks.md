# Главный модуль: незакрытые пункты

Из двадцати находок разбора закрыто девять: кольца при переносе, `directory`
руками, опечатка ключа в результате билдера, opcache на записи контроллера,
пустой `EXCLUDED_ROUTES` и границы сегмента в исключениях, плюс четыре
расхождения доки, ушедшие вместе с заменой файлов.

Здесь одиннадцать оставшихся.

| № | Чем аукнется |
| --- | --- |
| 6 | ~~метод и токен~~ — поправлено; форма без `@csrf` остаётся незащищённой |
| 1 | ~~сохранение не атомарно~~ — порядок исправлен, осталась только беда диска |
| 2 | имя статьи проходит проверку, а классом контроллера быть не может |
| 5 | query string перебивает позиционный параметр маршрута |
| 3 | неполный `routeParams` сохраняется, маршрутизатор ждёт ключи |
| 4 | у `routeParams` нет единого умолчания UTM |
| 13 | заготовка Livewire привязана к `lvcomponent` |
| 14 | после копирования Vue держит неверные `parentId` и `npp` |
| 15 | в store остались горячие клавиши с несуществующими переменными |
| 18 | пример query string в старой доке синтаксически неверен |
| 19 | README не описывает настройку выдачи статического html |

Первый в списке — шестой, и он же самый спорный: это не ошибка, а граница,
которую надо либо закрыть, либо описать вслух. Сейчас изменяющая данные статья
обязана защищаться сама, а форма с `@csrf` создаёт ложное чувство, что защита
уже есть.

Второй по важности — первый: сохранение статьи трогает диск и базу без общей
транзакции, и обрыв посередине оставляет статью без файлов.

---

## 1. Сохранение статьи и генерация файлов не атомарны

> **ЗАКРЫТО** — `php -l` идёт до базы и до диска, обновление в транзакции,
> файлы прежнего имени сносятся после успешного `update`, беда архива не
> отменяет сохранение. Общей транзакции базы и файлов нет и не будет: диск не
> откатывается. Осталась одна причина расхождения — отказ файловой системы.

**Где:**

- `admin/controller/API_ArticlesPostController.php::saveById()`;
- `admin/controller/MagicProBuilder.php::createMpro()`.

**Что происходит:**

1. `saveById()` удаляет старые рабочие файлы до model update.
2. Затем обновляет строку базы без общей транзакции.
3. После update записывает новые файлы.
4. Контроллер проверяется `php -l` уже после записи на диск.

Из этого следуют три воспроизводимых состояния:

- model validation отклонила изменение — база осталась старой, но её рабочие
  Blade и controller уже удалены;
- запись Blade/controller или `php -l` упали — база уже содержит новое
  состояние, а файлы отсутствуют, частичны или содержат невалидный controller;
- запись архива упала — база и файлы сохранены, но API отвечает ошибкой.

Существующий `docs/ru/main/inside.md` утверждает, что при провале lint сохранение
«падает целиком». Фактически rollback базы и файлов отсутствует.

## 2. Допустимое имя статьи может быть недопустимым именем PHP-класса

**Где:**

- `database/Models/Article.php`;
- `admin/controller/MagicProBuilder.php::dataController()`;
- `src/Routing/DynamicRouteHandler.php`.

Модель и маршрут разрешают дефис и цифру в начале имени. Генератор тем же
именем заменяет `Magic_Pro_Name_Controller` в декларации класса.

Например, `price-list` и `2026price` допустимы как статьи и Blade, но при
`useController = true` дают синтаксически недопустимый PHP-класс. Lint ловит это
только после изменения базы и удаления прежних файлов, то есть дополнительно
включается ошибка из пункта 1.

В UI, MCP schema и старой документации нет отдельного ограничения для
контроллерных статей.

## 3. Неполный routeParams сохраняется, но маршрутизатор требует ключи

**Где:**

- `database/Models/Article.php`;
- `src/Routing/DynamicRouteHandler.php`;
- `admin/js/app/ArtEditor/store.js::updateRouteParams()`;
- `src/Cleanup/ArticleCheck.php`;
- `src/Mcp/Tools/SaveArticleTool.php`.

Vue нормализует routeParams и при обычном сохранении отправляет полный объект.
Модель и API такой нормализации не делают: переданный объект заменяется целиком.

Маршрутизатор обращается без fallback к `adminOnly`, `utmParamsEnable`,
`getEnable`, `bindKeys` и `keysArr`. Поэтому программное сохранение, например
только `{'useController': false}`, оставляет опубликованную статью с массивом,
который падает на отсутствующем ключе и превращается в 404.

Cleanup добавляет только отсутствующий `useController`, а остальные обязательные
ключи не восстанавливает. MCP schema допускает каждый ключ routeParams как
необязательный, хотя само поле при передаче заменяется полностью.

## 4. У routeParams нет единого умолчания UTM

**Где:**

- `admin/js/app/ArtEditor/store.js` — `utmParamsEnable = true`;
- `src/Install/Installer.php::defaultRouteParams()` — `false`;
- `SaveArticleTool` и `docs/ru/main/use.md` описывают default `false`.

Новая статья создаётся с `routeParams = null`. После открытия в редакторе она
получает UTM `true`, а статья, созданная внутренним кодом с installer defaults,
— `false`. Фактическое умолчание зависит от пути создания и первого сохранения.

## 5. Query string подменяет позиционный параметр

**Где:** `DynamicRouteHandler::checkRout()`.

После построения параметров из path выполняется:

```php
$allQuery = array_merge($segmentParams, $request->query());
```

Для `keysArr = ['slug']`, `bindKeys = true` адрес
`/product/expected?slug=replaced` отдаст контроллеру `slug = replaced`.
Позиционная привязка поэтому не фиксирует значение и не может использоваться
как доверенная часть маршрута.

## 6. postEnable не ограничивает HTTP-метод и обходит CSRF

> **ЗАКРЫТО частично** — метод теперь ограничен (GET/HEAD, POST только при
> `postEnable`, остальное 405), присланный csrf-токен проверяется и неверный
> даёт 419. Формы без `@csrf` по-прежнему не защищены: включать проверку для
> всех — отдельное решение, оно ломает существующие формы.

**Где:** `admin/web.php`, `DynamicRouteHandler::checkFirts()`.

Catch-all зарегистрирован через `Route::any()` и целиком исключён из CSRF
middleware. `postEnable` только выбирает `$request->post()` вместо разбора GET.

Следствия:

- GET, PUT, PATCH, DELETE и другие методы всё равно попадают в ту же статью;
- GET при `postEnable` открывает страницу с пустым postParams;
- `@csrf` в Blade создаёт поле, но middleware его не проверяет;
- у каждой изменяющей данные статьи защита должна быть реализована отдельно.

README описывает «POST support», но не раскрывает эту границу безопасности.

## 13. Livewire-заготовка жёстко привязана к lvcomponent

**Где:**

- `admin/controller/default/defaultControllerLivewire.php`;
- `docs/ru/main/use.md`, раздел LiveWire.

В заготовке class placeholder заменяется на имя статьи, но `render()` всегда
возвращает:

```php
return view('magic::lvcomponent', ...);
```

Для статьи с любым другим именем её собственный Blade не используется. Старый
документ показывает `magic::Magic_Pro_Name_Controller`, что после общей замены
дало бы правильное имя, но фактический шаблон устроен иначе.

## 14. После копирования Vue хранит неверные parentId и npp

**Где:** `admin/js/app/ArtEditor/component/TreeArticle.vue::copyRec()`.

Backend создаёт копию рядом с исходной:

- `parentId` остаётся родителем исходной статьи;
- `npp = source.npp + 1`;
- копия должна стоять сразу после исходной.

Frontend создаёт локальный node с `parentId: node.key`, присваивает ему старый
`node.npp` и добавляет в конец массива children текущего родителя. До следующей
перезагрузки дерева UI не соответствует ответу базы; drag/drop копии может
ошибочно определить смену родителя и откатиться.

## 15. В store остались горячие клавиши с несуществующими переменными

**Где:** `admin/js/app/ArtEditor/store.js::handleKeydown()`.

Обработчики `Alt+3`, `Alt+4`, `Alt+5`, `Alt+6` обращаются к
`splitTreeStatusObj`, `addPannel` и `splitStatusEditorObj`, которых в store нет.
Нажатие вызывает JavaScript ReferenceError. В текущем Help эти комбинации уже
не рекламируются, но глобальный listener продолжает их обрабатывать.

## 18. Пример query string в старой документации синтаксически неверен

**Где:** `docs/ru/main/use.md`, раздел «Разрешены GET параметры».

Указан пример:

```text
/test?first=1?second=2&utm_source=source
```

После первого `?` параметры разделяются `&`. Корректная форма:

```text
/test?first=1&second=2&utm_source=source
```

## 19. README не содержит необходимой настройки выдачи статического HTML

**Где:** `Readme.md`, раздел Static generation; `API_Setup`; `Crawler.vue`.

README говорит, что при наличии статической версии Nginx отдаёт её напрямую.
Код MagicPro действительно создаёт и публикует HTML-файлы, но в пакете не
найдена конфигурация Nginx или инструкция `try_files`, связывающая
`STATIC_HTML_DIR` с публичным URL.

Также сохранение статьи не инвалидирует и не обновляет опубликованный HTML.
Без внешней настройки и повторного обхода утверждение README не выполняется
автоматически.
