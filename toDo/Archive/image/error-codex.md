# Найденные ошибки и расхождения

Файл содержит наблюдения, найденные при сверке документации с текущим кодом.
Ничего из перечисленного не исправлялось.

## Подтверждённые расхождения

### 1. PHPDoc публичного хелпера описывает другой вход и другой ответ

`src/Helpers/MproHelper.php`, PHPDoc `imageReduceX()`:

- называет `$file` путём от корня сайта;
- показывает вызов с `$item->img1['path']` без `public_path()`;
- обещает ключи `path`, `x`, `y`, `mime`, `size`.

Фактический `ImageJob` проверяет переданную строку через `is_file()` и
`getimagesize()`, поэтому ему нужен абсолютный путь файловой системы. Фактический
ответ содержит `path`, `width`, `height`, `size`, `ms`, `rotated`, `rotateMs`,
`cmd`, `errorMsg`; ключей `x`, `y` и `mime` нет.

Сгенерированный `docs/ru/helpers/use.md` повторяет это расхождение, потому что
строится из PHPDoc `MproHelper`.

### 2. Комментарий toArray() обещает SVG, код возвращает пустой path

PHPDoc `ImageJob::toArray()` говорит: «При ошибке вместо картинки svg из
настроек». Реализация возвращает пустую строку в `path`, если `errorMsg` не пуст.
Ни `toArray()`, ни другой путь `ImageJob` настройку `IMAGE_ERROR` не читают.

### 3. Текущая документация неверно называет формат по умолчанию

`docs/ru/image/use.md` и `docs/ru/image/inside.md` называют AVIF значением
`RESIZE_FORMAT` по умолчанию и на этом основании говорят, что кроппер обычно
кладёт AVIF.

В `src/Config/magicSchema.php` значение по умолчанию — `webp`. Fallback в
`ImageJob::init()` и `API_Feeds::imageCropUpload()` тоже равен `webp`.

Конкретная установка может быть вручную переключена на AVIF, но это не значение
схемы по умолчанию.

### 4. Описание skipped шире фактического алгоритма cleanup()

`docs/ru/image/use.md` говорит, что `cleanup()` никогда не трогает всё, что
положил в кеш не ресайзер.

Происхождение файла код не определяет. Любой файл в распознаваемой ветке `p`,
`s` или `b`, имя которого совпало с шаблоном производной, будет проверен и может
быть удалён. В `skipped` гарантированно попадают ветка `x`, неизвестная буква
корня и имена, которые не удалось разобрать.

### 5. Fallback качества не совпадает со значениями схемы

`ImageJob::defaultQuality()` вызывает `setting($key, 82)` для любого выбранного
ключа. При отсутствии ключа получаются:

| Формат          | Fallback кода | Значение схемы |
| --------------- | ------------- | -------------- |
| `webp`, `iwebp` | `82`          | `82`           |
| `avif`          | `82`          | `50`           |
| `jpg`           | `82`          | `70`           |
| `png`           | `82`          | `6`            |

При полностью загруженной конфигурации расхождение не проявляется. Оно возникает
при отсутствии отдельного ключа в `MagicGlobals::$INI['RESIZE']`; для PNG число
`82` выходит за документированный диапазон сжатия `0–9`.

### 6. Файл непосредственно в корне public или storage получает другую ветку

`ImageJob::place()` добавляет `/` к проверяемому корню и сравнивает его с
`dirname($file)`. Для файла `/project/public/photo.jpg` dirname равен
`/project/public` и не начинается с `/project/public/`.

В результате такой исходник не получает ожидаемый префикс `p`: следующая
проверка относит его к `b/public`. Аналогично файл прямо в корне `storage`
попадает в `b/storage`, а не в `s`. Обратный разбор всё равно находит исходник,
но фактическая раскладка не соответствует описанной классификации.

## Риски реализации

Ниже не зафиксированные сбои, а условия, при которых текущий код может вести себя
не так, как обещает публичный контракт. Для подтверждения нужны отдельные
воспроизводящие проверки.

### 7. clear() использует basename как часть glob без экранирования

`ImageJob::clear()` строит шаблон `{base}_*.*` и передаёт его в `glob()`.
Символы `*`, `?`, `[` и `]` в имени исходника будут интерпретироваться как
метасимволы шаблона. Метод может не удалить собственные производные или захватить
производные другого basename.

### 8. Неудачный encoder target может остаться годным кешем

Внешняя утилита пишет сразу в окончательный target. При ненулевом exit code
`ImageJob` сохраняет текст ошибки, но не удаляет возможный частичный файл.

Следующий новый `ImageJob` проверяет свежесть только по существованию и
`filemtime`. Если утилита оставила свежий неполный target, он может быть принят
за готовый кеш. В таком ответе `getimagesize()` даст нулевые размеры, но
`errorMsg` останется пустым и `path` будет опубликован.

### 9. Заявление «исключений нет» покрыто не всеми catch

`ImageJob::run()` перехватывает исключение ожидания блокировки, но не оборачивает
общим `catch` создание блокировки, повторный `fresh()`, `mkdir()`, вызов
`ImageEncoder::make()` и чтение результата. `finally` освобождает блокировку, но
не преобразует исключение в `errorMsg`.

Поэтому ошибки cache driver, файловой системы, GD или недоступной PHP-функции
теоретически могут выйти наружу вопреки заявленному контракту.

### 10. Срок блокировки может закончиться до кодирования

Lock выдаётся на 30 секунд. Если предварительный разворот и внешнее кодирование
занимают дольше, другой запрос сможет получить тот же lock и начать писать в тот
же target до завершения первого процесса.

Обычные изображения укладываются в этот срок, но код не продлевает lock и не
пишет результат во временный файл с последующим атомарным rename.
