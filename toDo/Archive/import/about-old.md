# Импорт: назначение

Перенос дерева статей в сайт из JSON-файла — того самого, который отдаёт
экспорт. Плюс сохранённые состояния: снимок всего дерева, из которого сайт
можно поднять обратно.

Два дерева в разговоре называются так:

- **берёза** — дерево из файла, то, что импортируем;
- **дуб** — дерево сайта, то, во что импортируем.

## Что умеет

| Что | Как |
| --- | --- |
| частичный импорт | берёза цепляется к дубу, дуб остаётся |
| полный импорт | дуб сносится, берёза встаёт на его место |
| проверка | первый проход: что заменится, что удалится, что появится |
| снимок | состояние всего дерева в файл, руками или перед импортом |
| восстановление | полный импорт из снимка |

Правило столкновения одно: **берёза главная**. Статья с тем же именем в дубе
удаляется вместе со всем своим поддеревом, статья из файла встаёт на её место.

## Из чего состоит

| Что | Где |
| --- | --- |
| разбор файла, план и работа | `src/Import/ImportTree.php` |
| сохранённые состояния | `src/Import/Snapshots.php` |
| API страницы | `src/Import/API_Import.php` |
| страница | `admin/views/import_tab.blade.php`, `admin/js/app/importAdmin/` |
| экспорт, он же снимок | `admin/controller/ImportExportController.php` |

## Чего не делает

Не сливает статьи по полям: совпало имя — старая уходит целиком, новая встаёт
целиком.

Не хранит залитый файл. Он живёт в браузере и приезжает на сервер каждым
проходом.

Не чистит старые снимки: сколько их держать, решает администратор.

Не трогает экспорт. Снимок — это его же вызов, слово в слово.
