# AI-агент: назначение

> **Раздел выключен.** Маршрут `POST /a_dmin/api/mcp` снят, страница `MCP`
> занята токеном для МСП по https (`docs/ru/mcp/use.md`). Код остался на месте
> целиком — `src/Ai/`, `admin/js/app/mcpAdmin/` — и включается возвратом
> маршрута.
>
> Почему так: сеанс `tmux` даёт агенту шелл на сервере, а МСП по https — только
> пятнадцать инструментов. На боевом сайте нужен второй, и держать открытыми оба
> входа незачем.

Запуск консольного AI-агента прямо из админки, в разделе `MCP`.

## Что он делает

Администратор выбирает агента и команду запуска, вводит дополнительный пароль —
и на сервере поднимается сеанс `tmux` с этим агентом. Дальше страница показывает
всё, что агент пишет, и отправляет ему команды. Уход со страницы сеанс не
переживает: его закрывает уборка по крону.

Смысл затеи — агент, который ходит в MCP этого же сайта. Он видит статьи, ленты
и файлы через инструменты MCP-сервера, а человек управляет им из браузера, не
заходя на сервер по ssh.

## Из чего состоит

| Что | Где |
| --- | --- |
| настройки, агенты и команды | `src/Ai/AiConfig.php` |
| сеанс: запуск, вывод, команды, закрытие, уборка | `src/Ai/AiSession.php` |
| команды админки | `src/Ai/API_Ai.php` |
| уборка зависших сеансов раз в минуту | `src/Scheduling/MagicProSchedule.php` |
| экран админки | `/a_dmin/mcp` |
| настройки | `storage/app/private/ai-sessions/configAI.php` |

## Чего он не делает

Не устанавливает и не настраивает агента. Есть ли `codex` на сервере, добавлен
ли ему MCP, что написано в его `CODEX.md` — дело того, кто настраивал сервер.
Система запускает командную строку из настроек и не проверяет её.

Не ограничивает агента. Всё, что агенту позволено, определяют его собственные
правила и права пользователя, от которого работает php. Раздел не песочница.

Не хранит переписку. История сеанса — это файл вывода, и он удаляется вместе с
сеансом. Ни базы, ни архива нет.

Не переживает перезагрузку страницы: имя сеанса живёт только в открытой
вкладке. Забытый агент остаётся на сервере до уборки.
