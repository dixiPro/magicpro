# Крон: назначение

Задачи расписания, заведённые в админке, без правки php-файлов.

## Что он делает

В админке заводится задача: название, `статья|метод`, параметры и строка `cron`.
Дальше планировщик Ларавела в назначенное время зовёт этот публичный метод
контроллера — напрямую, одним вызовом, без запроса и без вьюхи.

Метод — самостоятельная точка входа. Нужна та же работа ещё и по адресу — её
дёргает `process()` статьи; не нужна — метод живёт сам по себе. Один контроллер
может держать несколько таких методов, каждый своей задачей.

Правка в админке действует сразу: список задач читается заново при каждом
проходе планировщика, раз в минуту, без перезапуска приложения и без чистки
кеша.

## Из чего состоит

| Что | Где |
| --- | --- |
| команды админки: список, сохранение, включение, удаление, ручной запуск | `src/Scheduling/API_Cron.php` |
| вызов метода задачи | `src/Scheduling/CronTaskRunner.php` |
| разбор строки `статья\|метод` и её проверка | `src/Scheduling/CronTaskChecker.php` |
| регистрация в планировщике | `src/Scheduling/MagicProSchedule.php` |
| отметка живого крона | `src/Scheduling/Heartbeat.php` |
| задача | модель `MagicProCronTask` |
| экран админки | `/a_dmin/cron` |

## Чего он не делает

Не разбирает, чем кончилась работа метода. Ретраев нет, задача сама себя не
выключает. Упавший метод пишет свою ошибку в `cron.log` и показывает её по
кнопке «выполнить сейчас» — на этом участие крона заканчивается.

Не заменяет очередь Ларавела: это расписание, а не фоновая обработка заданий.
Долгая задача занимает проход планировщика целиком.

Не создаёт статей и контроллеров: задача только зовёт то, что уже есть.

## Что читать

`use.md` — если заводите задачу или пишете контроллер под неё.

`inside.md` — если правите саму подсистему: регистрацию, вызов, проверки.
