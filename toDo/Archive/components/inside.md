# Компоненты: как устроено

## Откуда берётся `x-magic::`

Одна строка в `MagicServiceProvider`:

```php
Blade::anonymousComponentPath(MAGIC_VIEW_DIR, 'magic');
```

`MAGIC_VIEW_DIR` — это `storage/dataMagicPro/view`, куда MagicPro пишет блейды
статей. То есть **любая статья одновременно является анонимным компонентом**:
статья с именем `img` зовётся как `<x-magic::img />`.

Отдельной сущности «компонент» в базе нет. Компонент — это статья, которую
договорились не публиковать маршрутом.

Рядом живёт вторая регистрация, для классовых компонентов:

```php
Blade::componentNamespace('MagicProControllers', 'magic');
```

## Как завести свой

1. Завести статью — в админке или через МСП `create-article`.
2. Имя дать по-человечески: `img`, `paginator`. Оно и будет именем тега.
3. **`isRoute` выключить.** Иначе компонент откроется как страница по своему
   имени и покажет разметку без параметров.
4. Первой строкой — `@props` с умолчаниями:

```blade
@props(['img' => [], 'width' => 700, 'mobile' => 1])
```

5. В комментарии сверху — пример вызова и что значит каждый параметр. Компонент
   зовут из текста записи, туда в код никто не полезет.

## Что можно и чего нельзя

**Функции объявлять нельзя.** `function make() {}` в блейде упадёт на втором
вызове компонента на странице: PHP не даст объявить функцию дважды. Замыкание в
переменной — можно, у каждого рендера своя область видимости.

**Обёртка должна быть инлайновой.** В тексте записи тег стоит внутри `<p>`,
редактор его туда положил. `<div>` внутри `<p>` браузер выкинет наружу и вёрстка
поедет. Поэтому у `img` обёртка — `<span>` с `display: inline-block`.

**Ширину задавать классом, а не инлайном,** если она зависит от ширины экрана:
медиазапрос в атрибут `style` не поставить. У `img` десктопная ширина идёт
инлайном (`max-width`), а доля телефона — классами `mimg-m2`, `mimg-m3`,
`mimg-m4` из `public/design/style.css`.

## Вызов из текста записи

Оператор пишет тег прямо в тексте, а разворачивает его хелпер:

```blade
{!! MproHelper::feedText($item, 'body') !!}
```

Хелпер подставляет `#code#` значениями полей записи и рендерит теги
`<x-magic::…>` — по одному, каждый своим `Blade::render()`. Подробности и
ограничения — `docs/ru/feed/inside.md`, раздел «Текст записи».

Из этого следует главное правило параметров: **всё, что компонент получает из
записи, приходит значением, а не ссылкой на переменную**. Массив картинки
уезжает в тег целиком, поэтому компонент не должен ничего доставать из базы сам.

## Компонента нет

Тег с несуществующим именем не рушит страницу: `feedText` пробует скомпилировать
тег отдельно, ловит ошибку и подставляет `unsupported`, а причина уходит в лог
`feed`. Это сделано намеренно — оператор ошибётся в имени рано или поздно.
