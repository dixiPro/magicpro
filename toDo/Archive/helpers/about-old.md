# Хелперы: назначение

Класс `MproHelper` — набор статических методов, доступных отовсюду без `use`.

## Зачем он

Блейд статьи — не то место, где пишут длинные пространства имён. Поэтому вещи,
которые нужны на страницах постоянно, собраны в один класс в глобальном
пространстве и зовутся коротко:

```blade
@foreach (MproHelper::getChildrenByName('topMenu') as $child)
```

Второе назначение — не пускать блейды напрямую к `env()`, к почтовому API и к
внутренностям модулей. Страница зовёт `MproHelper::sendMail()`, а через какой
транспорт письмо уйдёт, её не касается.

## Что внутри

| Тема | Про что |
| --- | --- |
| дерево статей | меню, хлебные крошки, переходы по иерархии |
| почта и логи | отправить письмо, записать в свой лог |
| внешние сервисы | телеграм, reCAPTCHA |
| шифрование | AES-токены для ссылок подтверждения |
| текст и файлы | чистка текста под мета-теги, markdown, MIME по расширению |
| картинки | входы в ресайзер |
| отладка | печать переменной |

## Чем он не является

Это не слой бизнес-логики. Половина методов — тонкие входы в другие модули:
картинки уходят в `ImageJob`, почта в `API_Mail`, проверка капчи в `API_Auth`.
Логика живёт там, здесь только короткий вызов.
