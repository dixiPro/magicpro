# Найденные ошибки и расхождения helpers

Проверены текущие `about.md`, `inside.md`, generated `use.md`, PHPDoc и код
`MproHelper`, а также непосредственные делегаты. Исходные файлы не
исправлялись.

## Подтверждённые расхождения документации

### 1. inside.md ошибочно запрещает вложенные папки getDoc

`docs/ru/helpers/inside.md:58-60` говорит, что слеш в имени запрещён и helper
видит только плоские файлы.

Фактическая проверка в `MproHelper::getDoc()`:

```text
^[A-Za-z0-9_-]+(/[A-Za-z0-9_-]+)*$
```

разрешает любое число безопасных сегментов. PHPDoc и generated `use.md`
правильно показывают `getDoc('feed/use')`.

### 2. inside.md предлагает вручную править generated use.md

`docs/ru/helpers/inside.md:140` завершает инструкцию добавления метода шагом
«Дописать строку в use.md».

`DocsCommand` полностью перезаписывает этот файл. Новый public-метод
автоматически появляется в оглавлении и отдельном разделе после
`php artisan magicpro:docs`. Вручную нужно править PHPDoc, затем запускать
генератор.

### 3. Гарантия синхронности generated-файла сформулирована слишком сильно

`docs/ru/main/use.md:349` говорит, что справочник собирается из PHPDoc и
«поэтому не расходится с кодом». Комментарий самого `DocsCommand` описывает
реальное окно рассинхронизации: файл отстаёт до следующего запуска
`magicpro:docs`.

Комментарий `admin/web.php:21` также говорит, что страница документации читает
PHPDoc прямо из исходника. Фактически view использует `DocsTree` и Markdown на
диске; для helpers этот Markdown ранее сгенерирован командой.

## PHPDoc и фактическое поведение

Ошибки PHPDoc автоматически повторяются в `docs/ru/helpers/use.md`.

### 4. crypt() возвращает не готовую для URL строку

PHPDoc `MproHelper::crypt()` (`src/Helpers/MproHelper.php:334`) называет
результат пригодным для ссылки. Метод применяет обычный `base64_encode`, в
алфавите которого есть `+`, `/` и `=`. Для безопасного URL результат нужно
передавать через URL/query encoder.

Кроме того, AES-256-CBC используется без MAC или authentication tag. Токен
скрывает содержимое, но не подтверждает его целостность; для ссылок
подтверждения это существенное недокументированное ограничение.

### 5. decrypt() не всегда обрабатывает чужую строку бесшумно

PHPDoc `decrypt()` (`src/Helpers/MproHelper.php:364-365`) обещает пустой
массив без исключения для чужой строки или неверного ключа.

Длина результата `base64_decode` не проверяется. На коротком payload OpenSSL
выдаёт warning о неправильной длине IV. В обычном CLI метод после warning
возвращает `[]`; обработчик ошибок Laravel может преобразовать warning в
`ErrorException`.

Также `json_decode` не проверяет тип результата. Успешно расшифрованный JSON
scalar конфликтует с объявленным return type `array`.

### 6. dump() печатает не «что угодно»

PHPDoc `dump()` (`src/Helpers/MproHelper.php:387`) обещает напечатать любое
значение JSON-ом.

`json_encode` вызывается без `JSON_THROW_ON_ERROR`. Для resource или
некорректной UTF-8 он возвращает `false`, исключение не возникает, catch не
выполняется, а метод печатает пустую строку. Проверено изолированным PHP-вызовом
на `php://memory`: `json_last_error_msg()` равен `Type is not supported`.

### 7. translitForUrl() не всегда режет по границе слова

PHPDoc `translitForUrl()` (`src/Helpers/MproHelper.php:638-639`) обещает
обрезание по границе слова.

Граница ищется только как последний дефис уже обрезанного slug. Если дефиса
нет, длинное слово режется посередине. Воспроизводимый пример:

```php
MproHelper::translitForUrl('abcdefghijk', 5); // abcde
```

### 8. trimAndCutText() может превысить limit

PHPDoc `trimAndCutText()` (`src/Helpers/MproHelper.php:698-699`) называет
`limit` потолком длины.

Реализация сначала берёт `limit + 1` символ, затем ищет пробел. У длинного слова
без пробелов хвост не удаляется:

```php
MproHelper::trimAndCutText('abcdefghijk', 5); // abcdef
```

Результат длиннее документированного потолка на один символ.

### 9. trimAndCutText() удаляет не все emoji

PHPDoc `trimAndCutText()` (`src/Helpers/MproHelper.php:695`) говорит, что
emoji выбрасываются. Регулярное выражение удаляет только Unicode-категории
`So` и `Cn`.

Emoji modifiers, variation selectors, ZWJ и части keycap sequences относятся к
другим категориям. Проверка `A👍🏽B` оставляет между `A` и `B` skin-tone
modifier U+1F3FD.

## Ошибки и риски реализации

### 10. Неуспешный sendMail дважды пишет одну ошибку

`AbstractMailApi::run()` уже пишет каждое исключение в лог `mail`. Получив
отрицательный envelope, `MproHelper::sendMail()` создаёт исключение из
`errorMsg`, ловит его и пишет вторую запись в тот же лог.

Фраза `docs/ru/helpers/inside.md:30-33`, что wrapper логирует ошибку, потому что
иначе о ней никто не узнает, уже неверна. На текущем пути ошибка известна
`AbstractMailApi` и логируется дважды.

Если сам `addLog()` падает, повторный вызов внутри catch тоже не защищён, и
`sendMail()` может выпустить исключение вопреки своему публичному контракту.

### 11. getPathToRootById() не распознаёт косвенные циклы

`Article` запрещает только прямую самоссылку. Цикл A → B → A модель разрешает,
а `getPathToRootById()` не хранит посещённые id. Он делает повторные запросы,
пока не сработает лимит, и возвращает массив повторяющихся имён вместо пути от
корня.

Дополнительно условие `while (++$count < 100)` обрабатывает максимум 99
статей, хотя `docs/ru/helpers/inside.md` описывает потолок как 100 шагов.

### 12. addLog() принимает непроверенное имя как часть пути

`MproHelper::addLog()` вставляет `$logName` непосредственно в:

```php
storage_path("logs/{$logName}.log")
```

Сегменты пути и `..` не запрещены. Внутренние вызовы передают константные
имена, но публичная сигнатура и PHPDoc не предупреждают, что пользовательский
ввод способен вывести файл за пределы `storage/logs`, если у процесса есть
права.

### 13. dump() небезопасен для недоверенного HTML

При `showXmp = true` JSON вставляется внутрь устаревшего raw-text элемента
`<xmp>` без экранирования. Строка с `</xmp>` закрывает контейнер и позволяет
добавить последующую HTML-разметку. Метод обозначен как отладочный, но технически
доступен из любой Blade-страницы.

### 14. telegramSend() не гарантирует объявленный array и не ловит сеть

Метод возвращает `$response->json()`, чей фактический тип — mixed. Пустое или
не-JSON тело может нарушить return type `array`. ConnectionException и ошибка
записи лога не перехватываются. PHPDoc говорит о возвращаемом ответе, но не
описывает эту границу исключений.
