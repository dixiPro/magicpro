# ТЗ v3: МСП — создание и настройка лент

Основа — `tzMcpFeeds2.md` и ответы владельца. Главное отличие от v2: у
заполненной ленты для МСП закрыто всё, «было / стало» не нужно.

## Решено

1. **МСП-агент умеет структуру лент**, не только записи.
2. **Отдельный инструмент `feed-api-schema`.** Структура и записи — разные
   разрешения в клиенте.
3. **Пока в ленте нет записей — агент делает с лентой что хочет. Появилась хоть
   одна запись — для МСП лента закрыта целиком:** ни схема, ни код, ни название,
   ни группа. Менять дальше может только человек в админке.
4. **Освобождённый слот чистится** — правка `API_Feeds`, теперь по сути для
   админки: через МСП у заполненной ленты слот не освободить.
5. **Агент создаёт группы** (`groupCreate`).
6. **Убрали поле из схемы — его данные стираются** (правка `API_Feeds`, по сути
   для админки): поле в слоте — колонка чистится, поле в `__data` — его ключ
   удаляется у всех записей ленты, поле-картинка — удаляются и её файлы.

## Инструмент `feed-api-schema`

| Команда | Что делает |
| --- | --- |
| `groupsList` | группы лент |
| `groupCreate {title}` | новая группа |
| `feedCreate {groupId}` | новая пустая лента; код и название — следующим `feedSave` |
| `feedSave {id, code?, title?, groupId?}` | код, название, группа; код уникален, проверяет API; **только у ленты без записей** |
| `schemaGet {feedId}` | схема как хранится |
| `schemaSave {feedId, schema}` | схема целиком, все проверки API; **только у ленты без записей** |

Схема сохраняется только целиком: агент берёт `schemaGet`, правит и отдаёт весь
объект.

У ленты с записями `feedSave` и `schemaSave` отказывают сразу, ничего не
сохраняя:

```text
the feed has records: its structure is changed only in the admin panel
```

Проверка — в инструменте МСП, а не в `API_Feeds`: в админке человек может
менять заполненную ленту как угодно.

Не даём: `feedClear`, `feedDelete`, `groupDelete`, `feedMove`, `groupMove`.

## Порядок работы агента

`groupsList` → `groupCreate` (если нужна новая группа) → `feedCreate` →
`feedSave` (код, название) → `schemaSave` → `itemCreate` / `itemSave`.

Код, название, группу и схему доводят до конца **до первой записи**: после неё
агент не поправит ничего.

## Чистка данных убранного поля (`API_Feeds::schemaSave`)

Колонка была занята полем в старой схеме и свободна в новой — перед сохранением,
в одной транзакции, у записей этой ленты:

| Слот | Чем заполняется |
| --- | --- |
| `__string_*`, `__bigint_*`, `__date_*`, `__link_*` | `NULL` |
| `__bool_*` | `false` (умолчание колонки) |

Поле из `__data`: ключ с кодом поля удаляется из `__data` каждой записи ленты.
Поле-картинка: вместе с ключом удаляются файлы медиатеки этого поля у каждой
записи.

## Ограничения

1. **Картинки.** Поле-картинку в схеме объявить можно, заполнить через МСП —
   нет.
2. **Заполненная лента.** Ни добавить поле («добавь цвет в товары»), ни
   переименовать ленту агент не может — это делает человек в админке.
3. **Права** — владелец токена с ролью `admin`.
