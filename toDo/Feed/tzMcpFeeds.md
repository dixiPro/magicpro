# ТЗ v1: МСП — создание и настройка лент

Черновик. Решение владельца пока одно: МСП-агент должен уметь и ленты, не только
их записи. Остальное — предложение и вопросы.

## Что есть сейчас (сверено с кодом)

| Инструмент       | Команды                                                        |
| ---------------- | -------------------------------------------------------------- |
| `feed-api`       | `feedsList`, `feedGet`, `itemsList`, `itemGet` — только чтение |
| `feed-api-write` | `itemCreate`, `itemSave`, `itemDelete` (в два шага, `confirm`) |

Всё остальное из `API_Feeds` агенту закрыто: группы, создание ленты, её код и
название, схема, очистка и удаление ленты. Лента для агента существует, только
если её заранее сделал человек в админке.

## Предложение

Новый инструмент **`feed-api-schema`** — отдельно от записей: ошибка в схеме
бьёт по всем записям ленты, и человек в клиенте видит, что агент зовёт именно
его.

| Команда                                  | Что делает            | Замечание                                         |
| ---------------------------------------- | --------------------- | ------------------------------------------------- |
| `groupsList`                             | группы лент           | чтение                                            |
| `groupCreate {title}`                    | новая группа          |                                                   |
| `feedCreate {groupId}`                   | новая пустая лента    | код и название — следующим `feedSave`             |
| `feedSave {id, code?, title?, groupId?}` | код, название, группа | код уникален, проверяет API                       |
| `schemaGet {feedId}`                     | схема как хранится    |                                                   |
| `schemaSave {feedId, schema}`            | схема целиком         | все проверки API: слоты, коды, `slugFrom`, `link` |

Схема сохраняется только целиком — как в админке: «колонка занята один раз» и
«код уникален» проверяются на полном наборе. Агент берёт `schemaGet`, правит,
отдаёт весь объект.

Не даём: `feedClear`, `feedDelete`, `groupDelete`, перемещения (`feedMove`,
`groupMove`). Удалить ленту — решение человека.

## Ограничения

1. **Картинки.** Поле-картинку в схеме объявить можно, заполнить через МСП —
   нет, как и сейчас в `itemSave`.
2. **Переименование кода поля в слоте**, когда в ленте есть записи, API
   запрещает — так и остаётся.
3. **Освобождённый слот хранит старые данные.** Убрали поле из `__string_2` —
   значения в колонке остались. Займёт слот новое поле — вылезут чужие значения.
   Так устроено и в админке; для агента это опаснее: он чаще перестраивает
   схему целиком.
4. **Схему ленты читают контроллеры сайта.** Агент, сменивший коды полей, ломает
   статьи, которые эти коды используют. `search-articles` по коду поля это
   показывает — правило в доку агента.
5. **Права** — как у остальных инструментов МСП: владелец токена с ролью
   `admin`.

## Дока

- `docs/ru/mcp/use.md` и описание инструмента — команды, «схема целиком»,
  порядок: `groupsList` → `feedCreate` → `feedSave` → `schemaSave` →
  `itemCreate`/`itemSave`.
- `docs/ru/mcp/agent.md` — правило: перед `schemaSave` искать статьи, которые
  читают ленту (`search-articles` по `code` ленты).
- Список инструментов на странице МСП в админке подхватится сам.

## Вопросы

1. **Отдельный инструмент** `feed-api-schema` или команды в `feed-api-write`?
2. **Схема с записями.** Разрешать агенту `schemaSave`, когда в ленте уже есть
   записи, или только пустой ленте? Вариант посередине — двухшаговое
   подтверждение (`confirm`), как у удаления: первый вызов показывает разницу
   «было / стало».
3. **Освобождённый слот** (п. 3 ограничений): чистить колонку при освобождении —
   это правка `API_Feeds`, одна для админки и МСП — или оставить как есть?
4. **Группы:** давать агенту `groupCreate` или только класть ленты в
   существующие?
