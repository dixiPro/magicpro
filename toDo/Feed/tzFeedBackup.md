# ТЗ v1: сохранение и восстановление одной ленты

Черновик. Единица — **одна лента**: её схема, записи и картинки. Решения
владельца пока только это; остальное — предложения и «Вопросы».

## Что есть сейчас (сверено с кодом)

| Часть    | Где лежит                                                                                                                                                              | Что важно для архива                                                                      |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Лента    | `magicPro_feeds`: `code` (уникален), `title`, `schema` (JSON), `group_id`, `position`                                                                                  | группа обязательна (`restrictOnDelete`)                                                   |
| Схема    | `version`, `fields`, `slugFrom`, `orderBy`, `orderDir`, `order`, `orderForm`, `viewArticle`                                                                            | `link`-поле хранит `relation.feed_id` — **id другой ленты**; `viewArticle` — имя статьи   |
| Записи   | `magicPro_feed_items`: слоты `__string_1..5`, `__bigint_1..3`, `__date_1..3`, `__bool_1..3`, `__link_1..3`, `__data` (JSON), `__slug`, `__position`, `__visible`, даты | `__link_*` — **id записей**; `__slug` уникален в ленте                                    |
| Картинки | Spatie MediaLibrary: таблица `media` + файлы `storage/app/public/magicFeed/<media_id>/…`                                                                               | в поле записи лежит `path` = `/storage/magicFeed/<media_id>/<файл>` — **id медиа в пути** |
| Тексты   | поля записи                                                                                                                                                            | могут содержать `#image#`, `<x-magic::…>` и пути картинок                                 |

Нет: выгрузки и загрузки ленты, ни в админке, ни в API, ни в МСП.

## Предложение: что делаем

### Сохранить

Команда `feedExport` (API лент, кнопка в админке ленты) → файл
`feed-<code>-<дата>.zip`:

```text
feed.json      лента: code, title, schema, группа (по имени), формат архива
items.json     записи: все поля по логическим кодам схемы + __slug, __position,
               __visible, created_at, updated_at, старый id
media/<старый id записи>/<поле>/<файл>   оригиналы картинок
```

Записи — по **логическим кодам**, а не по слотам: схему можно поменять, код
поля остаётся понятным.

### Восстановить

Команда `feedImport` (загрузка zip) — два режима:

| Режим              | Что делает                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| **Новая лента**    | создаёт ленту (новый `code`, если занят — ошибка или суффикс, см. вопросы), схему, записи, картинки |
| **Заменить ленту** | та же `code`: удаляет все записи и их картинки, ставит схему и записи из архива                     |

Порядок: проверка архива целиком → транзакция базы → картинки. Упало — база
откатывается, скопированные файлы удаляются.

Записи создаются через ленту (`$feed->items()->create()`) — `__position`,
slug, валидация схемы работают как при обычном сохранении.

## Ограничения

1. **Ссылки на другие ленты не переносятся.** `link`-поле ведёт на запись
   чужой ленты по id; в другом сайте этих id нет. Варианты — в вопросах.
2. **Ссылки внутри одной ленты** (запись → запись той же ленты) можно
   пересчитать: старый id → новый id по `items.json`.
3. **id записей меняются.** Всё, что снаружи ленты хранит id записи (статьи,
   другие ленты, заказы, закладки), после восстановления смотрит в пустоту.
4. **Пути картинок меняются:** в пути `media_id`, он новый. Поле `image`
   пересобирается из новой медиа; **пути внутри текстов** (markdown, html) —
   только если заменять строкой старый путь на новый (см. вопросы).
5. **`viewArticle`** — имя статьи; на другом сайте статьи может не быть. Лента
   восстановится, ссылки на записи — нет.
6. **Группа** ищется по имени; нет — создаётся (или в первую группу — вопрос).
7. **Схема несовместима с кодом сайта.** Архив ставит свою схему; контроллеры
   сайта, которые ждут других полей, — забота сайта.
8. **Размер.** Архив с картинками может быть большим: лимиты загрузки
   (`upload_max_filesize`, `post_max_size`, nginx `client_max_body_size`) и
   время запроса. Большие ленты — только через artisan-команду.
9. **Уменьшенные копии** (кеш ресайзера) не сохраняются: сделаются заново.
10. **Версия формата.** В `feed.json` — версия архива и `version` схемы; архив
    новее пакета — отказ.
11. **Права.** Только админ (`role = admin`).
12. **Статика.** После «Заменить» страницы с лентой в запечённом HTML устарели
    — нужен новый обход паука.

## Вопросы

0. Отдельно сохраняем структуру и данные.
   Две кнопки

1. **Где кнопки:** в админке ленты («Сохранить», «Восстановить»)? Нужны ли
   artisan-команды `magicpro:feed-export <code>` / `feed-import <file>` для
   больших лент и крона? Нужно ли в МСП?

   > в МСП нет, в артисане нет

2. **Режимы восстановления:** оба («Новая» и «Заменить») или только один?
   > Добвить ленту - восстанавливаем структуру
   > добавить данные — восстанавливаем данные
3. **`code` занят** при «Новой ленте»: ошибка или `code_2`?
   > нет, если code есть структура не восстанавливается
   > если код есть, данные закачиваются без проверки схемы
4. **Ссылки на другие ленты:**
   - обнулить `link`-поля (запись есть, ссылки нет);
   - сохранить по slug записи чужой ленты и искать на новом сайте по slug +
     `code` ленты;
   - отказ, если в схеме есть `link` на чужую ленту.
5. **Пути картинок в текстах:** заменять старые пути новыми или не трогать?
6. **Скрытые записи** (`__visible = false`) — сохранять тоже?
7. **Даты `created_at`** — брать из архива или ставить текущие?
8. **Автоматическое сохранение:** архив перед «Заменить» и перед
   «Очистить ленту» — страховка от ошибки. Нужно?
9. **Где хранить архивы на сервере** (если сохраняет крон или страховка из
   п. 8): `storage/app/private/magic/feeds/`, сколько держать?
