# ТЗ v2: МСП — создание и настройка лент

Основа — `tzMcpFeeds.md` с ответами владельца.

## Решено

1. **МСП-агент умеет структуру лент**, не только записи.
2. **Отдельный инструмент `feed-api-schema`.** Схема бьёт по всем записям ленты
   разом, запись — по одной строке. Разные инструменты — разные разрешения в
   клиенте: записи можно пускать без подтверждения, структуру — нет.
3. **`schemaSave` на ленте с записями — в два шага, «было / стало».** Первый
   вызов ничего не сохраняет и показывает разницу; сохраняет второй, с
   `confirm: true`.
4. **Освобождённый слот чистится.** Правка в `API_Feeds`, общая для админки и
   МСП.
5. **Агент создаёт группы** (`groupCreate`).

## Инструмент `feed-api-schema`

| Команда | Что делает |
| --- | --- |
| `groupsList` | группы лент |
| `groupCreate {title}` | новая группа |
| `feedCreate {groupId}` | новая пустая лента; код и название — следующим `feedSave` |
| `feedSave {id, code?, title?, groupId?}` | код, название, группа; код уникален, проверяет API |
| `schemaGet {feedId}` | схема как хранится |
| `schemaSave {feedId, schema, confirm?}` | схема целиком, все проверки API |

Схема сохраняется только целиком, как в админке: агент берёт `schemaGet`,
правит и отдаёт весь объект.

Не даём: `feedClear`, `feedDelete`, `groupDelete`, `feedMove`, `groupMove`.
Удалить ленту — решение человека.

### «Было / стало»

Лента с записями, `schemaSave` без `confirm`: ничего не пишется, в ответе:

- поля добавлены / убраны / изменены — код, подпись, тип, слот;
- смена `slugFrom`, `orderBy`, `orderDir`, `viewArticle`;
- **какие слоты освобождаются и у скольких записей в них есть значения** — это
  то, что будет стёрто;
- `confirmRequired: true` и подсказка повторить с `confirm: true`.

Проверки схемы (слоты, коды, `link`) выполняются уже на первом шаге: схема,
которую не сохранить, отказывает сразу, а не после подтверждения.

Пустая лента сохраняется с первого вызова.

## Чистка освобождённого слота (`API_Feeds::schemaSave`)

Слот освобождён — колонка была занята полем в старой схеме и свободна в новой.
Перед сохранением схемы, в одной транзакции:

| Слот | Чем заполняется |
| --- | --- |
| `__string_*`, `__bigint_*`, `__date_*`, `__link_*` | `NULL` |
| `__bool_*` | `false` (умолчание колонки) |

Только записи этой ленты. Касается и админки: убрали поле в редакторе схемы —
его значения ушли.

## Ограничения

1. **Картинки.** Поле-картинку в схеме объявить можно, заполнить через МСП —
   нет.
2. **Переименование кода поля в слоте**, когда в ленте есть записи, API
   запрещает — так и остаётся.
3. **Схему ленты читают контроллеры сайта.** Смена кодов ломает статьи, которые
   их используют.
4. **Права** — владелец токена с ролью `admin`, как у остальных инструментов.

   всех записей, как слот, или оставлять? В `__data` чужие значения не
   всплывают: новое поле с тем же кодом — это то же поле.
2. **Админка.** Там тоже показывать «было / стало» перед сохранением схемы с
   записями, раз теперь убранное поле стирает данные? Или хватит текущего
   подтверждения?
